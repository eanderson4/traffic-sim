**Should-fix**

1. `scripts/runreport.py:370` — `iv["time_loss_s"]` raises a bare KeyError on a legal metrics file. The interval field is optional: engine/metrics.go:123 (`TimeLossS *float64 // nil when the time_loss group is off`) and metricsjson.go:41 (`omitempty`). A set configured without the time_loss group crashes the standard report with a traceback instead of a refusal (or a zero-loss report). Use `.get("time_loss_s", 0.0)` or exit with a message naming the missing group.

2. `scripts/chicago/mkod.py:983` (and the freeway/arterial totals feeding it) — the mass-balance line "`through traffic: X of Y veh/h inflow`" and `realized[*]` are computed from the **unscaled** rate, while the file is written at `rate * pscale` (mkod.py:993, 1103, and the interior loop). With a profile library carrying `scale != 1` (the shipped profiles-am.json has scale 0.5 in tests; any user library can), the printed totals no longer describe the emitted file — while the district table (`observe`) *does* use the scaled rate, so mkod's own two reports disagree. This is exactly the "flag that silently invalidates another flag's meaning" trap the file's comments warn about.

3. `scripts/chicago/mkod.py:1044` (and 991) — a flow that resolves no profile is dropped with only a stderr counter, and for the ramp path this silently loses relocated demand: `relocate[corr]` was already deducted from the cut face, so if the *interior* pick has no profile that volume vanishes entirely, contradicting the "the volume is not lost — it is re-emitted below" invariant (comment at the deduction site). Conversely a *portal* with no profile still emits its relocated share (the deduction at ~line 976 happens before the `continue` at 991), leaving a corridor carrying only `ramp_share` of that portal's inflow. Given this file's refuse-don't-warn posture everywhere else, an unmatched flow under a no-default library should probably be fatal, or at minimum the relocation should be skipped when the profile is missing.
