## Blockers

None found. The two failure modes I chased hardest both check out: `{run}/meta` is written in `RunLive` immediately after `NewEngine` (engine/natsio/run.go:95,108), i.e. after world build but *before* the driver's ~400 s exit-routing pass, so `identityTimeout=120s` is consistent with the la-lean numbers cited at engine/cmd/demosrv/main.go:163; and generation order (parts → manifest last, all temp+rename, double-checked stat under `c.mu`) makes a killed generation safe.

## Should-fix

1. **Part URLs are not content-addressed — the chunked path reintroduces exactly the tear the cache header comment forbids** (engine/cmd/demosrv/geojson.go:159, manifest URLs `/net/{id}.geojson.part-NNN`). The cache *files* carry `{schema}.{hash}`, but the URLs the client walks don't. If the scenario is edited between the viz fetching the manifest and fetching part-007, `c.part` resolves each index against the *current* hash, so the client concatenates features from two different network versions with no error (counts usually overlap; a shrink at least 404s the tail). Single-file mode was atomic per fetch. Trivial fix: embed hash12 in the part URL and have the handler match it (mismatch → 404 → client refetches manifest).

2. **The identity probe can pass against a foreign broker running (or having run) the same run id** (engine/cmd/demosrv/supervisor.go, `probeRunMeta`). `demos.json` run ids are static and checked in, so the most likely foreign listener — another instance of this same demosrv — has the same `r1/meta` key; `Registry.Finish` rewrites rather than deletes meta, so even a *finished* foreign run satisfies `kv.Get`. If that probe lands before the reaper closes `done` for our bind-failed child, `start` reports success, the supervisor tracks a corpse, and the viz attaches to the foreign run — the original incident with extra steps. Cheap narrowing without a contract change: require meta status `running`, and/or keep probing `done` for a grace period after the first successful probe. Full fix (per-spawn nonce echoed into meta) is an ADR-0006 payload change — defer, but note it.

3. **The manifest `parts` foreign member is a new cross-service payload contract with no ADR.** It's consumed by viz/src/netload.ts (TS side unstaged, so this commit ships a contract whose only consumer is out-of-tree). It's HTTP not NATS, so rule 5 doesn't strictly bind, but rule 3 ("message contracts, service boundaries") does, and ADR-0015/0016 set the precedent that chunking schemes get ADRs. ADR-0017 doesn't mention it. A short ADR or an ADR-0017 addendum (docs-only, ungated) would do.

## Nits

- engine/cmd/demosrv/supervisor.go:36-40 — the `readyTimeout` comment says world build "precedes the listen", but in `serve` the ws listener binds at `ns.Start()` *before* `RunLive`/`NewEngine` (engine/cmd/serve/main.go:224); the port probe passes in ~1 s and world build is actually covered by the identity phase. Comment-only, the generous bound is harmless.
- engine/cmd/demosrv/main.go:48 — with `-ws 0.0.0.0:8443`, `wsClientURL()` tells browsers to dial `ws://0.0.0.0:8443`, which non-local clients can't. The flag help conflates listen and dial address; fine for loopback use.
- engine/cmd/demosrv/main.go (`handleNet` part route) — `strconv.Atoi` accepts `+7`, so `.part-+007` aliases part 7. Harmless.
- engine/cmd/demosrv/geojson.go (`part`) — `scenario.Load` runs twice per part request (once via `c.path`); consistent with the stated no-memoization discipline, just noting the 2× cost per part on big-city scenarios.
- engine/cmd/demosrv/geojson.go (`geoJSONFrameOf`) — hand-mirrors the exporter's frame construction; a future `GeoJSONFrame` field added in engine/geojson.go silently goes missing from manifests. An exported `engine.FrameOf(nf)` would remove the duplication.

## Questions

- `start` now holds `s.mu` for up to readyTimeout + identityTimeout (~3 min on a big net, vs 10 s before), and `status()`/`withActiveReplay` block on the same mutex — the menu badge freezes for the whole world build. The `withActiveReplay` comment already accepts ~10 s holds as a demo-console tradeoff; is ~1–2 min still inside that acceptance, or does `status()` deserve a lock-free snapshot?
- Is the whole-document ~1 GB sizing buffer (geojson.go:121, plus up-to-256 MiB per-part buffers alive during the split) acceptable on the deploy targets, or should sizing move to a counting writer? The comment argues one-off spike; fine if that's a considered call.
