Review of the staged M12 overlay change (`engine/scenario`: variant.go, variant_test.go, scenario.go). I could not run `go test`/`go vet` in this sandbox (command approval denied), so the golden-vector constant and suite-green claims are unverified here — static review only.

**Blockers:** none found.

**Should-fix**

1. `engine/scenario/scenario.go:150-156` — `Load` dispatch treats *any* `os.Stat` error as "manifest absent" instead of checking `errors.Is(err, fs.ErrNotExist)`. An I/O or permission error on one manifest silently reroutes dispatch (e.g. unreadable `variant.yaml` in a variant dir falls through to the plain-scenario path and reports "scenario.yaml: no such file"). Cheap to fix and squarely in the repo's fail-loud discipline.
2. `engine/scenario/variant.go:63` (`Set yaml.Node`) + `scenario.go:662` — `checkNodeTypes` walks the patch `set` mapping against `yaml.Node`'s *own struct schema* (lowercased fields: `kind`, `style`, `tag`, `value`, `content`, `line`, …). No valid patch is falsely rejected today (no `Flow` field collides), but a typo'd key that happens to match a `yaml.Node` field name (e.g. `set: {tag: 5}`) fails at variant decode with a bewildering "wants !!str" type error instead of the clean "field not found" at apply time — and it's a latent trap if `Flow` ever gains such a field name. Consider special-casing `yaml.Node` destinations in `checkNodeTypes` (skip, like `interface{}`).

**Nits**

- `engine/scenario/variant.go:185-187` — if the base dir contains *both* manifests, the chaining check fires first and misreports it as "base is itself a variant"; same message for the self-referential `base: .`. Both fail loud, message is just wrong.
- `engine/scenario/variant.go:324` — `%q` on a comma-joined string prints the leftover patch targets as one quoted blob (`"a, b"`).
- `engine/scenario/variant.go:207` — `types: []` in a variant is a non-nil override of length 0, which `validateManifest` then silently re-defaults to `[car]`. An explicitly empty type override arguably deserves rejection under fail-loud; "too early to need this" is a fine triage.
- `engine/scenario/variant_test.go:831-836` — the "anchor on id-less flow" case doesn't exercise an id-less flow (the fixture's only flow has an id); it's a duplicate of "missing anchor". The M12 addendum names id-less flows as a distinct hard-error mode.

**Questions**

- Patching a flow's `id` itself (`set: {id: new-name}`) is permitted — it rewrites the anchor namespace under the overlay's feet. Result is still strict-validated, but is that intended, or should `id` be off-limits in `set`?
