Review of the staged gate tooling (hook, review script, ADR-0013, doc updates). No engine/NATS surface is touched, so determinism/contract focus mostly collapses to correctness of the gate itself. The hook's core mechanics check out: the stamp is per-worktree (`--git-dir`), partial commits fail via git's temp `GIT_INDEX_FILE` changing the `write-tree` result, `wait || rc=1` is fail-closed under `set -eu`, and (base, tree) binding makes stamp reuse safe — identical pair implies identical reviewed content. ADR-0005/0006 references in the embedded brief match the actual ADRs; CLAUDE.md is a symlink to AGENTS.md, so the doc edit propagates.

**Findings:**

**should-fix**

1. `hooks/pre-commit:178` / ADR-0013 §4 (`docs/kb/decisions/ADR-0013-external-review-gate.md:115-118`) — the MERGE_HEAD waiver is too broad. "No meaningful merge diff" is false for conflicted merges: hand-written conflict resolutions (and evil merges — any content staged while MERGE_HEAD exists) are novel, never-reviewed code, and they pass ungated. This is the one genuine hole for honest actors, not just forgers. Minimum: correct the ADR claim and note the exposure; better: compare the staged tree against `git merge-tree` auto-merge output and gate on divergence.

2. Staged-commit completeness — `docs/kb/INDEX.md` and `docs/kb/articles/decisions/adrs.md` are modified in the working tree but **not staged**, so the commit ships ADR-0013 unregistered in the KB (AGENTS.md rules 2/4). Note the interplay: staging them after stamping changes the index tree and fails the gate, forcing a full re-review. Either stage them before running the review round, or make them the planned separate docs-only commit — but don't let the registry lag silently.

3. `scripts/external-review.sh:332-336` — `cp -n` exits non-zero on an existing destination under coreutils ≥ 9.2, which with `set -e` aborts after reviews complete but **before stamping**; on older coreutils it silently skips, archiving a stale file. Collision needs an identical `$ts-$dh-$$` runid so it's near-unreachable in practice, but the failure mode is confusing when hit. `cp` (no `-n`) or an explicit existence check is cleaner.

**nit**

4. `hooks/pre-commit:181` — `git rev-parse HEAD` on an unborn branch (orphan checkout) fails, leaving `base` empty and producing a confusing generic block message. Fail-closed, but worth a friendlier path if orphan branches ever matter.
5. `scripts/external-review.sh:245` — the hooksPath check compares against the literal `hooks`; equivalent values (`./hooks`, absolute path) trigger a spurious warning.
6. `hooks/pre-commit:200-202` — "always fail this gate" slightly overstates: `git commit -a` with a clean working tree yields the same temp-index tree and correctly passes. Conversely `-a` picking up only ungated docs edits still blocks (tree differs) — fail-closed but potentially surprising; the wording could say "fail unless the temp index matches the stamped tree."
7. `scripts/external-review.sh:288` — `wc -l` on the diffstat includes the summary line (off-by-one, cosmetic).
8. `scripts/external-review.sh:311` — `grep -qx` misses a marker with a trailing CR; fail-closed annoyance only.
9. `scripts/external-review.sh` — reviewer `.err` files are never archived on success; on failure they survive via `keep=1`, which is probably enough.

**question**

10. `git config core.hooksPath hooks` replaces `.git/hooks` wholesale — any pre-existing local hooks in a clone stop running. Intentional/acceptable?
11. Prompt-injection: reviewed code can address the reviewers directly (e.g., instruct a model to emit `REVIEW-COMPLETE` and suppress findings). ADR-0013 §4 accepts stamp forgeability for honest actors, which arguably covers this — worth an explicit sentence in the ADR since the attack rides *inside* reviewed content rather than requiring committer action.

No blockers.
