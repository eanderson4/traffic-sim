# Review — cadence split + head clustering

No blockers found. The contract-relevant change (signal-table republish cadence 100→20 ticks) carries its ADR-0006 note in the same diff, subject and payload are untouched, and the Go changes stay off the sim/recording plane (recorder keyframes, registry `UpdateState`, and CRC cadence are unchanged — replay determinism is unaffected since `PublishSignals` is a pure fire-and-forget projection of engine state).

**Should-fix**

- None.

**Nits**

- `viz/src/signals.ts:130` — head ids are no longer unique by construction. Two clusters founded by lanes of the *same* `linkIdx` (same-link lanes that fail `sameApproach` — split by distance or opposite bearings) both get id `${p.id}:${rep}`. Same column ⇒ identical colors, and MapLibre applies the shared feature-state to both features, so it renders correctly today — but the `SignalHead.id` doc ("feature id AND feature-state key", signals.ts:28) implies uniqueness, and `prevSigStates`/the source-rebuild `key` in main.ts:222 silently collapse the duplicates. A cluster ordinal suffix would restore the invariant cheaply.
- `viz/src/signals.ts:84-89` — greedy running-mean bearing can drift: each joiner only needs dot > 0 against the *current* mean, so a chain of lanes each ~89° apart can rotate the mean until members ~170° apart share one cluster; likewise Y-junction arms with identical columns and convergent (<90°) bearings inside 75 m merge into one mid-block head. Deterministic (wire link order) and cosmetic-only, so fine at the triage bar — noting it so the artifact is recognized if it shows up on a real net.
- `viz/src/signals.ts:85` — distance gates against the *running* centroid; an early member can end >75 m from the final centroid. Same class as above: deterministic, cosmetic.

**Questions**

- `engine/natsio/player.go:270-272` — the duplicate-keyframe check only compares `keyframes[0]` and `keyframes[1]`. That matches the old behavior (a re-recorded run id duplicates from tick 0, so the first pair catches it), but if partial re-records are possible the corruption could first appear deeper in the list. Fine to defer; flagging in case the store model allows mid-stream dirt.
- `engine/natsio/run.go:40` — `signalCatchUpEvery` is tick-denominated, so real-time convergence scales with `Dt` (20 ticks = 2 s only at dt = 0.1 s). The ADR text states "2 s at 1×" unconditionally; harmless while dt is fixed at 0.1, just a doc drift risk if dt ever varies.

Verified along the way: the split `%signalCatchUpEvery` / `%KeyframeEvery` blocks in run.go:168-178 preserve registry semantics; the late-join test's `≥ 60` bound is race-safe (subscription is established after the watcher has *seen* tick 60, so any received table is a later cadence publish; run holds 160 ticks with publishes through tick 160); the unchanged shared-linkIdx merge test (signals.test.ts:132) still passes under clustering (single-point shapes → null bearings → distance-only join, no setback); `columnKey`'s NUL padding is unambiguous; setback direction (−mean entry bearing) is correct for stop-line-entry = first polyline point.

REVIEW-COMPLETE
