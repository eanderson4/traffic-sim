**Blockers** — none found.

The guard scheme (closed latch → epoch snapshot → pending check → post-readiness revalidation, mirrored against stop's pending→epoch bump order) is internally consistent: I walked the interleavings (stop queued behind mu, stop landing mid-guard, stop during readiness/verify, shutdown racing autostart's channel check) and each is caught by at least one of the four checks; the "bumper cannot complete while we hold mu" invariant at supervisor.go:338-353 holds because both `stop()` and `shutdownFinal()` only decrement `stopPending` under mu. The reaper now clearing `s.active` (supervisor.go:316-319) is safe against the swap case (`s.active == a` guard) and against `startGuarded`'s own corpse-clear (by then `s.active != a`).

**Should-fix**

1. `engine/cmd/demosrv/deploy.go:372` + `supervisor.go:263-274` — within the retry window, autostart can replace an **operator-started** run that crashed: attempt 1 fails, operator starts demo X during backoff, X dies, retry sees the corpse as idle and starts the configured demo — with no epoch/intent signal that the operator ever intervened (a start, unlike a stop, bumps nothing autostart observes). ADR-0020 promises "an operator's start winning the race (left alone)"; this edge violates the spirit for a crashed operator run. Cheap fix if you care: terminal-ize on `errAlreadyActive` *ever having been observed*, or accept and note it in the ADR's autostart terminal-conditions list.

**Nits**

2. `supervisor.go:510-512` — the injected `s.ready` hook returns before the `done`/epoch checks, so test-stub runs skip the abort path entirely; production abort fidelity rests solely on `TestStopAbortsInFlightStart`. Fine today, worth knowing.
3. `engine/cmd/demosrv/main.go:1389-1395` (patch) — the `hs.Serve` error path `log.Fatalf` (and every earlier `Fatalf`) skips `defer os.RemoveAll(binDir)`, leaking the pre-warm temp dir. Pre-existing pattern, cosmetic.
