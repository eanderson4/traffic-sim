## Findings

**Should-fix**

1. `engine/metrics.go:979` (`findChains` cap) / `engine/metrics.go:1067` (`exitResolve`, `capN=3`) / `engine/metrics.go:958` (`crossedChain`, `capN=2`) — bounded chain enumeration can be silently wrong, contradicting the "loud, never silent" pin the ADR addendum sells. If ≥3 simple chains reach exit A and a 4th (unenumerated) reaches exit B, `exits` collapses to `{A}` and the despawn books confidently to a possibly-wrong exit with **no** `DroppedCrossings` count; likewise `crossedChain` with `capN=2` can agree on the first two chains while a differing 3rd goes unseen, so `ambiguous` stays false. Cheap fix consistent with the existing contract: treat `len(chains) == capN` as potentially truncated → set `ambiguous` (or `ok=false`). Needs ≥3 parallel simple chains within 8 hops, so arguably deferrable under the triage bar — but the fix is one line and the loudness guarantee is the design's stated invariant.

**Nits**

2. `engine/metrics.go:774` — mid-run `Totals()` adds `len(k.pendingGaps)` to `DroppedCrossings`; late-spawning pending IDs (jittered multi-origin order inversion) sit in the set until their injection or Finalize, transiently inflating the count. No mid-run consumer in this commit, but the NATS publisher commit will poll `Totals()` — worth a doc line or deferring gap-counting to Finalize.
3. `engine/metrics_test.go:603` (`TestKernelFirstStepDespawn`) — the comment claims it exercises the `ts == nil` reconstruction path, but `NewKernel` seeds `tstates` for pre-placed vehicles when `Trips` is on, so the defensive branch at `engine/metrics.go:561` is not reached by this test (and looks unreachable generally). Test still passes; comment misleads.

**Questions**

This matches the documented formula, so presumably intended; flagging only because the discontinuity slightly undercounts wait after burst-drain episodes.
