## Questions

1. **`supervisor.go:349` + `waitIdentity`/`waitPort` `<=` compare — intentional semantics widening?** The round-14 fix (`startGen+1` stamp, `<=` probe) means a *different* start that was already queued on `mu` when `stop()` stamped now allocates `gen == stamp` and gets aborted too — the old code explicitly protected that start ("no stale-flag abort of an unrelated spawn"). Concretely: start-A in its readiness wait, operator clicks start-B (queues on mu), then stop — B now dies with `errStartAborted`, and if B were an autostart retry it gives up terminally. "Stop kills everything that began before it" is a defensible — arguably better — semantic, and the comment at `supervisor.go:346-348` scopes the guarantee to starts beginning *after* stop completes, so I read this as intended. Confirm and move on.
