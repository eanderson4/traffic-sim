## Findings

**should-fix**

1. `scripts/import-city.sh:266,271` — `-source "import-city.sh@$REPO_REV ($NC_VER, …)"` embeds the repo HEAD commit and the netconvert version banner in `NetProvenance.Source`, which lands in the network JSON and therefore in the ADR-0012 scenario content hash (`engine/scenario/scenario.go:217` hashes the canonical network JSON, provenance included). This contradicts the refusal three lines up at `import-city.sh:263-265`, which rejects a missing extract timestamp precisely because "identical inputs hash differently": re-running the identical import after any commit now yields a different content hash anyway. Also `rev-parse HEAD` ignores a dirty tree, so the stamp can misattribute the recipe version. Either drop the volatile parts from `-source` (keep them in `import-report.json`, which is outside the hash) or record in ADR-0017 that re-import hash stability is explicitly not a goal.

**nit**

2. `scripts/import-city.sh:261` — `$SRC` is shell-interpolated into an inline Python string literal; a path containing a single quote breaks the expression, and `2>/dev/null || true` converts that into the misleading "extract has no osm3s.timestamp_osm_base" refusal. Pass the path via `sys.argv`. (Fails closed, so only a diagnosis problem.)

3. `scripts/osm-stop-nodes.py:466-471` — directionless-stop inference: at a node with *mixed* oneway tags (e.g. `yes` on one way, `-1` on another), the fallback walks forward on every way, i.e. against travel on the `-1` way, marking the junction behind the stop. ADR-0017 §4 only pins the all-ways-agree case; this residual is rare and acceptable, just noting the gap.

4. `scripts/osm-stop-nodes.py:517` — an explicit `direction` tag fighting a oneway (walked as tagged, per ADR-0017 §4) creates arm keys `incident_arms` never counts, so `len(arms) >= total` can flip the junction to `allway_stop`, not merely mark a phantom approach. The class-flip consequence goes one step beyond what the ADR records; fine to leave as a mapper-error outcome.

5. `scripts/overpass2osm.py:689-693` — dedupe keeps the first occurrence's `lat`/`lon`; a first occurrence without coordinates (e.g. a skeleton-output element mixed in) later crashes with KeyError at emission. Loud failure on malformed input, acceptable.

**question**

6. `scripts/import-city.sh:284` — generated `scenario.yaml` pins `seed: 42` for every city. Intentional showcase-seed convention (ADR-0014 picks the showcase seed once on the baseline), or just a placeholder? No action needed if intentional.
