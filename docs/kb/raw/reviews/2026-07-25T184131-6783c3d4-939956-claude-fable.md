## Review — deploy manifests + Dockerfile + public registry (staged diff)

**Verified clean:** entrypoint flags all exist with matching semantics (`main.go:57-63`); `DEMOSRV_ADMIN_TOKEN` is the documented env intake (`deploy.go:31`) and is stripped from engine children and go-build subprocesses (`main.go:142,246`); `-wspublic` without a token fatals server-side, so the entrypoint's `:?` check is a redundant-but-fine fast-fail; `demos.public.json` matches the registry schema exactly (strict `DisallowUnknownFields`, `registry.go:29-42`) — ids/run tokens valid, run ids unique, capacity > 0; repo-root-relative `data/scenarios/<city>-lean` paths resolve to `/data/...` via `WORKDIR /` + `filepath.Abs`, matching the initContainer layout; `-nobuild /opt/bin` matches `prebuiltBins`'s `<dir>/serve`+`<dir>/replay` expectation and the Dockerfile's `-o /out/` build; BackendConfig port-name mapping + NEG annotation are correct GKE usage; no NATS subject or payload changes; ADR-0020 amendment matches reality.

### Blocker

1. **README's own deploy command violates its own go-live precondition.** `deploy/README.md:120` (step 3: `kubectl apply -f deploy/k8s/`) applies `deploy/k8s/ingress.yaml`, which the ingress itself (`ingress.yaml:437-441`) and the preconditions section (README:72-84) say must NOT be applied before broker auth lands. DNS already points at the static IP (README:94-96, done 2026-07-25), so once an operator follows step 3 verbatim, the only thing keeping the publish-capable unauthenticated ws plane offline is the ws backend's *failing* `/healthz` check — and if the `/healthz` engine change ever lands before the broker-auth change, exposure is instant and silent. Make the precondition structural, not prose: move `ingress.yaml` (and `backendconfig.yaml`'s ws half, if you like) out of the applied directory (e.g. `deploy/k8s/go-live/`) or enumerate the safe files in step 3.

### Should-fix

2. **Pinned image tag vs. unique-tag workflow.** `deployment.yaml:362` hardcodes `:v0.1.0` while the documented flow (README:108-111) pushes unique tags via `kubectl set image`. Any subsequent `kubectl apply -f deploy/k8s/` (the documented update path for manifest changes) silently rolls the image back to `v0.1.0` — stale or nonexistent → ImagePullBackOff. Same root cause bites first deploy: step 1's `set image` fails (no deployment yet), then step 3 deploys `:v0.1.0`, which was never pushed. Either template the tag into the manifest per deploy or document that `apply` must be followed by `set image`.

3. **LA demo can exceed the hardcoded attach timeout on the target hardware.** `serveArgs` pins `-attach-timeout 600s` (`engine/cmd/demosrv/main.go:290`, comment says ~400 s for la-lean — measured on a dev box), but README:133 says LA driver attach is **7–15 min on 2 vCPU**. The shipped registry advertises `la`; at the top of that range the serve child dies at attach and the switch fails after ~10 idle minutes. Add it to the LA caveat list (alongside the memory UNVERIFIED note) or raise the timeout before advertising LA.

### Nit

4. `deploy/k8s/deployment.yaml`: public-facing pod runs as root with no `securityContext`/`automountServiceAccountToken: false`, and the ~5 GB emptyDir has no `sizeLimit`. Acceptable at this stage per the triage bar; note for go-live.
5. `-overlaydir /data/networks/overlays` (entrypoint:275) is never populated — the bucket holds only `scenarios/` + `netcache/` — so `/overlay/*` always 404s in this deployment. Harmless by design (flag doc says missing dir just 404s), but if any city demo's viz expects zone overlays, they need a bucket prefix + initContainer line.
6. pnpm is pinned only in the Dockerfile (`pnpm@10.20.0`); `viz/package.json` has no `packageManager` field, so local builds and the image can drift.

### Question

7. Is the `/healthz` engine change planned to land in the same commit as broker auth? If they can land separately, finding 1 stops being theoretical — worth stating the coupling explicitly in ADR-0020's go-live section.

No determinism or contract findings: seeds are pinned in the registry, no engine code changes, no NATS subject/payload changes.
