## Findings

**Blockers:** none.

The guard lattice (closed latch → epoch snapshot → stopPending → idle check → re-check closed → post-readiness revalidation in pending-then-epoch order) is consistent with `stop()`/`shutdownFinal()`'s pending-first/bump-second write order; I traced the interleavings and found no start that is both unrefused and unabortable. The reaper's new `s.active = nil` is compatible with `stopLocked` (nil → no-op, `main.go:413-428` working tree) and `withActiveReplay` (nil ≡ done-closed). `handleNet` validates `{file}` against the registry before any cache-fill, so the public-GET surface is bounded to registered demos.

**Should-fix**

- None that clear the repo's own triage bar. The one semantic change that reaches local dev — a start racing a queued stop now 409s instead of queueing (`supervisor.go` `startGuarded` stopPending check; `main.go:485` handleStart 409 mapping) — is deliberate and recorded in ADR-0020 Consequences, so it's a decision, not a defect.

**Nits**

- `deploy.go` (adminGate/routes design): the gate is opt-in per route registration (`main.go` routes(), the seven `s.adminGate(...)` wraps). A future mutating route added without the wrap ships open silently. A method-based middleware (401 all non-GET/HEAD when token set) would fail closed by construction. Noting for the record; ADR-0020 already frames the current shape as "gated set is exactly the POSTs."
- `main.go:1256` (patch line): `log.Fatalf("demosrv: -wspublic %q: …", wsPublicURL, err)` echoes the rejected URL verbatim — a userinfo-bearing typo (`wss://user:pass@host`, the exact case validateWsPublic rejects) lands its password in the startup log. Fatal path, operator's own log; trivial to redact if you care.
- `deploy.go` `startGuarded` entry: a `shutdownFinal` whose pending mark lands between a start's epoch snapshot and its pending check surfaces as `errStartAborted` ("stop requested") rather than `errSupervisorClosed` — autostart's log line says "aborted by a stop request" during a shutdown. Behavior (no spawn, no retry) is correct either way; label only.
- `deploy_test.go` `TestResolveAdminToken`: hand-rolled save/restore of the env var; `t.Setenv` does this and additionally blocks accidental `t.Parallel`.

**Questions**

- Flag-supplied token: `stripEnv` keeps `DEMOSRV_ADMIN_TOKEN` out of children, but a token passed via `-admintoken` stays readable in demosrv's own `/proc/<pid>/cmdline` to any same-UID process (including the engine children the stripping protects against). The comments acknowledge argv visibility and the docs steer to the env path — was a warning (or refusal) for `-wspublic` + argv-token considered and rejected as over-hardening? Fine either way; just confirming it was a choice.
- `autostartBackoff` totals ~14 s across 4 attempts (2+4+8). Is that empirically enough for the "slow port release after pod reschedule" case the retries exist for? If not, it's a constant tweak, not a structural issue.

**Contract / ADR discipline** — clean. No NATS subject or payload changes. The HTTP API changes (401/409 semantics, verbatim ws advertisement) are covered by ADR-0020, which correctly flags the unauthenticated publish-capable ws plane as a go-live precondition and files the ADR-0006 amendment in the pending-ADR queue (`adrs.md:46`). **Determinism** — no engine-core paths touched; no map-iteration/float/wall-clock/RNG concerns in the diff (runNonce remains crypto/rand, pre-existing).
