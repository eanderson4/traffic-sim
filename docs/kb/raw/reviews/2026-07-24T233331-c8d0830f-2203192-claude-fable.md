## Findings

**Blockers** — none.

**Should-fix**

1. `engine/natsio/driver/driver.go:181` — The hello deadline-exhaustion error discards the last `nc.Request` error. The old path wrapped it (`%w`); now a run that fails because of, say, a permissions/auth error on the subject reports only "deadline exhausted — engine contract plane never came up", which is actively misleading and un-`errors.Is`-able. Keep the last error and wrap it: `fmt.Errorf("driver: hello: deadline exhausted (%s): %w", cfg.MetaWait, lastErr)`.

**Nits**

2. `driver.go:405-407` — Production nil-guard on `d.wantLane` exists only because the test builds `Driver` by struct literal (`driver_test.go:338-355` initializes `wantRoute` but not `wantLane`). Initialize the map in the test literal and drop the guard; the guard also masks future construction-site bugs.

3. `driver.go:342-348` — Fleet cleanup is keyed on `d.fleet`, so `wantLane`/`wantRoute`/`routed` entries created for an obs ego that never made it into `d.fleet` (claim reply lost but engine granted) are never reclaimed after despawn. Pre-existing shape for `routed`/`wantRoute`; `wantLane` just joins it. Note-and-defer.

4. `driver_test.go:246-250, 367` — The file comment says over-budget egos stay "COMPLETELY untouched (no wantRoute entry, no routed mark)", but by design they do get `wantLane` entries at first observation (that's the determinism freeze). The assertions are right; the prose overstates. Worth one word so a future reader doesn't "fix" the wantLane write.

**Questions**

5. `driver.go:411-415` — The budget meters every draw, including exitCache memo hits, which are cheap after warmup: a 1000-vehicle burst on one already-scanned origin lane still takes ~32 ticks to route at the default 32/tick, with every deferred vehicle on kernel-default routing meanwhile. Metering only cache misses (the actual O(network) scans) would bound the real cost without the artificial rollout delay. Plausibly "too early to need this" — flagging as a question, not a fix.

6. `driver.go:81-83` — `RouteBudgetPerTick <= 0` means "default 32"; there is no way to configure "unlimited" (old behavior) short of `MaxInt`. Fine if intentional.

**Determinism / contract checks (clean)**

- `pickExit` derives a fresh domain-labeled stream per call (`destinations.go:124`), so deferring a draw by N ticks cannot shift any RNG sequence; the frozen `wantLane` keeps the draw's lane input identical to the un-budgeted behavior, so budget on/off and budget size never change *which* exit a vehicle draws — only when the intent first goes out. Matches ADR-0007 discipline.
- Budget admission walks `obs.Egos` slice order (deterministic frame order), not a map. The fleet-cleanup map iteration is order-independent deletes. No wall-clock in any decision path (the hello `time.Now` is connection bootstrap, not simulation).
- No NATS subject or payload changes; `RouteBudgetPerTick` is local driver config, off the wire. No ADR note required.
- Hello retry math is correct: request timeout capped at remaining budget, sleep capped at remaining budget, negative-duration sleep degrades to no-op then exits at the top of the loop. `MetaWait` now genuinely bounds `New`.
- Test synchronization is sound: `onObs` runs on the test goroutine (state asserts are race-free), subscriber counter is mutex-guarded, and the quiet-interval check at `driver_test.go:411-430` correctly avoids the single-lucky-read false pass.
