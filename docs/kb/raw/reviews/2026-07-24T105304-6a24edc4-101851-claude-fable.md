## Should-fix

**S1. ADR-0006 addendum's "un-routed runs are bit-identical" over-claims** — `docs/kb/decisions/ADR-0006-nats-message-contract.md` (addendum, determinism note) vs `engine/rightofway.go:146-154` and `:255-259`. The virtual-walk fix changed held-turn semantics independently of routing: old `gateTarget` applied `v.HeldTurn` at *every* hop of the sight walk (and old `exitBlocked` at every hop past the box); the new probe consumes it after the first crossing. A run with turn intents but **no** routes whose sight walk crosses two multi-successor lanes within `maxSightM` gets a different gate target → different braking → different trajectory. The new behavior is the correct prediction of `boundaries()`, but the ADR's bit-identity claim should say "runs without route *or turn* intents" (or note the held-turn probe fix explicitly). One-line doc amend; determinism claims in an ADR are the one place this repo shouldn't round up.

## Nits

- `engine/routing.go` `routeTable`: memo growth is bounded only by client input — any driver-grant client can cycle `Route` across valid lane IDs, and each distinct valid destination allocates a `[]int32` of len(lanes) (~224 KB on a 56k-lane network; all-lanes worst case ~12 GB). Exit-routing draws only from exit candidates so real use is bounded to hundreds of tables. Fine for local-first v1 — but it's client-controlled server memory on a public contract; worth one line in the KB so the deferral is visible when multiplayer (ADR-0006 §9) arrives.
- `scripts/chicago/scorecard.py`: `stops` is now the chosen set's interval sum, correctly labeled `(set X)` — but the `trips` array carries authoritative per-trip stops network-wide; `sum(t["stops"] for t in m["trips"])` would give a true network figure with no set-scoping caveat. Take or leave.
