# Review — VCR replay wiring (demosrv proxy + viz replay panel)

**Blockers:** none found.

## Should-fix

1. **The feature ships dark — no UI can start a recording.** `/api/demos` now carries `recordings` + the `kind` discriminator (engine/cmd/demosrv/registry.go:319, main.go:255), and `POST /api/replay/{id}/start` exists, but the menu reads only `demos` (viz/src/demos.ts:130) and the in-app switcher likewise. Nothing renders a recording card or posts the start; the only entry point is curl. If menu wiring is a planned follow-up commit, note it in the commit message; otherwise the output-only `Kind` field has no consumer and the panel is unreachable in practice. (Related: `Recording` has no `tags`, which the card renderer requires — worth deciding before the menu commit.)

2. **One transient poll failure permanently kills the replay panel.** `ReplayPanel.poll()` → `hide()` clears the interval on *any* refresh failure (viz/src/replaypanel.ts:219–223), including a single 3 s `AbortSignal` timeout or a blip while demosrv is busy — the replay keeps running but its controls are gone until a full page reload. The 404 case (child really gone) and the network-failure case deserve different handling: hide on 404, tolerate N consecutive fetch errors otherwise.

## Nits

3. **Overlapping status polls can land stale state.** 1 s `setInterval` with a 3 s per-request timeout and no in-flight guard (replaypanel.ts:216, 127) means a slow response can resolve after a newer one and briefly overwrite `status` backwards. Self-corrects on the next poll; a reentry guard like `seekBusy` would close it.

4. **Recordings-only registry is rejected.** `LoadRegistry` still requires `len(reg.Demos) > 0` (registry.go:378-ish, unchanged), so a demos.json with only recordings fails with "no demos". Fine today, surprising later.

5. **Readiness probes only the ws port.** If an unrelated process holds 8901, the replay child exits at bind (cmd/replay/main.go:110–114 is fatal) and the supervisor burn-waits `readyTimeout` on the ws port before erroring (supervisor.go). Pre-existing pattern; a dead-child fast-path in `waitReady` would tighten it. Not needed now.

## Questions

6. **dt deep-link hint vs the recording's actual dt** (replay.go:33–43): if the scenario manifest's `dt` is edited after a recording is made, the viz paces every frame wrong from the URL hint while `/status` carries the authoritative dt that nothing reconciles. The comment and the KB deferral (ab8b039) acknowledge this — confirming it's intentionally deferred, not forgotten.

7. **`serve` absolutizing `spec.Net.Path` into RunMeta** (engine/cmd/serve/main.go:148–154): schema-unchanged value change to a durable/published record. Scenario runs already recorded absolute paths (`Scenario.NetPath` is resolved absolute, scenario/scenario.go:130), so this only changes `-netfile` runs and there's precedent — but it does bind recordings to the machine's filesystem layout (moving the repo breaks old stores). Fine under ADR-0004 local-first; worth one line in the commit message since RunMeta is contract-adjacent (rule 5). Note `filepath.Abs("")` → cwd would be a landmine, but serve requires `-scenario` xor `-netfile`, so `Path` is never empty here.

## Checked and clean

- **Determinism:** no map iteration in sampled paths (registry loops are slices; `seen` is membership-only); no wall clock or RNG enters sim state; SeekGate/`buffer.reset` are viz-render-side only. Backward-seek reset semantics (drop history, never lerp across the jump, duplicate-tick paused republication is not a seek) are correct and pinned by tests.
- **Contract:** new `/api/replay/*` endpoints are the localhost UI plane (ADR-0002 carve-out already argued for the control plane; loopback enforced in cmd/replay); no NATS subject or payload schema changes. `clearCongestion`'s whole-feature-state wipe is safe — `ratio` is the only key on the `network` source (signals live on their own source).
- **Proxy:** `/status` in the player reads mutex state directly and never queues behind a seek on the control channel, so the panel's 3 s poll won't spuriously time out mid-seek; explicit verb routes (no `{action}` wildcard) keep the proxy closed; 1 MiB body cap and 502-on-unreachable are sensible.
- **Supervisor:** kill-before-spawn covering both kinds preserves store exclusivity and the single ws port; corpse discipline in `activeKind` matches `status`.
