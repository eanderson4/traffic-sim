## Review — demosrv public deployment (ADR-0020)

**Blockers:** none. Concurrency invariants (closed latch before abort stamp, gen-under-mu, `<=` probe compare, corpse-clearing in the idle guard) all check out under Go's seq-cst atomics; all seven mutating POSTs are gated (`main.go:387-399`); the ADR covers the `ws`-advertisement semantic change and the new env var, so the contract rule is satisfied. No NATS subject or sim-path changes — determinism concerns don't apply here.

**Should-fix**

1. `supervisor.go:349-352` — the `startGen+1` stamp with `<=` probes now spuriously aborts a *fresh* start that wins the mu race against a pending `stop()`: B queues on mu after the stamp, acquires before stop, allocates gen N+1 ≤ stamp N+1, spawns, and its probes kill it. The old `==` design explicitly preserved queued-later starts ("no stale-flag abort of an unrelated spawn"); the new comment claims only starts "after stop completes" are unaffected, which quietly narrows that guarantee. Benign UX (operator re-clicks), but the comment should say so honestly — or stamp-and-compare could snapshot gen at mu-acquisition. Accepting it as-is with a one-line comment amendment is a fine triage.

2. `supervisor.go:350-352` — two overlapping `stop()`s wipe each other's pre-lock stamp: stop1's `abortGen.Store(0)` under mu erases stop2's stamp while stop2 still waits on mu; a start that then beats stop2 to mu runs the full ~660s readiness wait with stop2 queued behind it — the exact case the stamp exists to prevent. The shape predates this diff, but this commit reworked the mechanism (and the double-click-stop + autostart-retry mix makes concurrent stops slightly more plausible). A counter or stop-owner check would close it; deferring with a note is also defensible.

**Nits**

3. `deploy.go:296` — `CutPrefix(..., "Bearer ")` is case-sensitive and single-space-only; RFC 7235 makes the scheme case-insensitive. Irrelevant for your own clients, occasionally relevant for header-normalizing middleboxes.

4. `main.go:1227` (log line) — startup log prints `*addr`, not `ln.Addr()`; with `-addr :0` it announces `:0`. Cosmetic.

5. `main.go` Serve-error path calls `sup.shutdownFinal()` but never closes `srv.shutdown`; harmless today only because `log.Fatalf` exits before the backoff sleep matters. A future non-fatal path there would leak the autostart goroutine.

**Questions**

6. `hs.Close()` on SIGTERM (pre-existing, unchanged) hard-drops in-flight responses — on the public pod that's a client mid-download of a hundreds-of-MB `/net/{file}` chunk at every rolling redeploy. `Shutdown(ctx)` with a short deadline may be worth it when the deploy manifests land; fine to defer.

7. `-autostart` with a typo'd id serves an idle menu (deliberate, ADR-documented) while every other flag misconfiguration fatals fast. Registry is already loaded pre-listen, so a startup existence check would be free — but the ADR's debuggable-beats-crash-looping rationale is coherent; flagging only for consistency awareness.

The ADR's own deployment-precondition callout (unauthenticated publish-capable ws plane behind `-wspublic`) is the real go-live risk and is correctly flagged as gating deploy, not this commit.

REVIEW-COMPLETE
