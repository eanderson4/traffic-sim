## Should-fix

1. **`engine/cmd/demosrv/geojson.go:111` — `netKey` reads and SHA-256s the entire network file on every `/net/` request, and the part path does it twice** (`part()` at geojson.go:217 hashes, then calls `c.path()` at geojson.go:120 which hashes again). For la-lean that's ~10 full reads of a multi-hundred-MB `network.json` per page load (manifest + 4 sequential parts × 2). Works, but a `(path, mtime, size) → hash` memo — or passing the already-computed hash from `part()` into a `path` variant — removes most of it cheaply.

2. **`engine/natsio/bus.go:272` — `sigMaxPayload = 4 << 20` is the third hand-copied instance of the broker cap** (also `engine/cmd/serve/main.go` and `engine/cmd/replay/main.go` literals). If someone later adjusts one, the "a single oversized program fails the run loudly" guard at bus.go:216 silently validates against the wrong cap. Export one const from `natsio` and have both cmds use it.

3. **`engine/cmd/demosrv/supervisor.go:214` — `/api/status` reports the demo as active for the entire identity phase** (mirror is stored right after spawn, up to 660 s before readiness). The menu's running-card deep link during that window navigates to a run that can't stream yet; the viz watchdog message softens it but a `starting` state in the snapshot would be truthful. Acceptable to defer — record it.

## Nits

4. `engine/cmd/demosrv/supervisor.go:254` — `stop()` snapshots `startGen` before taking `mu`; a `start()` that increments after the load isn't aborted and `stop()` then blocks up to 660 s on `mu`. Window is microseconds and the dev server tolerates it, but the comment claims the abort "is always the LATEST generation," which this race falsifies.
5. `engine/cmd/demosrv/geojson.go:95` — `isManifest` substring-sniffs `"parts"` in the first 4 KiB; a single-file net whose head contains that byte sequence (lane id literally `parts`) gets mislabeled and served `no-store`. Harmless, but a `json.Decoder` peek of top-level keys would be exact.
6. `engine/natsio/bus.go` `onSignalRequest` — malformed-request logs (non-inbox reply, non-empty payload) have no first-3 budget like every other loud path; a buggy observer republishing requests can spam stderr at wire rate.
7. `engine/cmd/demosrv/geojson.go` `geoJSONFrameOf` duplicates the exporter's frame construction; a future `GeoJSONFrame` field added in `engine/geojson.go` silently misses the manifest. Export a `FrameOf(nf)` helper from `engine` instead.
8. `viz/src/netload.ts` `fetchNetworkOnce` — `doc.parts as string[]` is unchecked; a malformed manifest with non-string entries produces `fetch(undefined)` rather than a clear error.
9. `viz/src/main.ts` `requestSig` — the `retry` flag is effectively redundant: a reply gap implies the set can't complete (chunks are sent once), so `!completed` already covers it; at worst it fires one redundant pull after a success. Fine to leave.
