**should-fix — view-only probe false-positives on the live public deploy (confirmed).**
`viz/public/play.html:11950`, `viz/src/hero/timingpanel.ts` (`runnerAvailable`), `viz/src/hero/main.ts` (probe wiring). The probe treats GET `/api/timing/run` → 200 as "runner live". I probed the deploy named in the diff: `https://show-beat-the-signal.phantomjam.pages.dev/api/timing/run` returns **HTTP 200** — Cloudflare Pages ships no `404.html`, so its SPA fallback serves `index.html` with 200 for extensionless paths. Result: on the public link the Run buttons are *enabled*, and a visitor's POST dies with a confusing error — the exact opposite of the "Run disables itself with a notice" behavior `docs/show/signal-game-plan-2026-08-29.md` (diff line 8986) documents as verified.
