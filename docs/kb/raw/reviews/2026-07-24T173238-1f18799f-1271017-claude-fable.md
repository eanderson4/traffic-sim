## Review — chunked GeoJSON (ADR-0018), demo identity probe, sig-chunk client, themes/stop signs

Reviewed the staged patch against repo HEAD (note: the ADR-0016 *server-side* files — `engine/natsio/bus.go`, `sigframe.go`, `server.go`, `player.go` — are modified but **unstaged**; this commit ships the client half only).

### Blocker

None found. Engine determinism untouched (exporter-only Go changes; float/Map work is viz-side, insertion-ordered, deterministic). NATS payload/subject changes are covered by accepted ADR-0016; the part-URL scheme by ADR-0018.

### Should-fix

1. **`engine/cmd/demosrv/supervisor.go:137-163` + `:284-303` — `start()` holds `s.mu` across `waitIdentity` (up to 600 s).** `status()`, `stop()`, and `withActiveReplay` all take the same mutex, so during an la-lean start (~400 s by your own numbers) the demos menu's 3 s status polls hang and pile against the browser's per-host connection cap, and `/api/stop` cannot cancel a mistaken start until the identity phase completes. Previously `waitReady` bounded this at ~10 s. Consider a lock-free status snapshot and/or probing outside the lock with an epoch check.

2. **`viz/src/tssg.ts:151` — `parseSigChunkHeader("")` throws, but nats.ws `MsgHdrs.get()` returns `""` (not `undefined`) for a missing key** (`headers.js` `get()` falls through to `return ""`). Any sig frame that carries *any* headers without `sig_chunk` will be rejected and flip the HUD into error state on every frame. Works today only because HEAD's engine publishes headerless frames. Treat `""` as absent; the test at `viz/test/sigchunk.test.ts:3646` currently pins the wrong contract (`""` in the malformed list).

3. **`viz/src/main.ts:327-343` — broadcast rounds and `requestSignalTable` replies interleave into one accumulator.** The engine publishes cadence chunks and reply chunks from different goroutines; interleaved `1/n,1/n,2/n,2/n…` streams read as regressions, aborting *both* sets, and each abort fires another request once `sigReqInFlight` clears — a possible request ping-pong on big tables (self-healing, but wasteful, and it defeats the catch-up the request exists for). Since the server side is still unstaged, consider tagging replies (separate accumulator, or a generation id header) before that half ships.

### Nit

- `engine/cmd/demosrv/supervisor.go:305-309` — `probeRunMeta` is dead code, and its comment is false: `waitIdentity` calls `natsio.ProbeRunMeta` directly, and a package-level `func` (not a `var`) can't be stubbed at all.
- `engine/cmd/demosrv/main.go:329` (and `replay.go:134`) emit `ws=ws://…` raw while `demos-core.ts` `buildAppURL` percent-encodes — the "must agree" comment now holds only after URL parsing; the two pinned test strings differ. Harmless, but pick one encoding.
- `viz/src/config.ts:39` — `localStorage.getItem` unguarded: in storage-disabled browsers property *access* throws SecurityError (the `typeof` check doesn't cover Chrome's blocked-cookies case), which would kill `loadConfig` entirely. demos.html and main.ts wrap theirs in try/catch; do the same here.
- `viz/src/main.ts` — `applyLayerToggles` reads `mapReady` (declared later, `main.ts:305`) in TDZ; currently unreachable only because the loading overlay blocks legend clicks until after map creation. Fragile ordering — hoist the declaration.

### Question

- Is the client-first split for ADR-0016 chunking intentional (server half in a follow-up reviewed commit)? The client is back-compatible either way, but the `ts.{run}.state.sig.req` path is dead until the responder lands, and `requestSig()` fires a 10 s `requestMany` on every attach against a subject with no responder in HEAD.
- `identityTimeout` (600 s) exactly equals the `-attach-timeout` passed to serve — a build finishing right at the boundary attributes the failure to whichever timer fires first. A small skew (identity slightly longer) would keep the error message pointing at the real cause.

Solid work overall: the manifest/part contract is clean (atomic writes, manifest-last, hash-pinned URLs, byte-identical small nets), the netCache double-check lock is correct, the accumulator's never-half-swap discipline is well-tested, and the navy palette is pinned byte-for-byte.
