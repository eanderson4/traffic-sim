## Review — chunked GeoJSON (ADR-0018), TSSG chunking + pull resync (ADR-0016), run-identity probe, viz themes/stop signs

Determinism: clean. Chunk packing is a pure function of file order (`signalChunksMax`), no map iteration on any sampled/published path, float work is viz-only, wall clock appears only in demosrv orchestration (`runNonce`, probes) — not the sim. Contract: the new subject (`ts.{run}.state.sig.req`), `sig_chunk` header, `MaxPayload` 4 MiB, manifest/part URLs, and the `junction`/`row` GeoJSON properties are all covered by ADR-0016/0017/0018 ratified in this same diff; the legacy-reader hazard is documented. Verified: NewBus builds on NewPublishBus and closes the sig.req responder on its error path; the log stream (`ts.{run}.log.>`) doesn't overlap `state.sig.req`; nats.ws 1.30.3 has `requestMany`; tick patch offset 8 matches the frame layout; part-URL parse/404 paths hold.

**Blockers:** none found.

**Should-fix**

1. `engine/cmd/demosrv/main.go:58` vs `main.go:158` — the two client-facing ws values diverge. `/api/demos` carries `reg.WS = wsClientURL()` (verbatim listen address, computed once), while start URLs use `advertisedWsURL(r)` (request-host substitution for loopback/wildcard). The running-card deep link (`demos.ts` `engineWs`) therefore disagrees with the start URL — the comment in `handleStart` says they must agree. Concretely: with `-ws 0.0.0.0:9443`, deep links carry `ws://0.0.0.0:9443`, which Firefox/Safari won't dial; with the default loopback listen reached via `localhost`, deep link says `127.0.0.1` while start says `localhost` (works, but the pinned shapes differ). `handleDemos` has `r` in hand — compute `ws` per-request with the same helper.

2. `engine/cmd/demosrv/geojson.go:185` — `part()` runs `scenario.Load` for validation, then `c.path()` runs `scenario.Load` again: each Load parses the network JSON **and** `CompileNet`s it plus canonical-re-marshals for the hash. The header comment's "scenario.Load per request is trivially cheap" inverts at exactly the scale chunked serving exists for — la-lean means 2 full ~GB parses+compiles per part × 4 sequential part fetches, likely the dominant share of the measured ~150 s load. Reuse the loaded scenario (pass it through, or split `path` into a hash-keyed inner helper). Works as shipped, so should-fix, not blocker.

**Nits**

3. `engine/cmd/demosrv/main.go` (handleStart) embeds the ws param unencoded while `viz/src/demos-core.ts:buildAppURL` uses `encodeURIComponent` — both parse identically via URLSearchParams, but the two "must agree" tests now pin different literal shapes.
4. `main.go:158` `advertisedWsURL` mangles IPv6 request hosts: `[::1]:8080` → `ws://::1:8443` (brackets not restored).
5. `viz/demos.html` inline script duplicates both palettes as literals — drift risk against `theme.ts` (acknowledged in the comment, and `theme.test.ts` doesn't reach it).
6. `viz/src/main.ts:392` — a malformed `sig_chunk` header / decode error flips the HUD to "disconnected" though the socket is fine (pre-existing pattern, now reachable via header parse).
7. `engine/natsio/bus.go` `PublishSignals` — `noteFrameSize` runs even when the publish failed, so the one-time >1 MiB watermark can log for a frame that never left.

**Questions**

8. `viz/src/main.ts:346` — after 3 failed pulls the retry budget only re-arms on a completed generation. During a **paused replay** there is no broadcast cadence, so a client whose 3 attach-time pulls all fail (transient disconnect) shows no signals until resume. Accepted bound, or worth re-arming on reconnect?
9. Part URLs pin `{schema}.{hash12}` but not the chunk threshold/count — fine while `geojsonChunkThreshold` is compile-time; if it ever becomes a flag, two demosrv builds sharing a cache dir could mix part sets under identical names.
