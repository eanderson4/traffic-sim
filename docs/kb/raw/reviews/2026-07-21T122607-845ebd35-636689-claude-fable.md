## Review — M12 variant overlays (staged diff)

Verified against ADR-0012 §4 + both M12 addenda. The design-to-implementation mapping is faithful: dispatch is fail-loud on non-ENOENT stat errors, patch application order is `v.Patches` slice order (the only map iteration in an output path is the leftover-patch error set, which is sorted, variant.go:113–120), the hash frames the materialized manifest under `scenario.yaml` with run coordinates stripped so identity/hand-written equivalence holds, `checkNodeTypes`'s `yaml.Node` bypass is correctly scoped and `rejectDupKeys` closes the duplicate-key gap it opens, and no NATS subject/payload is touched. No blockers found.

**Should-fix**

1. `variant.go:154` — `network: ""` silently inherits the base network. This is the one empty override the file's own discipline misses: `types: []`, `params: {}`, `spawner: {}` are all rejected as "empty override — omit the field to inherit" (variant.go:308,311,314), but an explicit empty-string network no-ops instead of failing loud. Same rationale as those three; same one-line guard.

**Nit**

2. `variant.go:140` vs `:154` — `validateManifest(&eff)` runs before `eff.Network = v.Network`, so its manifest-name check (scenario.go:525) sees the *base* network. `network: variant.yaml` therefore escapes the crisp "names a manifest file" rejection and fails later as JSON-parse noise ("variant network variant.yaml: invalid character…"). Loud, so not a correctness hole — but off-message relative to the check you just added.
3. `variant.go:110` (patch flow) — a `ticks: 0` override reaches `validateManifest` and reports "missing ticks", which misdescribes an explicitly written zero. Loud, just a confusing message.
4. `variant.go:451–461` — `mergeMapping` rescans `dst.Content` to replace a value it already located via `mappingValue`. Harmless at flow sizes; noting only because it's a doubled lookup.

**Question**

5. `variant.go:295–303` — `validateVariant` re-implements `resolvePart`'s lexical checks for `base` and `p.Part` (backslash, drive-letter, clean, abs) as a third and fourth copy. Intentional divergence (base legitimately allows `../`, patch parts don't touch disk in the variant dir), but consider extracting the shared lexical core before a fifth copy drifts — deferring is a valid triage outcome per the one-round rule.

**Caveats on verification:** the sandbox denied `go test`, so I could not re-run the suite or confirm the golden vector `642ec5aa…` (variant_test.go:211) and the CRC bit-identity test myself; the implementation-notes addendum's "full engine suite green" claim is taken on trust. Test coverage itself is strong — identity hash, hand-written equivalence (including the network-replacement and shadowing layouts), CRC run identity, and every failure mode in the addendum has a fixture.

REVIEW-COMPLETE
