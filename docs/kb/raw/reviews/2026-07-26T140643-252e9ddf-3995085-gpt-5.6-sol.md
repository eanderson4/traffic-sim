- **blocker** `docs/kb/decisions/ADR-0026-batched-intents.md:50` — `schema_version` is currently the global wire version negotiated by hello, not an intent-encoding discriminator. Using `3` while retaining v2 compatibility leaves no valid upgrade path: bumping the global version rejects v2 controllers, while retaining hello v2 lets new default-on drivers attach to old engines that cannot decode TSIB. Define capability negotiation or a separate encoding header and explicit old/new compatibility matrix.
- **should-fix** `docs/kb/decisions/ADR-0026-batched-intents.md:212` — Headerless TSIB is not guaranteed to be rejected structurally. A one-record TSIB is 68 bytes and the v2 decoder can accept it when bytes 40–41 happen to decode as route length 24, potentially producing a corrupt v2 intent. The “loud, never silent” claim and proposed test are therefore insufficient.
- **should-fix** `docs/kb/decisions/ADR-0026-batched-intents.md:107` — Calling batching “not a contract change” directly contradicts line 145 and the repo rule that wire payloads are public contracts. Say “no downstream semantic change”; TSIB is unquestionably a message-contract change.
- **should-fix** `docs/kb/decisions/ADR-0026-batched-intents.md:122` — The ~23.8k split limit lacks header headroom. At 23,830 records the payload leaves only 32 bytes below 1 MiB, approximately consumed by the serialized `schema_version` header alone. Specify a conservative cap and boundary publish test; one publish failure otherwise drops an entire large batch.

Collect-before-publish can shift every intent one or more ticks while engine p99 still looks improved; acceptance needs batch-age/applied-lag percentiles.
