## Should-fix

**1. `autostartDemo`'s already-active bail is check-then-act; the guarantee its own test claims doesn't hold.** `engine/cmd/demosrv/deploy.go:93` reads the lock-free status snapshot, then `deploy.go:99` calls `sup.start`, which unconditionally `stopLocked()`-replaces whatever is active (`supervisor.go:192`). Interleaving: autostart sees idle → operator's authed POST wins the race to `sup.mu` and spawns → autostart's `start` queues on `mu` for the operator run's whole readiness wait → acquires it and kills the operator's just-ready run. `deploy_test.go:271` (`TestAutostartBailsWhenRunAlreadyActive`) asserts the operator run survives, but only tests the sequential case — the interleaved one loses. Fix is small: a `startIfIdle` variant that re-checks `s.active` under `mu`, used only by autostart.

**2. Autostart can spawn an orphaned engine child after shutdown.** The signal handler (`main.go:130-135`) does `sup.stop(); hs.Close()` and the process exits — but the autostart goroutine may be sleeping in a backoff window (up to 2+4+8 s, `deploy.go:109-110`) and will then `sup.start` a real engine child. `childSpawner` sets no `Pdeathsig`/process group (`main.go:186`), so the child survives demosrv's exit and squats on the ws port. Bounded in K8s (container teardown kills the namespace) but real for local `-autostart` use. Fix: a shutdown channel that both aborts the backoff sleep and makes the supervisor refuse starts after final stop.

## Nits

- `main.go:126`: `hs.Addr` is now dead — `Serve(ln)` ignores it. Harmless, mildly misleading.
- `deploy.go:64`: `strings.CutPrefix(..., "Bearer ")` is case-sensitive and single-space; RFC 7235 makes the scheme case-insensitive. Fine for an operator-controlled client set — noting only.
- ADR-0020 line 121 ("default local behavior is byte-for-byte unchanged") is slightly overbroad: the 10 s `ReadHeaderTimeout` (`main.go:126`) now applies locally too. Behavior change is benign; the ADR sentence just overclaims.
- `resolveAdminToken` env fallback means a stray `DEMOSRV_ADMIN_TOKEN` in a dev shell silently 401s local POSTs. Documented in the flag help; acceptable, but a startup log line ("admin gate ON, token from env") would make the surprise diagnosable.
- `deploy_test.go:377` `syscall.Mkfifo` is POSIX-only — consistent with the package's existing `sleep`-stub discipline, so fine unless non-Linux CI ever appears.

## Questions

- `-wspublic` is verbatim with zero validation — a typo (`https://…`, trailing slash, bare host) is advertised to every client and only fails in the browser. ADR-0020 makes "operator authoritative" the design, so presumably accepted; a startup warn on a non-`ws`/`wss` scheme would cost two lines.
- With GETs public, `/net/{file}` serves ADR-0018 chunked GeoJSON (city nets are hundreds of MB) unauthenticated on the public pod. Egress/abuse is an infra concern (LB/CDN), not demosrv's — flagging so it's a conscious deferral.
