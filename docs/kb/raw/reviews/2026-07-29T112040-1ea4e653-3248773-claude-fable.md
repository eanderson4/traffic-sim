# Findings

## Blocker

**B1 — Warm start + demand director can silently double-spawn (or spuriously reject) the verbs in the `(startTick, startTick+Lead]` overlap window.**
`engine/natsio/demand/director.go:284` (`fastForward`) skips arrivals with `at ≤ startTick`. But the cold run's director had sent verbs up to `startTick+Lead` (onSnapshot sends while `at-tick ≤ f.Tick+Lead`, director.go:309), and those accepted directives are in the restored `dirQueue` (keyframed). The warm run's director re-sends all of them. The only dedupe that survives the restart is `EnqueueSpawn`'s scan of `dirQueue`/`dirNew` (engine/director.go:154–162) — the Contract-layer `c.verbs` reply memory that exists exactly for "restart overlap" (engine/natsio/contract.go:765–767) is a fresh empty map in the warm process and is not keyframed. So: while the original directive is still queued, the duplicate is rejected (benign but inflates `Rejected`); once the original has been injected and removed — entirely plausible in batch mode (`-pace 0`), where the engine outruns the verb round-trip for the earliest ticks in the window — the duplicate is **accepted and spawns a second vehicle**, silently diverging from the cold program. That contradicts ADR-0029's stated property ("the program from that tick on is identical") and the diff's own director.go comment. Neither bit-exact test covers it: `TestWarmStartRoundTripIsBitExact` and `TestRunLiveWarmStartIsBitExact` both use the built-in spawner, and `TestFastForwardMatchesTheColdProgram` tests sampler position only. Fix direction: seed the warm run's verb-dedupe (or skip set) from the restored `dirQueue`'s RequestIDs, which serve/RunLive has in hand at restore time.

## Should-fix

**S1 — `-state-in` + `-metrics-out` panics on the first stepped tick.** `Kernel.Observe` enforces `first Observe at tick 1` (engine/metrics.go:417–418); serve wires the observer unconditionally (engine/cmd/serve/main.go:403–416, 470) and `validateStateFlags` (main.go:1279) doesn't refuse the combination. A warm-started measurement run dies with a panic at `startTick+1`. Loud and immediate, so no bad data — but this is precisely the "knowable before the run starts" class `validateStateFlags` exists for; refuse it there with a message.

**S2 — `leaderAtFor` spends the held turn on the wrong condition.** engine/engine.go:451–455 zeroes `probe.HeldTurn` only when `len(cur.Successors) > 1`. `boundaries()` consumes it on **every** crossing (engine.go:749), and both existing probes zero it unconditionally after the first hop (`gateTarget` rightofway.go:167, `exitBlocked` rightofway.go:271–272). If the first hop crosses a single-successor lane (e.g., an internal stub) and a diverge follows within sight, the walk steers by a held turn the real vehicle would already have spent — the lookahead watches a branch the vehicle won't take, which is the exact defect class ADR-0032 fixes. `TestLeaderLookaheadHonoursHeldTurn` only covers the diverge-at-first-hop case. Move the zeroing out of the `len > 1` branch.

**S3 — `engine/vehicle.go:84–88` comment is false: it says `stuckTicks` is "NOT keyframed."** Keyframe v5 carries it (engine/keyframe.go:150–152, 271–274), ADR-0034 documents that exact correction as review-caught, and `TestStuckTimerSurvivesAKeyframe` pins it. A stale claim on state that decides whether a vehicle exists is the kind of comment the next replay investigation will trust.

## Nit

- **N1** — `strandStuck` threshold: `uint64(300/0.1)` truncates to 2999 ticks (299.9 s), not the documented 300 s (engine/gridlock.go:1806). Deterministic everywhere, just off-by-one against the docs.
- **N2** — engine/warmstart.go:27 says lane-id keyframes are "format v5"; v5 is now the stuck timer (ADR-0034). ADR-0029 itself says v4 in Decision 1 and v5 in the Phase-1 note — three inconsistent numberings for the future lane-id format.
- **N3** — `validateStateFlags`' `-state-at == inTick` refusal says "the dump would never fire" (engine/cmd/serve/main.go:1304), but RunLive explicitly fires a pre-loop dump at the starting tick (run.go, "has no Step to hang off"). Refusal fine; rationale wrong.
- **N4** — `LoadState` skips the byte-length cross-check when the sidecar says `StateBytes: 0` (engine/warmstart.go:3784) — a hand-edited sidecar dodges half the pairing guard.

## Question

**Q1** — "A red light is never a trigger" (ADR-0034, gridlock.go comment) is emergent, not enforced: `jammedAtJunction` never reads the signal. A head unserved across ≥3 green phases strands the instant `boxBlocked` happens to read true — including from cross traffic momentarily in the box, not just spillback. Probably intended (such a head is genuinely unserved), but `TestEscapeIgnoresOrdinarySignalQueue` has no cross traffic during red, so this case is unpinned.

Keyframe version selection writes/reads consistently across the v3/v4/v5 combinations. No NATS subject or payload change; metrics JSON additions are additive and ADR'd (ADR-0034 amending ADR-0014); keyframe v5 is ADR'd with v2–v4 kept readable.
