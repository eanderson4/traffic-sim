## Review — staged diff (TSSG chunking, chunked GeoJSON, spawn identity, themes)

Engine kernel is untouched; the sigframe refactor is byte-pinned by golden tests; new subject `ts.{run}.state.sig.req`, the `sig_chunk` header, and the 4 MiB `MaxPayload` are all covered by ADR-0016 (asyncapi.yaml already carries the channel from the earlier commit), and the HTTP GeoJSON manifest by ADR-0018. No determinism risks found (no map iteration in sampled paths, `runNonce`'s wall clock is demosrv infra, `withSigTick` copies before patching). No blockers.

**Should-fix**

1. `engine/cmd/demosrv/supervisor.go:152-153` — `start` now holds `s.mu` through `waitIdentity`, i.e. up to `identityTimeout` = 660 s (supervisor.go:46). `status()` (:238) and `stop()` (:212) take the same mutex, so during a la-lean world build (~400 s) every `/api/status` poll (the menu polls at 3 s) and `/api/stop` blocks until start returns — the menu badge freezes and a bad start (foreign broker, no child death) cannot be aborted for 11 minutes. This was tolerable at the old 10 s bound; at 660 s it isn't. Snapshot the status fields outside the start-critical section (or make readiness observable without the start mutex).

2. `engine/cmd/demosrv/main.go:58` vs `main.go:158` — the two ws-advertisement paths disagree. `handleStart`/`handleReplayStart` use `advertisedWsURL(r)` (request-Host substitution for loopback/wildcard listens), but the menu's running-card deep link uses `reg.WS = wsClientURL()`, which is the verbatim listen address (supervisor.go:75). With `-ws 0.0.0.0:8443` the deep link carries `ws://0.0.0.0:8443` — not dialable in a browser — while the start response for the same run is correct. Route `/api/demos`' ws through the same request-aware helper (serve it from the handler, not a static registry field).

3. `engine/cmd/demosrv/main.go:415` — `Cache-Control: no-store` is set for every non-part `/net/` response, not just manifests. A big-but-under-threshold net (sf-lean's 188 MB single document) loses `ServeFile`'s Last-Modified/304 revalidation and refetches ~188 MB on every page load — a regression at exactly the scale this change targets. Scope no-store to the manifest case (have `netCache.path` report which shape it returned, or stat the size).

**Nit**

4. `engine/cmd/demosrv/supervisor.go:318` + `engine/natsio/probe.go:31` — `waitIdentity` opens a fresh WebSocket NATS connection + JetStream context every second for up to 660 probes. Works, but one held connection (or a backoff past the first minute) would be quieter in the child's logs and cheaper.

5. `viz/demos.html` inline script — the navy/paper palettes are duplicated by hand from `theme.ts` (the `:root` block makes a third copy). `theme.test.ts` pins only `theme.ts`, so the menu's copies can drift silently. Acceptable for chrome, but worth a generated constant or at least a pointer comment in theme.ts back to demos.html.

6. `viz/src/main.ts` (`handleSigMessage`) — when round N lost a chunk, round N+1's chunk 1 reports `gap: true` and fires `requestSig()` even though round N+1 is in flight and will normally complete ~instantly; the pull is redundant in that path. Bounded by `sigReqInFlight`/the 3-retry budget, so it's only a minor extra full-set transfer under loss.

7. `engine/cmd/demosrv/geojson.go` `part()` — loads and hashes the scenario, then `c.path()` immediately re-loads it. Consistent with the stated no-memoization discipline; noting only because it's on the per-part request path (N parts × 2 loads).

**Question**

8. `engine/natsio/bus.go` `PublishSignals` — la-lean's chunked table is ~10 × 768 KiB per 20-tick rebroadcast (~3.7 MB/s per subscriber at 10 tps) *in addition to* the new pull path. ADR-0016 explicitly keeps the rebroadcast, so this is per-decision — but was dropping (or slowing) the broadcast cadence once `sig.req` exists considered for city-scale runs? A one-line ADR note on why the cadence stays 20 ticks at any table size would close it.
