## Findings

**Should-fix**

1. `engine/natsio/tsib.go:93` — `DecodeTSIB` never validates the reserved `flags u16` (buf[6:8]) or `reserved u32` (buf[20:24]). The ADR pins them as "reserved, 0" and the demux design's stated principle is "fails loudly instead of misparsing," but a future producer setting a v1 flag bit would be silently accepted with the bit ignored by every engine shipping this decoder — which permanently forecloses using `flags` for v1-compatible extensions (you'd be forced into a version bump anyway, so the field becomes dead weight). Rejecting nonzero reserved fields now is one comparison and one test case; loosening later is backward-compatible, tightening later is not. If lenient-on-reserved is the intended forward-compat stance, say so in the format comment and the M4 asyncapi note instead.

**Nit**

2. `engine/natsio/bus.go:295` — the hot-path comment ("a MIMEHeader lookup canonicalizes (allocates)") contradicts the comment ten lines below it ("nats.Header is case-sensitive, no canonicalization") and is wrong for nats.go ≥ v1.13: `Header.Get` is a case-sensitive direct map lookup, no canonicalization, no allocation. The `len(msg.Header) == 0` gate is harmless but its stated rationale is false; the existence-vs-Get distinction (absent vs present-empty) is the real reason for the direct index, and that comment is correct.

3. `engine/natsio/tsib.go:70` — `EncodeTSIB` silently skips `RouteSet` intents. If the M2 driver ever fails to divert a route intent to standalone v2, the vehicle silently gets no intent that tick and hold-last masks it — no counter, no error. Acceptable for the M1 codec since diversion is explicitly M2's test surface (per the ADR), but consider having `EncodeTSIB` return the skipped count so the driver can assert it matches its diversion list.

**Question**

4. `engine/natsio/bus.go:95` (const block) — since nats.Header is case-sensitive and the demux is an exact-key lookup, a producer sending `Intent_Encoding: tsib` falls through to v2 parsing (structural rejection for multi-record; claim-filter backstop for single-record) rather than the unknown-encoding drop. Backstopped either way, but the M4 asyncapi note should state the key is exact-case `intent_encoding`, matched byte-for-byte.
