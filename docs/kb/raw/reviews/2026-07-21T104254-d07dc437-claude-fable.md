**No blockers.** The gate design is sound — tree-hash stamp captured before review, re-verified byte-exact at commit time, fail-closed on reviewer failure/drift. Findings:

**Should-fix**

1. **Gated-path mismatch between AGENTS.md and the hook.** `hooks/pre-commit:19-21` gates all of `viz/` minus `dist|node_modules|public` (so `viz/package.json`, `viz/index.html`, lockfiles are gated), while `AGENTS.md:41-42` — written in this same diff — enumerates only `viz/src`, `viz/test`, `viz/scripts`. One of them is wrong; per rule 2 the doc must match the mechanism. (ADR-0013 says "viz/ minus generated content", agreeing with the hook — fix AGENTS.md.)

2. **Completion marker check is a substring grep, weakening exactly this class of commit.** `scripts/external-review.sh:91` uses `grep -q "REVIEW-COMPLETE"`, but the brief (and this very diff, which embeds the marker twice) will be quoted in reviewer output. A reviewer that truncates or dies mid-review after quoting the diff/brief false-passes. The brief promises "a line containing exactly" — enforce it: `grep -qx 'REVIEW-COMPLETE'`, or require it as the last line. Cheap, and ADR-0013 §4's fail-closed claim depends on it.

3. **Patch generation honors diff config.** `scripts/external-review.sh:47-48`: `git diff --cached` applies external diff drivers and textconv if the user configures them, so the archived "reviewed patch" (which ADR-0013 calls the authority for what was reviewed) may not be the real content. Add `--no-ext-diff` (and consider `--binary`) — the drift check at line 105 is internally consistent either way, but the archived artifact isn't. The stamp itself is immune, as the comment says; the *archive* isn't.

**Nit**

4. `scripts/external-review.sh:38-39` — argument parsing silently ignores anything that isn't exactly `--gemini`. A typo (`--Gemini`) runs a two-reviewer round and stamps it, and the operator believes they ran a milestone round. Reject unknown args.

5. `scripts/external-review.sh:44-45,102` — `keep=1` is set on the success path too, so every successful run leaves a `/tmp/external-review-*` dir and exits printing "artifacts kept … for debugging". After a successful archive+stamp, reset `keep=0` (the artifacts are already in `docs/kb/raw/reviews/`).

6. `hooks/pre-commit:43-45` — the message covers `git commit -- <paths>` and `-p` but not `git commit -a`, which also builds a temporary index and will fail the gate the same way. Add it to the message to save the first person who hits it.

7. Paths containing newlines can confuse the line-oriented `grep` classification in `hooks/pre-commit:19-21` (a hostile name could straddle the gated/ungated split). Practically irrelevant in this repo; `--name-only -z` would close it.

**Question**

8. Conflicted merges: `git commit` after resolving a merge runs pre-commit, and there is no meaningful "staged diff of the merge" to review — the gate will block every conflicted merge of already-reviewed work, forcing the skip hatch. Intended, or worth an explicit carve-out (e.g., pass when `MERGE_HEAD` exists) documented in ADR-0013?

9. The stamp is trivially forgeable (`git write-tree > .git/external-review-stamp`). ADR-0013 §3 frames the gate as process-proof for honest actors, and `EXTERNAL_REVIEW_SKIP=1` already exists as the honest bypass — so this seems accepted, but the ADR could say so explicitly.

No determinism or NATS-contract exposure: the change is tooling/docs only; wall-clock use (`external-review.sh:42`) is confined to archive filenames. ADR-0013 exists for the decision itself, satisfying AGENTS.md rule 3. Self-gating of `hooks/` and `scripts/` (§5) is correctly reflected in the hook's path set.
