## Findings

**Blockers** — none.

**Should-fix**

1. `engine/cmd/demosrv/geojson.go:239` — a part request that passes the schema/hash pin but misses the file (`Stat` fails) returns a plain error → 500, not `errStalePart` → 404. The reachable case: hash validated at `geojson.go:224`, scenario edited, then `c.path` inside `part()` regenerates a *new* generation and the old part is gone. The client (`viz/src/netload.ts` `fetchNetworkOnce`) treats non-404 as fatal, so the exact mid-fetch-edit scenario ADR-0018's hash pinning exists for wedges the page load instead of triggering the promised manifest refetch. Classing the current-schema stat-miss as `errStalePart` makes the failure mode self-healing.

2. `engine/cmd/demosrv/supervisor.go:231` — `stop()` stores `stopRequested` before acquiring `s.mu`; a *fresh* `start()` already queued on the mutex can win the lock first, read the flag in `waitPort`/`waitIdentity`, and 502 spuriously ("start aborted") while the stop then no-ops. Small window, self-heals on retry, but the abort flag cancels a start it was never aimed at. A generation counter or checking the flag only for the run active when stop was called would close it.

**Nits**

3. `engine/cmd/demosrv/geojson.go:224` — `part()` hashes the network file, then `c.path` re-reads and re-hashes it. On la-lean that's two full multi-hundred-MB read+SHA256 passes per part × 4 parts per load. Pass the hash through (or a path variant that skips revalidation).
4. `engine/cmd/demosrv/supervisor.go:77` — `wsClientURL()` for a wildcard listen advertises `ws://0.0.0.0:8443` (registry default at `main.go:59`, and the `advertisedWsURL` fallback when `r.Host` is empty). Non-dialable in some browsers; rarely hit since `advertisedWsURL` substitutes the request host.
5. `viz/demos.html` inline script — the navy/paper palettes are hand-copied from `theme.ts`; no test pins them, so they can drift (the comment acknowledges it).
6. `engine/natsio/bus.go` `onSignalRequest` — nothing bounds resync requests: any observer can solicit the full multi-MB chunk set + `Flush` per message. Fine local-first; worth a line in ADR-0016 §7 for when observer auth actually lands.

**Questions**

7. `engine/natsio/driver/driver.go` has 73 *unstaged* insertions while the staged `serveArgs` comment (`engine/cmd/demosrv/main.go`) and ADR-0018 lean on the driver's exit-routing-pass timing for the 600 s attach story. Staged code compiles without it (no API change consumed), but is shipping demosrv's 600 s timeout without the driver change intentional, or is half a fix being left behind?
8. `viz/src/main.ts` `installSigTable` — a pull reply (tick = last published) can overwrite a table a newer broadcast round just installed. Harmless today because nothing derives phase state from `sigTable.tick` and tables are static (ADR-0016's documented `sig_gen` limitation); just confirming that's the intended reliance.

**Contract check** — clean: new subject `ts.{run}.state.sig.req`, `sig_chunk` header, observer-publish amendment, and the 4 MiB `MaxPayload` are all covered by the ratified ADR-0016 and AsyncAPI 2.3.0 with migration notes; the tightened `kf_chunk`/`sig_chunk` regex matches what producers already emit (1-based), so durable recordings are unaffected. ADR-0016's text was correctly updated to match the implemented shape (20-tick rebroadcast kept, `sig_gen` deferred with the interleaved-round limitation stated).
