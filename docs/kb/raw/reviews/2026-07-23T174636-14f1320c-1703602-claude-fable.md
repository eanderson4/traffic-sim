# External review — replay player (VCR driver)

**Blockers: none.** The concurrency design (engine confined to the Run goroutine, control channel serviced before the step decision, ack built at completion), the determinism discipline (wall clock only in the pacing wrapper per ADR-0005 §4; per-tick slices in stream order, no map iteration in the sim path), and the contract handling (`-replay` reservation enforced at `RunLive`, `NewRecorder`, and `NewPlayer`; ADR-0006 addendum + asyncapi note present; log streams capture only `ts.{run}.log.>`, so replay-plane publishes can't leak into any record stream) all check out. The resume-vs-end-hold race is correctly closed by the double check in `player.go` handleCtrl (`done || e.Tick >= endTick` on the loop goroutine — a resume arriving in the one-iteration window after stepping onto endTick but before the hold CAS is still refused).

## Should-fix

1. **`engine/natsio/bus.go:309` — `NewBus` (the intent-subscribing constructor) still accepts `-replay` run ids.** The reservation is enforced at `RunLive`/`NewRecorder`, and today `RunLive` is `NewBus`'s only caller, so nothing is broken — but the ADR text says the suffix "is refused at every live/record entry point," and a future direct `NewBus` caller would attach a live contract plane (intent subscription) to a replay id. One `validRunID` call in `NewBus` (not `NewPublishBus`) closes it and keeps the code matching the ADR's claim. If you defer instead, soften the ADR wording.

## Nits

2. **`engine/natsio/player.go:515` vs `player.go:899`** — the tick-floor representable-range check (`Dt / speed * float64(time.Second)`, `IsInf || v < 1 || v >= MaxInt64`) is duplicated verbatim in `NewPlayer` and the `/speed` handler. Extract next to `checkSpeed` so the two can't drift.
3. **`engine/natsio/player.go:935` — `ctrl()` (and `Done()`) block forever if `Run` is never started**; `runDone` only closes when Run exits. Both real callers start Run immediately, so this only bites future test/embedding code. A comment on `ctrl` would be enough.
4. **`engine/cmd/replay/main.go:236` — `checkLoopback` trusts the literal `"localhost"` without resolving it.** A hosts-file remap of localhost to a routable address slips through. Loopback-IP-only (drop the localhost special case) would be strictly tighter; cosmetic on a dev box.
5. **Timing-bound test assertions** — `player_test.go` asserts `/pause` completes < 1 s behind a 10 s floor (TestPlayerSlowSpeedControlsResponsive) and the done hold engages within 200 ms of the final tick (TestPlayerEndHoldEngagesPromptly). Margins are generous (50 ms chunks, 5 ms poll) but these are the kind of wall-clock bounds that flake on saturated CI. Acceptable now; loosen if they ever flake rather than adding retries.

## Questions

6. **`engine/cmd/replay/main.go:110` — should `-ws` get the same loopback refusal as `-http`?** The WebSocket listener is a full unauthenticated NATS client port (`NoTLS`), and on the replay broker it fronts the *durable record store*: a non-loopback WS client can publish into `ts.{run}.log.>`, which the record streams capture — the recorder's OCC header only guards the recorder's own writes, so foreign appends land silently (your own zero-cadence check anticipates exactly this "dirty store" shape, and the CRC audit would flag it later rather than prevent it). This mirrors the existing live-serve WS posture and ADR-0004 is local-first, so deferring is defensible — but the archival store makes replay's WS strictly higher-stakes than serve's.
7. **Post-divergence state is path-dependent by design** — after a CRC divergence, forward playback continues on the diverged trajectory while a seek to the same tick restores the recorded truth from a keyframe, so tick N can render two different worlds depending on how you got there. The ADR's loud-and-continue policy covers this and counters/logs make it visible; flagging only so it's a known property, not a surprise during the demo.

Nice touches worth keeping: the truncated-vs-done horizon rule (ADR addendum "Playback horizon") is exactly right about not inventing an under-controlled tail, and the seek-doesn't-move-counters semantics is well specified and well tested.
