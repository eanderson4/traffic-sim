**Blockers:** none.

**Should-fix**

1. `engine/natsio/driver/driver.go:193` — the hello request timeout is still capped at `min(2*time.Second, remaining)`, but the 2 s cap was designed for the old retry-all loop. Now that only `nats.ErrNoResponders` retries and a timeout is fatal, 2 s becomes the hard ceiling on the engine's reply latency once it *has* subscribed — `MetaWait` (10 s) no longer buys a slow-but-live engine anything, which is exactly the big-network startup case the retry exists for. Pass `remaining` as the request timeout; it's still a single request, so the ghost-controller rationale is untouched and MetaWait still bounds the total wait.

**Questions**

2. Ghost-controller residue on a *single* timed-out hello still exists: the engine registered the controller, the reply was lost, the driver errors out, and a supervisor restart sends a fresh hello — the orphan holds claim capacity until engine-side liveness reaping (the heartbeat/silence budget) detaches it. The fix correctly stops *multiplying* ghosts; confirm the silence budget actually reaps a controller that never sends anything post-hello, otherwise capacity leaks once per failed start.

**Nits**

3. `driver.go:419` (routeStep) — the `if d.wantLane == nil { d.wantLane = map[uint64]int{} }` guard exists only because `TestRouteBudgetPerTick` constructs `Driver` literally without the field (`TestRouteBudgetFrozenLane` does set it). Initialize it in the test and drop the production guard — it can silently mask a future constructor regression.
4. `driver_test.go` `TestRouteBudgetFrozenLane` — the test never asserts that `pickExit(..., moved)` differs from the frozen-lane draw; if the two lanes happen to yield the same exit, the test passes even if the code used the current lane. Add an inequality guard (or `t.Skip` when they coincide).
