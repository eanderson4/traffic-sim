## Findings

**Should-fix**

1. **`CompletedObsTick` doc overclaims completion** — `engine/natsio/driver/driver.go:283-288, 391-394`. The watermark is stamped unconditionally at the end of `onObs`, but (a) `publishIntent` (driver.go:417-421) and `flushBatch` (driver.go:428-437) swallow `Publish` errors, so on a failed publish the tick is stamped "FULLY PUBLISHED" with intents missing, and (b) `nc.Publish` only buffers to the client library — nothing is flushed, so "gone out" means "handed to nats.go", not on the wire. The test is safe because it independently proves size (`SentIntents − sentMark ≥ vehicles`) and consumption (Phase B quiet window), but the comment invites future callers ("Use it, never LastObsTick, wherever completion semantics are meant") to treat it as a real completion barrier. Tighten the doc to "onObs finished handing the tick's intents to the NATS client; publish errors do not block the stamp" — or skip the stamp when any publish errored.

**Nit**

2. **`LastObsTick` is now caller-less** — `engine/natsio/driver/driver.go:278-281`. The test migrated fully to `CompletedObsTick`; `LastObsTick` survives only as an exported begin-watermark whose own doc warns against using it. If it has no observability consumer planned, deleting it removes the footgun the new doc apologizes for. Fine to defer.

3. **Sentinel exactness claim leans on fleet stability** — `engine/natsio/driver_test.go:1244-1250`. "provably EXACTLY `vehicles` intents" holds because the ring net never despawns and the fleet was fully claimed before quiescence; the code correctly checks `≥ vehicles` rather than `==`, so a violated assumption fails loud (timeout) rather than silently. No change needed — noting the dependency.

**Verified-clean** (things I checked and found sound):

- **Sentinel ordering is airtight as claimed**: `sentMark` is read at driver_test.go:1258 after `quietWindow()` proved `SentIntents` unmoved for 50 ms with `CompletedObsTick` covering all published obs, and the driver publishes nothing without an obs — so the delta at driver_test.go:1269 can only be the sentinel's response. `lastObs` is captured after `AfterStep` (which publishes obs at `e.Tick`), and the wait loop never calls `AfterStep`, so no other obs can satisfy the watermark.

Atomics give the reader proper happens-before.
