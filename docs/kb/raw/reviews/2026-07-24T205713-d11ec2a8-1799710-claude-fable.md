**Should-fix**

1. `engine/cmd/demosrv/supervisor.go:169` (start) + `:246` (status) — `start` now holds `s.mu` through `waitIdentity`, i.e. up to **660 s** (routine 100–400 s on big nets). `status()` and `stop()` take the same mutex, so during any big-net start every `/api/status` poll (menu polls at 3 s — they pile up) hangs, and a wedged start against a foreign broker **cannot be cancelled** for 11 minutes. The pre-change worst case was 10 s, which made the shared mutex fine; the new timeout changes the calculus. Snapshot status fields outside the lock, or make the identity wait interruptible by stop.

2. `engine/cmd/demosrv/geojson.go:105` (`netKey`) — every `/net/{id}.geojson` and every part request re-reads and re-hashes the **entire** network file (hundreds of MB for la-lean). A chunked load is manifest + N parts sequential → N+1 full reads/hashes plus ~GB transient allocs, on the exact path this feature targets. Dev server, so deferrable — but a (path, mtime, size)→hash memo is cheap and removes it.

**Nits**

3. `engine/cmd/demosrv/supervisor.go:36` — comment says `identityTimeout` "Matches the -attach-timeout demosrv passes serve"; it's 660 s vs 600 s. ADR-0018 states the 660 intentionally; fix the word "Matches".
4. `engine/cmd/demosrv/geojson.go:77` (`isManifest`) — sniffing the first 4 KiB for the literal `"parts"` can false-positive on a single-file net whose frame/projection text ever contains `"parts"`. Consequence is only a spurious `no-store`; fine today.
5. `engine/geojson.go:66` — `WriteGeoJSON` now builds the full feature slice **before** `encodeGeoJSON`'s version check; a version≠1 file does all the (potentially GB-scale) work before erroring. Check version first.
6. `viz/src/main.ts` (`handleSigMessage`) — a sig decode error calls `hud.setConnection(false, …)` though the socket is healthy. Pre-existing pattern, just extended; noting it.

**Questions**

7. `viz/src/tssg.ts` (`SignalTableAccumulator.feed`) — a cross-generation splice is possible: receive A:1/3, A:2/3, drop B:1/3 and B:2/3, receive B:3/3 → `i==expected && n==total` passes and A's chunks 1–2 merge with B's chunk 3. Today this is harmless because the chunk set is immutable per run (encoded once at `NewPublishBus`; only the tick byte differs), so the spliced table is content-identical. If signal programs ever become dynamic mid-run, this silently installs a mixed table — worth a comment pinning the immutability assumption the correctness rests on.
8. `engine/natsio/bus.go` (`onSignalRequest`) — each request re-sends the full set (la-lean ~7.3 MB) with no rate limit; N reloading tabs multiply it. Within the local-first threat model this is presumably accepted — flagging for the record.
