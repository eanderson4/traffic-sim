**Should-fix**

1. `engine/cmd/demosrv/supervisor.go:152-153` — `start` holds `s.mu` through `waitReady` + `waitIdentity` (60 s + up to 660 s). During a legitimate la-lean spawn (~400 s world build), `status()` (:271) and `stop()` (:212) block on the same mutex: the menu's 3 s `/api/status` polls hang and pile up, and a wedged spawn cannot be aborted until the identity timeout expires. Previously the lock was held ≤10 s; this is a ~66× widening of that window. Consider running the identity wait outside the lock (state already guarded by `activeRun.done`) or letting `stop` cancel an in-flight start.

2. `engine/cmd/demosrv/main.go:422` — `Cache-Control: no-store` is applied to every non-part `/net/` response, not just manifests. A big-but-under-threshold net (sf-lean's 188 MB single document) loses `ServeFile`'s Last-Modified/304 path and refetches in full on every viz load — a regression at exactly the scale this change targets. Scope no-store to the manifest case. (Flagged in a prior round — if triaged as deferred, record it.)

3. `engine/cmd/demosrv/geojson.go:197` (`part`) + `:100` (`path`) — every part request reads and sha256s the entire network file twice: `part` calls `netKey` to validate the pin, then `c.path` calls `netKey` again before its manifest stat. A warm-cache la-lean load (manifest + 4 parts) does ~9 full read+hash passes over a multi-hundred-MB file, serialized with the client's sequential fetches. Memoize the hash by `(path, size, mtime)` or thread `part`'s hash into `path`.
