## Should-fix

1. **A slow seek permanently hides the replay panel.** `supervisor.withActiveReplay` (engine/cmd/demosrv/supervisor.go:~186) holds `s.mu` for the whole seek forward — up to `seekTimeout` = 10 s (engine/cmd/demosrv/replay.go:29). Meanwhile the panel polls `/api/replay/status` every 1 s (viz/src/replaypanel.ts:308), each poll aborting client-side at 3 s (replaypanel.ts:182) because the server-side handler blocks on the same mutex (`proxyCtl` → `replayActive` → `activeKind`, supervisor.go:~207). `FailGate(3)` (replaypanel.ts:273) hides the panel and clears the poll timer after 3 consecutive failures — reached at ~5.5 s into any seek. So exactly the big-record seeks the 10 s timeout exists for kill the panel until page reload. Suppress the fail streak while `ctl.seekBusy`, or make `activeKind` not contend with the seek's lock hold.

2. **Empty 300px HUD box on every live demo for ~4 s.** `#replay` (viz/index.html:101, `min-width: 300px` + the `.hud` background/border) is visible-but-empty while `probeWithRetry` runs its 5×1 s attempts (replaypanel.ts:296); the root is hidden only after the last 404. Modelpanel/switcher get away with show-then-hide because they fail in one fast round-trip; the retry loop makes this a visible artifact on the common (non-replay) path. Start the root `display:none` and show on first success.

## Nits

3. **`"tags" in d` doesn't guard `"tags": null`.** `Demo.Tags` is `json:"tags"` without omitempty (engine/cmd/demosrv/registry.go:33), so a tag-less demo (the example's second entry is one) serializes `"tags": null`, the `in` check passes, and `for…of null` throws, breaking the whole menu render (viz/src/demos.ts:74). Pre-existing for the old `d.tags` code, but the new guard was written to handle exactly this shape — `d.tags ?? []` finishes the job.

4. **Demo run ids are write-only in `seenRuns`** (registry.go, demos loop): two demos may share a run while recordings must be unique registry-wide. Harmless under single-active-run and pre-existing, but the asymmetry is now one line away from closing.

5. **`forwardCtl` 1 MiB cap** (replay.go:238): a body of exactly 1 MiB logs a false truncation warning, and a genuinely truncated body is still forwarded as a 200 with malformed JSON. Acknowledged in the comment; fine at this stage.

6. **SeekGate is armed on live demos too** (viz/src/main.ts:~460): a delivery stall > `maxJump` ticks (e.g. long-backgrounded tab) false-trips a reset — self-healing within a frame, so cosmetic only.

## Questions

7. **`filepath.Abs(spec.Net.Path)` bakes a machine-absolute path into the durable RunMeta** (engine/cmd/serve/main.go:152). It fixes the cwd bug (replay re-sims via `BuildNet` reading that path), but the recording now breaks if the store moves to another machine or the checkout relocates, and the registry/record payload's value semantics changed (relative → absolute) — ADR-0006 treats those payloads as contract. Commit ab8b039's KB entry logs run-meta-lifecycle deferrals; confirm this portability tradeoff is captured there (or add a migration note). The swallowed `Abs` error (keep-relative fallback) is fine.

Determinism: clean — no map iteration in sampled paths, no wall clock in sim logic, `scenario.Hash` is content-based (relative paths) so the `Net.Path` mutation doesn't shift identity, and the `-replay` suffix reservation in the registry matches `natsio`'s (`server.go:187`). The reset-before-POST seek ordering and its test (replaypanel.test.ts "resets BEFORE the POST") are well done.
