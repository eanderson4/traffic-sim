## Findings

**Should-fix**

1. `engine/cmd/serve/main.go:56,270` — **Pace is an unrecorded run condition.** Driver-replica and demand-director intents arrive on wall time, so their reaction latency *measured in ticks* scales with `-pace`: the same (scenario-hash, seed) at 1× vs 8× produces systematically different traffic (and different `-metrics-out` numbers). ADR-0005's consequences designate (scenario, seed) as the comparison run key and ADR-0012 §6 builds seed sweeps on it, but neither the recording nor the KV registry meta captures the pace, making it an invisible confounder across sweep runs. Minimal fix: stamp the pace into the run's registry meta (or the recording's run entry), or at least a KB note that cross-pace comparisons are invalid. Replay determinism itself is unaffected (replay re-simulates from the recorded log).

**Nit**

2. `viz/src/snapshots.ts:124` — At high pace, consecutive received snapshots span many ticks, and `Math.hypot` measures the straight-line chord, not path length — speed is increasingly underestimated on curved geometry as pace grows. The test's "1× and 8× read the same" claim (viz/test/snapshots.test.ts:494) holds only for straight-line motion. It's already a "labelled estimate"; consider a comment.

3. `engine/cmd/serve/main.go:203–204,240–243` — `os.Exit` after `jetStreamStoreDir` skips the deferred `cleanupStore`, leaking the temp dir on later startup errors (broker not ready, fresh-recording refusal). Pre-existing pattern with the old `defer os.RemoveAll`; unchanged in substance.

**Question**

4. `engine/cmd/serve/main.go:337` / `viz/src/config.ts:383` — `?dt=` hands contract-adjacent data (the scenario's timestep, already authoritative in the run registry meta) through a hand-copied URL. A stale/omitted `dt` on a 0.05 s scenario silently doubles every displayed speed and flips the congestion overlay. Fine for the demo, and "too early" is a valid answer — but when the viz grows registry access, dt should come from there, not the URL.

5. `engine/cmd/serve/main.go:14–16` — With a durable `-store`, the SIGINT "abandons the KV run entry" behavior now *persists* the abandoned entry across serve exits. Anything that later reads run status from that store sees a forever-running run. Acceptable for demo mode? (One line in the doc header would settle it.)

No blockers. Determinism discipline is respected: no wall clock enters sim state, `PaceFloor` only sleeps, viz speed now correctly divides by sim time; no NATS subject or payload changed (`?dt=` is viz-local URL config, not contract). The `-pace 0`/driver refusal and the fresh-recording fail-closed check are both correct and well-reasoned; tests cover the mapping edges (NaN/Inf/truncation-to-zero) and the pace-invariance of derived speed.
