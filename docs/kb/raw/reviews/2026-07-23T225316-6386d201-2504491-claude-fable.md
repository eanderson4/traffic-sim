## Review — staged diff: 45° approach cone + stop bars (viz/src/signals.ts, viz/test/signals.test.ts)

**No blockers.** Tests pass (104/104 against the staged sources). No determinism risks: viz-only code, no map iteration in output-ordering paths (`shapesByLane` is only `.get`), clustering order is the wire's deterministic link order, `stopBar`'s min/max is order-independent, no wall clock/RNG. No contract impact: `SignalHead` is a viz-internal interface, no NATS subject/payload touched — no ADR needed.

**Question — turn-lane chords vs the strict 45° cone** (`viz/src/signals.ts:111`). The comment (`signals.ts:103`) asserts lanes of one true approach stay within ~20° at the stop line. That holds when internal-lane shapes are curved with a near-tangent first segment, but a sparse 2-point internal lane for a 90° turn has a *chord* bearing ~45° off its through lanes — and `> Math.SQRT1_2` is strict, so exactly-45° splits. If any scenario's internal lanes are 2-point chords, turn movements sharing a column with the through would each mint an extra head. The header says the quoted counts (1100/824/1625) are "by column alone" — were the head counts re-measured on Manhattan/Wilshire/stress-DTLA with the 45° cone? If the "~one head per extra arm" delta was measured, this is answered; if estimated, worth one measurement before committing to it.

**Nit — cone is per-join, not per-cluster** (`viz/src/signals.ts:98-111`). The gate tests against the *running* mean, so greedy drift lets a cluster's total bearing spread exceed 45° (44° join rotates the mean ~22°; the next join can sit ~66° from the first lane). Deterministic (fixed wire order) and probably desirable for gently fanning approaches, but the "within ~45°" comments describe the join condition, not a cluster invariant.

**Nit — `bar` is produced but unconsumed in this commit.** The renderer changes in `viz/src/signalhead.ts` are unstaged, so this commit ships a computed-but-dead field. Fine as commit slicing (nothing at HEAD constructs `SignalHead` literals, so the required field can't break the typecheck), just confirm the renderer commit follows.

**Nit — negative zero** (`viz/src/signals.ts:123`). `nx = -uy` yields `-0` for an axis-aligned mean bearing; downstream arithmetic normalizes it and the test's non-strict `deepEqual` wouldn't catch `-0` anyway. Harmless today; would only bite if a future consumer serializes bar coords into something `-0`-sensitive (e.g. `Object.is`-keyed caching).

Test coverage is good: both sides of the cone boundary (60° splits, 10° merges), the degenerate no-bearing case, and an exact bar-geometry assertion.
