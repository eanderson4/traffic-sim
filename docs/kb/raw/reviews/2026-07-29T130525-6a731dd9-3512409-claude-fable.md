## Review — ADR-0029/0031/0032/0033/0034 batch (warm start, permissive green, routed lookahead, mutual yield, gridlock escape)

Verified against the staged patch plus repo context: `Step()` ordering, CRC composition (`engine/engine.go:879` — `stuckTicks` correctly excluded, removal itself CRC-visible), keyframe writer/reader version gating (both keyed on the same `version` var; empty-queue-v5 case handled and pinned), metrics `gone` loop (`k.last = cur` at `engine/metrics.go:681` — no stranded leak into `activeAtHorizon`; per-tick `k.timeLoss` at `:558` supports the new denominator), `fastForward` tick conversion matches `onSnapshot` (`director.go:277` vs `:309`), `resetStuckBehind`/`LaneFingerprint` iterate slices not maps, observer contract is once-per-Step so per-tick `StrandedIDs` is safe, old registry specs unmarshal `StrandAfterS=0` so pre-change replays are untouched. Keyframe v5 as a record-plane payload change carries the required migration note (ADR-0034). No blockers found.

**Should-fix**

1. `engine/cmd/serve/main.go:938` — `probeWritable` only probes the parent directory. `-state-out` pointing at an existing *directory* passes the probe, then the dump's `os.Rename` fails at tick N and aborts the run — exactly the discover-it-an-hour-in failure the probe exists to prevent. A `Stat` on the target (refuse dir) closes it.
2. `engine/cmd/serve/main.go:841` (`validateStateFlags`) — the sidecar guards seed, network, and types, but not **Params**. Warm-starting a state saved from a run with `-safety-decel 4` (or any non-default param) and forgetting the flag splices two programs with at most a NOTE (`main.go:269`, and no note at all for flag-built runs, whose `ScenarioHash` is empty). By this commit's own standard — the seed splice is refused because "a printed note is not enough" — the params splice is the same trap with no guard. Recording `Params` (or a hash of it) in the sidecar and refusing on mismatch is symmetric with the seed rule.
3. `engine/warmstart.go` (`writeFileAtomic`) — fixed `path + ".tmp"` temp name: two runs dumping to the same path (a plausible batch-script mistake) race on the temp file and can cross-write; the sidecar digest converts that into a refusal at load, but a `CreateTemp`-based name would prevent the corruption instead of detecting it.

**Nit**

4. `engine/natsio/demand/director.go:279` — `skipped++` before the `!ok` check counts the exhausted (never-existed) draw as a skipped arrival, so the "skipped N arrivals" log overcounts by one per flow that exhausts during fast-forward; `TestFastForwardMatchesTheColdProgram` replicates the same counting so it can't catch it.
5. `engine/gridlock.go:84` — `uint64(StrandAfterS / Dt)` truncates (300/0.1 is not exact in binary), so the threshold can land one tick off the nominal count. Deterministic and cross-platform-stable (IEEE), so no replay risk — just an imprecise boundary.
6. `engine/metrics.go:615` stranded branch — the vehicle's final tick contributes no stopped-time/occupancy to the lane accumulators (≤1 tick per strand, stationary). Consistent with "no exit chain to account", worth a comment at most.

**Question**

7. `director.go:268` `fastForward` is production-unreachable in this commit (serve refuses `-state-in`+demand, `demand-director` refuses `-start-tick`>0) — kept, tested, and documented as phase-2 machinery, so confirming that's intended shelf-ware rather than an integration that was meant to be wired.
8. `engine/rightofway.go:451` — a red-held signalised foe now unblocks a *minor unsignalised* ego too (uncontrolled link at a partially signalised junction), not only permissive egos. ADR-0033's "unsignalised junctions untouched" is accurately scoped to `foe.Signal == nil`, and the new behaviour is arguably correct semantics — flagging only so the scope is understood.

The self-corrections already folded in (v5 empty-queue round-trip, stuck-timer keyframing, sidecar digest, type-table fingerprint, the armed-timer clarification) all check out against the code, and each carries a pinning test.
