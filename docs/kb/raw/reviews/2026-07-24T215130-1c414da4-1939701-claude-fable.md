### Should-fix

1. **`engine/cmd/demosrv/supervisor.go:157` (`start`) + `:255` (`status`)** — `start` now holds `s.mu` through `waitIdentity` (up to 660 s on la-lean), and `status()`/`withActiveReplay()` take the same mutex. During a big-city spawn every `/api/status` poll (menu polls each 3 s) and `/api/replay/*` call blocks until identity completes; pending fetches pile up behind the browser's per-host connection cap and freeze the menu page for minutes. Previously the lock was held ≤ ~10 s, so this is a new regression. `stop()`'s `stopRequested` abort works, but reads shouldn't ride the start mutex — snapshot the active run under a short lock or a separate one.

2. **`viz/src/main.ts` (`requestSig`, ~line 3990 of the patch)** — the 3-pull budget can burn out in under a second and is never re-armed except by reconnect or a pull *success*. A viz tab attached during world build (broker up, `Bus` not yet constructed) gets an immediate no-responders error from `requestMany` per attempt → 3 rapid recursive retries → budget dead. When the run then starts and a broadcast chunk drops (the la-lean busy-tab case this ADR exists for), `requestSig` refuses forever; convergence falls back to catching a fully unbroken n-chunk broadcast round. Cheap fix: re-arm `sigReqRetries` on any received broadcast sig message (proof a live publisher exists), or back off between retries instead of recursing immediately.

3. **`engine/cmd/demosrv/geojson_test.go:24`** — trailing comment is one column out of alignment with lines 22–23 (`gofmt` aligns consecutive end-of-line comments; this file will show in `gofmt -l`). Convention is gofmt-clean; I couldn't run gofmt in this sandbox, so please verify with `gofmt -l engine/`.

### Nits

4. `engine/cmd/demosrv/geojson.go:560-568` — `path`'s doc comment now dangles above `isManifest` (the new funcs were inserted between the comment and `func (c *netCache) path`); the comment block reads as isManifest's.
5. `engine/cmd/demosrv/geojson.go` (`part`) — each part request reads + sha256's the multi-hundred-MB network file **twice** (`part`→`netKey`, then `c.path`→`netKey` again). Dev server, sequential fetches — fine today, but it's 2×N full-file hashes per page load on la-lean.
6. `engine/cmd/demosrv/geojson.go` (`isManifest`) — substring sniff for `"parts"` in the first 4 KiB can false-positive on a single-file net whose head happens to contain that byte sequence; consequence is only a wrong `no-store` on a huge file, but matching `"parts":` or decoding the head would be tighter.
7. `engine/cmd/demosrv/main.go` (`advertisedWsURL`) — a bare IPv6 `Host` header without port (`[::1]`) yields `ws://[[::1]]:8443` (JoinHostPort re-brackets). Rare with a non-default HTTP port; strip brackets before joining if you care.
8. `viz/src/main.ts` — `cfg.theme in THEMES` walks the prototype chain (`?theme=constructor` labels the toggle "CONSTRUCTOR") while `getTheme` correctly uses `Object.hasOwn`; cosmetic only, but use the same check.
9. `viz/demos.html` + `viz/index.html` — the navy/paper palette literals are hand-duplicated from `theme.ts` in two places (inline script + `:root` defaults); theme.test.ts pins theme.ts only, so the HTML copies can drift silently. Acknowledged in comments — just flagging the untested duplication.
10. `engine/natsio/sigchunk_test.go:198,268` — tests mutate `bus.sigChunks` after `NewPublishBus` has the `sig.req` responder live; the write (test goroutine) and read (subscription dispatch goroutine) have no in-process happens-before edge across the loopback socket, so `-race` may flag `TestSignalTableRequestReply`. Building the chunks before constructing the bus (or a small test hook) avoids it.
11. Docs: ADR-0016 §8 says "4 MB" where the code and AsyncAPI say 4 MiB (`4 << 20`); trivial, but the ADR is the contract's rationale record.
