**Verdict: no blockers.** The shell logic is careful (fail-closed marker check, tree-hash binding, drift check, per-worktree gitdir). Findings below.

## should-fix

1. **`hooks/pre-commit` (only file in `hooks/`) — clean merges bypass the gate, contradicting ADR-0013 §4's "there is no merge waiver."** A conflicted merge resolved via `git commit` runs `pre-commit`, but a non-conflicting `git merge` that auto-commits runs the `pre-merge-commit` hook — which doesn't exist here — so an auto-merged commit touching gated paths lands with no gate at all (and the merged tree is a novel combination neither reviewer saw). Same for `git rebase`/`cherry-pick`, which skip `pre-commit` entirely. Fix: add a `pre-merge-commit` that execs `pre-commit`, or narrow the ADR §4 / hook-comment claim (diff.patch:159, hooks/pre-commit:11–12) to conflict resolutions only.

## nit

2. **hooks/pre-commit:243–244 and ADR §4 (diff.patch:157): "partial commits … *always* fail this gate" is an overclaim.** `git commit -a` (or `git commit -- <paths>` covering exactly the staged set) with no additional unstaged edits builds a temp index whose `write-tree` equals the stamped tree, so it *passes*. Harmless — identical content — but the documented behavior is wrong, and someone will eventually "prove" the docs wrong with it.

3. **scripts/external-review.sh:354 — the 200-byte floor rejects a legitimately clean, terse review.** The brief demands terseness; "No findings.\nREVIEW-COMPLETE" would be flagged as "did not complete." Fail-closed so not unsafe, but it structurally incentivizes reviewer padding. Consider dropping the floor or lowering it to ~50 bytes; the marker check already handles empty/truncated output.

4. **scripts/external-review.sh:287 — the hooksPath warning only fires when `core.hooksPath` is *unset*.** A clone with it set to anything other than `hooks` (or an absolute path elsewhere) gets no warning and no enforcement. Compare the value, not just existence.

5. **Unborn-HEAD edge:** both `git rev-parse HEAD` calls (hooks/pre-commit:227, scripts/external-review.sh:300) fail on a repo with no commits — the script aborts under `set -e` before reviewing, so a fresh repo's first gated commit can only use the skip hatch. Consistent with ADR §5's "bootstrap used skip once," but worth knowing it's structural, not one-time.

## question

6. **scripts/external-review.sh:382 — the stamp is never consumed.** After a successful commit it goes stale naturally (base HEAD moves), and the (base, tree) binding makes replay safe, so this is fine — but if you ever weaken the binding, remember the stamp lingers. No action needed now.

7. **`--allowedTools` for the Fable reviewer (scripts/external-review.sh:332) omits `ls`/`find`-style discovery**, so its repo-context exploration is Read/Grep/Glob only. Probably intentional; flagging in case reviews come back shallower than the Sol ones.
