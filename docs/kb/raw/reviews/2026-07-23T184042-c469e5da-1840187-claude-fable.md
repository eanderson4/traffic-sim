## Findings

**Blockers** — none found. Determinism discipline is clean (demosrv is orchestration-only; no map iteration in sampled paths, no wall clock in engine state, `scenario.Hash()` hashes rel-path + content so the `filepath.Abs` change doesn't shift run identity).

**Should-fix**

1. **`viz/src/demos-core.ts:1425` — `buildReplayURL` drops the dt hint, so the two navigation paths for the same recording disagree.** POST `/api/replay/{id}/start` returns `...&dt=0.05` (replay.go:622), but clicking an *already-running* recording card navigates via `buildReplayURL` with no `dt` → config.ts's 0.1 default → rendered speeds/pace off by 2× for a dt-0.05 recording. The comment acknowledges it, but the fix is cheap: have `LoadRegistry` (or `handleDemos`) resolve dt per recording into the `/api/demos` payload so the client deep link can carry it — demosrv already has `scenarioDT` for exactly this.

2. **`engine/cmd/serve/main.go:152` — absolutizing `spec.Net.Path` bakes a machine-specific path into the durable record.** `RunMeta.Spec` is embedded in full in the KV registry and the recording (registry.go:24-29), so a recording now replays only from the exact checkout path it was recorded on — moving the repo or sharing `data/recordings/` breaks the replay child's network load. Relative was worse (cwd-dependent), but recordings are precisely the "durable artifact binds the result" case your review workflow flags. Consider recording repo-root-relative and resolving at replay time, or explicitly log this in the KB run-meta-lifecycle deferral (ab8b039) so it's a decision, not an accident.

3. **`viz/src/replaypanel.ts:1874-1881` (`poll`) — one transient status failure hides the panel for the session.** `init` retries 5× because "a startup hiccup must not hide the panel for the session", but the steady-state poll hides permanently on a single null (one 3-s abort, one demosrv 502). The replay keeps running with no controls and no recovery path short of a reload. Mirror the init discipline: hide only after N consecutive poll failures.

**Nits**

4. `viz/src/replaypanel.ts:1923-1928` — no `pointercancel` handler; a cancelled touch/drag leaves `dragging = true`, so the slider stops tracking playback until the next pointer interaction.
5. `engine/cmd/demosrv/demos.example.json:7` — `_recordings_note` is a second unknown-field key, but the `_placeholder` text still says "remove this key" (singular). Someone will remove `_placeholder` only and get a strict-decode error naming `_recordings_note`.
6. `engine/cmd/demosrv/registry.go:106` — a recordings-only registry fails with "no demos". If that's intended (menu needs at least one live demo), the error should say so.
7. `viz/src/main.ts:1604` — `SeekGate` runs on live-demo streams too; a >240-tick delivery gap (backgrounded tab with server-side frame drops at 8× pace) false-positives as a seek. Consequence is a harmless buffer/congestion reset, so fine — just noting the gate isn't replay-scoped.

**Questions**

8. On a replay page, ModelPanel probes `/api/demo/{recording-id}/params` → 404 → panel hides. The IDM params are resolvable from the recording's `scenarioDir` — deliberate scope cut, or worth routing `handleParams` through both namespaces like `/net/{id}`?
9. `SeekGate` default `maxJump=240` is derived from dt 0.1, but decimation ("~10 Hz wall at any pace", replay `-speed`) makes ticks-per-frame = speed·dt⁻¹/10 — at dt 0.01 and 8× that's 80/frame, still safe, but the constant silently depends on the SPEEDS cap staying ≤8. Worth a sentence where SPEEDS is defined.
