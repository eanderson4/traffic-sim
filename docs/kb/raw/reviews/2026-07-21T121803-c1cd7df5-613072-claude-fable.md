## Review — M12 variant overlay (engine/scenario)

Verified against the ADR-0012 M12 addendum (§287–361): grammar, patch semantics, hash-frame model, and fmt scoping all match the decided design. Determinism discipline is clean — the only map iterations in load paths are membership checks or sorted before use (`variant.go:428` leftover sort), patches apply in manifest/declaration order, and the hash rides struct re-encodes as before. No NATS subject/payload changes. I could not execute `go test` in this session (Bash approval unavailable), so the golden variant hash and the suite are reviewed statically, not re-run.

**Blockers** — none.

**Should-fix**

1. `engine/scenario/variant.go:65` (`Set yaml.Node`) — **duplicate keys inside a patch `set` are silently collapsed, last-wins.** yaml.v3's duplicate-key error is raised in the decoder only for map/struct destinations; decoding into a `yaml.Node` preserves both pairs without error, and neither `rejectNonStrict` nor `rejectNull` checks for them. `mergeMapping` (`variant.go:421`) then applies both pairs in order, so `set: {veh_per_h: 100, veh_per_h: 200}` merges to a single key `200` *before* `parseDemand`'s strict fence ever sees the document — the one spot in the format where a dup key is accepted silently instead of failing loud. Deterministic, and the hash stays consistent with the materialized result, but it contradicts the strict-subset contract (and the comment at `scenario.go:658` — "duplicate mapping keys are already a yaml.v3 parse error" — which is untrue for Node destinations). Fix: reject duplicate mapping keys when walking `p.Set` in `validateVariant` (the `rejectNull` walk is a natural place for a combined check).

**Nits**

2. `engine/scenario/variant.go:113` — empty-override asymmetry: `types: []` is specially rejected (`variant.go:307`, good), but `params: {}` silently resets the base's `dt` to the engine default and `spawner: {}` silently disables the base spawner (rate 0). Both are legal "replace wholesale" per the addendum, and the no-demand check catches the worst spawner case, but a base with a non-default `dt` can be silently reverted by an empty mapping the author probably meant as a no-op. Consider rejecting empty `params:`/`spawner:` mappings with the same "omit to inherit" message.
3. `engine/scenario/scenario.go:516–531` — the new duplicate-part-ref / manifest-name-ref rejection is a validation tightening within `format_version: 1`: a previously loadable (if pathological) scenario now fails. The rationale comment is right and fail-loud is the ADR's stance; just noting it's a behavior change without a version bump, worth a line in the commit message.
4. `engine/scenario/variant.go:430` (`mergeMapping`) — when `dv != nil` the inner loop re-scans `dst.Content` for the index even though `mappingValue` already found the value node; a scan-once-for-index helper would drop the double walk. Style only.

**Questions**

5. `engine/scenario/variant.go:305` — `base` may climb arbitrarily far (`../../..` to anywhere), while part refs are symlink-fenced inside their directory. The addendum explicitly allows `../`, so this is per design; flagging only because it makes "the directory is the unit of sharing" one-sided — a shared variant dir is not self-contained. Presumably fine for local-first, deferred to the pack format.

Also confirmed sound, for the record: the fail-loud stat dispatch in `Load` (`scenario.go:150–166`), the `yaml.Node` carve-out in `checkNodeTypes` (real schema check happens post-merge), the network shadowing/collision rules, hash-frame equivalence to the hand-written layout, and fmt's variant-only file scope with comment preservation.

REVIEW-COMPLETE
