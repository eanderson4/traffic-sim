# Review — staged diff (TSSG chunking / chunked GeoJSON / run-identity / themes)

No blockers found. The chunking design (complete standalone v1 frames, encode-once cache, order-based generation detection with the documented `sig_gen` limitation) is internally consistent, the contract changes are properly ADR'd (0016/0018 ratified, asyncapi bumped to 2.3.0, `EmptyPayload`/`SignalTable`/`stateSigReq` refs all resolve), and the determinism-sensitive paths are clean (pure file-order chunk pack; wall clock confined to supervisor infra and the already-contracted `CreatedUnix`; no map-iteration ordering in published paths).

## Should-fix

1. **`viz/src/main.ts:632`-ish (`requestSig`) — the 3-pull budget permanently burns out during engine startup, disabling the pull path ADR-0016 exists for.** On a big live demo, serve's broker accepts connections before the world build (~400 s on la-lean), but the `sig.req` responder only subscribes when the Bus is created after the build. The attach-time `requestSig()` therefore hits no-responder/timeout, and the recursive retry (`if (!completed || retry || …) requestSig()`) burns all 3 attempts long before the responder exists. `sigReqRetries` resets only on a *pull* success or a ws reconnect — neither happens here (the connection never drops) — so every later broadcast-gap/partial-stall `requestSig()` is a silent no-op for the rest of the session. The busy tab then depends entirely on eventually receiving one complete 10-chunk broadcast round — the exact failure mode the ADR was written against. Worse on paused replay, which has no broadcast fallback at all: a burned budget means no signal table until reload. Cheap fixes: don't count no-responder/empty-reply outcomes against the budget, or decay the budget on a timer, or re-arm it when the first broadcast chunk arrives (proof a responder now exists).

2. **`engine/cmd/demosrv/geojson.go:105`,`184` — every `/net` part request re-reads and re-SHA256s the entire network file twice.** `part()` calls `netKey` (full read + hash) for validation, then `c.path()` which calls `scenario.Load` + `netKey` again. For la-lean that's ~8 full reads of a several-hundred-MB `network.json` per page load, all synchronous under request handling, on top of streaming the ~1 GB of parts. Correctness is fine (part filenames are content-pinned); it's pure wasted IO/latency on exactly the networks this feature targets. A tiny mtime+size-keyed memo of `netKey`, or having `part()` skip the second hash by passing the validated hash into a stat-only fast path, removes it.

## Questions

3. **`contracts/asyncapi.yaml:583` — `x-reply` instead of AsyncAPI 3's native `reply` object on the operation.** AsyncAPI 3.0 has first-class request/reply (`operations.*.reply` with `channel`/`address`). Was the extension deliberate (tooling limitation), or worth migrating while the channel is new? Not a contract-content problem — the semantics are documented either way.

4. **`engine/cmd/demosrv/supervisor.go:337` (`waitIdentity`) — one fresh ws connect + JetStream + KV get per second for up to 660 s.** Works, but a single held probe connection with a KV watch would be both cheaper and faster to converge. Fine to defer; flagging in case the 1 Hz connect storm shows up in engine logs during long world builds.

## Nits

5. `engine/cmd/demosrv/geojson.go:71` (`isManifest`) — substring sniff for `"parts"` in the first 4 KiB can false-positive on a feature id/property literally equal to `parts` in a single-file net. Consequence is only a spurious `no-store` header; fine at this stage.
6. `engine/cmd/demosrv/supervisor.go:352` — the post-probe child-death error says the run "belongs to a foreign process", but with per-spawn unique ids the likelier cause is our own child crashing right after registering. Message will mislead the first person who debugs that path.
7. `viz/src/main.ts` (`handleSigMessage` catch) — a malformed `sig_chunk`/decode error is reported via `hud.setConnection(false, …)`, claiming a connection failure that isn't one. Pre-existing pattern, just now reachable from a new parse path.
8. `engine/cmd/demosrv/geojson.go:196` (`geoJSONFrameOf`) — hand-mirrors the exporter's frame construction; if `encodeGeoJSON`'s frame ever gains a field, the manifest silently drifts unless `geojsonSchemaVersion` is also bumped. A shared helper in `engine` would remove the duplication.

Test coverage on the new surfaces is genuinely strong (chunk-pack boundaries, tick patching, accumulator gap/regression/same-tick cases, request/reply round-trip against a real embedded server, manifest/part HTTP contract, identity phases against real ws brokers).
