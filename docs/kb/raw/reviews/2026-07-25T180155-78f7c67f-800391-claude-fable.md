## Review: ADR-0020 demosrv public deployment (staged diff)

Verified: staged == working tree for all demosrv files; `go vet` clean; `go test ./cmd/demosrv/` passes (4.5 s). No NATS subject/payload changes — the HTTP-surface changes (401 gate, new 409 semantics) are covered by ADR-0020, and the broker-auth go-live precondition is correctly registered as a pending ADR-0006 amendment rather than papered over.

**Blockers:** none.

I walked the concurrency scheme adversarially — `stop()`'s pending-then-epoch order vs `startGuarded`'s closed→epoch-snapshot→pending→closed-again order (supervisor.go:377-409, startGuarded entry + final revalidation supervisor.go:338-353), the reaper/`startIfIdle` corpse window, the autostart epoch0 capture at the `go` statement (main.go, evaluated synchronously pre-Serve), and the Serve-error/signal double-shutdown path (`shutdownOnce`, idempotent `shutdownFinal`). No interleaving found that spawns past the latch, un-stops an operator stop, or leaks a child on exit. The one hole that exists (operator-started run crashing inside the retry window gets replaced) is explicitly accepted in the ADR.

**Should-fix**

1. `deploy_test.go:1083-1125` (`TestResolveAdminToken`) — use `t.Setenv` instead of manual `os.Setenv`/`LookupEnv`/cleanup. The manual restore is correct today, but `t.Setenv` also panics under a future `t.Parallel()`, which is the failure mode this hand-rolled version would silently race instead.

**Nits**

2. `deploy.go:298-312` (`validateWsPublic`) — `url.Parse` accepts spaces/control chars in the path (`wss://host/a b` validates), the same copy-paste-typo class the validator exists to catch. Cheap to reject non-token characters; fine to skip at this stage.
3. `deploy.go:276` (`stripEnv`) comment / ADR rationale slightly overstates the threat: the engine child runs same-UID, so it could read demosrv's own `/proc/<pid>/environ` regardless. The strip's real value is accidental-leak defense (child dumping its env, crash reports) — worth one word of honesty if the comment is ever touched, not worth a re-review.

**Questions**

4. `supervisor.go:550` — during the identity phase, epoch-abort latency is bounded by one `natsio.ProbeRunMeta` call plus the 1 s sleep. If ProbeRunMeta's internal dial timeout is multi-second, SIGTERM→child-kill on a public pod inherits it. Pre-existing (the old `abortGen` check sat at the same loop position), so out of scope here — just confirm it's acceptable for the K8s `terminationGracePeriodSeconds` you pick.

Notably solid: fail-closed token intake with presence-awareness on both sources, `-wspublic`⇒token coupling, raw-`#` fragment check, gate-at-mux so autostart is ungated by construction, and the 409-vs-502 distinction propagated to replay.go:130-139.

REVIEW-COMPLETE
