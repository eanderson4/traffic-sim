# Review — M12 overlay (variant.yaml) implementation

**Blockers:** none found.

I specifically hunted the classes the brief names and came up clean:

- **Hash identity:** patched parts hash via `parseDemand`'s struct re-encode (`scenario.go:283`), unpatched parts reuse the base's captured canonical bytes (`variant.go:245`), the materialized manifest strips seed/ticks (`variant.go:214`), and the replaced network drops the base's network frame while the shadow layout keeps one frame per rel path (`variant.go:180-183`). All four equivalence tests (identity, patch, replacement, shadowing) pin hash-equals-hand-written, plus a golden vector and a CRC run-identity test.
- **Determinism:** the only map iterations are lookup-only (`origins`, `baseRefs`, `seen`, `anchors`) or sorted before emission (`leftover`, `variant.go:250-254`). Patches apply in base-manifest-order × variant-declaration-order. No wall clock, no RNG, no float accumulation.
- **Fail-loud coverage:** the base snapshot (`base.parts`) is the sole source of inherited bytes — no re-read TOCTOU (`variant.go:163-166`); `Stat` errors other than not-exist don't reroute dispatch (`scenario.go:158-163`); dup keys inside `yaml.Node` patch sets are closed by `rejectDupKeys` since yaml.v3 only rejects them for map/struct destinations (`variant.go:353`); null-as-deletion is fenced at both the whole-document and per-set level; the `checkNodeTypes` bypass for `yaml.Node` (`scenario.go:705`) is safe because the merged document re-enters the full strict fence, and the "coercion in set" test proves it.
- **Contract:** no NATS subjects or payloads touched; the ADR-0012 M12 addenda (design + implementation notes) exist in the working tree — they're docs-exempt but should ride in the same commit.

## Nits

1. `variant.go:100` — when the base directory holds *both* manifests, the chaining check fires first and reports "base is itself a variant" instead of the more accurate both-manifests error `Load` would give. Cosmetic misdiagnosis.
2. `variant.go:118` + `scenario.go:478` — an explicit `ticks: 0` override reports "missing ticks", unlike the care taken for `network: ""` (`variant.go:92`). An author zeroing ticks gets told the field is absent.
3. `variant_test.go:432` — `_ = baseDir` blank-assign; just don't bind the second return.
4. `variant.go:353-368` (`rejectDupKeys`) — non-scalar mapping keys all have `Value == ""`, so two complex keys in a set report as `duplicate mapping key ""`. Fails loud either way, but the message is nonsense for that input.

## Questions

1. Null asymmetry: `rejectNull` makes `seed: null` a hard error in variant.yaml, while `scalarTag` (`scenario.go:781`) still admits nulls in scenario.yaml ("author's business"). Justified — null≡absent is only a removal directive where absence means *inherit* — but if you want one strictness story, tightening scenario.yaml later is a hash-neutral change (null fields already decode to zero/absent).
2. `resolvePart`'s new drive-letter check (`scenario.go:449`) also rejects legitimate POSIX names like `a:b.yaml`. Presumably the intended portability trade; noting it's a (pre-hash-binding) behavior change for plain scenarios too, not just variants.
