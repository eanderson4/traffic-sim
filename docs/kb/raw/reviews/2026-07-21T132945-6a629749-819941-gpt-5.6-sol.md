- **blocker** `engine/metrics.go:282` — First observations assume every vehicle spawned at `S=0` during that tick. Vehicles present when the kernel is constructed—especially ring initial populations—therefore add their absolute position as distance, corrupting VMT, trip distance, time-loss, and entry tick. Seed `last`/trip state from tick-0 engine state or otherwise distinguish initial vehicles.
- **blocker** `engine/metrics.go:393` — Despawned vehicles disappear before `Observe`; the “gone” path emits the trip without accounting for the exit tick’s distance, time, time-loss, occupancy, or stops. Every completed trip is consequently short by its final vehicle-tick; same-tick spawn/despawn vehicles are invisible entirely.
- **blocker** `engine/metrics.go:426` — Interval bounds are off by one. With the first observation at engine tick 1, `closeDue` closes `[0,P)` at tick `P-1`, so it contains only `P-1` observations while using a `P·dt` denominator; `Finalize` then uses `tick+1`, making a 1500-tick run span 1501 metric ticks. This biases q/k/occupancy and manufactures a partial interval at exact horizons.
- **blocker** `engine/metrics.go:339` — A successor crossing followed by a lateral hop in the same tick enters this branch; `v.S-prev.s` is normally negative and clamped to zero, losing the entire tick’s distance. This is reachable because boundaries precede lane changes and directly violates ADR-0014’s split/conservation rule.
- **should-fix** `engine/metrics.go:327` — Crossing time-loss is not “split by the same proportion” as ADR-0014 requires. Independent lane-speed calculations can produce a negative lane contribution, which is appended whenever their sum is positive. Interval time-loss can therefore be negative even though per-tick time-loss is clamped.
- **should-fix** `engine/metrics.go:370` — Occupancy assigns the full tick to the final lane even when distance/time were split across a lane-boundary crossing. ADR-0014’s `time_present × vehicle_length` definition requires the same `tOld`/`dt-tOld` split.
- **should-fix** `engine/metrics.go:520` — `MeanTimeLossS` is zero whenever `KernelConfig.Trips` is false because its numerator and denominator are updated only by `emitTrip`. This contradicts the stated invariant that run totals remain defined independently of trip-record emission.
- **should-fix** `engine/metrics.go:254` — Duplicate lane IDs are accepted. Because `lanes` retains duplicates but `acc` aliases them, interval closure emits one populated record followed by a duplicate zero record after resetting the shared accumulator.
