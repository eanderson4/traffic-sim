**Should-fix**

1. `engine/cmd/demosrv/deploy.go:341-359` — the "autostart never un-stops what an operator stopped" invariant (round 17) has a residual hole: the loop checks `stopEpoch != epoch0` *before* calling `startIfIdle`, then blocks on `s.mu`. If an autostart retry queues on `mu` behind an operator's start (which can hold the lock through the ~660 s identity wait), and the operator's *stop* also queues and wins the lock race after the start releases, the stop completes fully (`stopPending` back to 0), and autostart then acquires `mu`, snapshots the *new* epoch, finds idle, and spawns — resurrecting a demo the operator deliberately stopped. Go's mutex starvation mode makes the longer-blocked autostart waiter likely to acquire first (getting the terminal `errAlreadyActive` instead), so the window is narrow — but the clean fix is cheap: thread `epoch0` into `startIfIdle` and compare against it under `mu` (where the snapshot at deploy.go:341 is taken today, the comparison at supervisor.go happens against a fresh load instead). Recordable-and-defer is a defensible triage given autostart only runs in the pod's first seconds.
