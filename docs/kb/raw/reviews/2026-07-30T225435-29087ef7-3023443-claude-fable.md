## Blocker

**B1. `rerouteTable`'s reachability walk does not actually install the candidate it is checking — a chain that revisits lane `i` escapes through the still-static `mixed[i]`, passes the check, and the subsequent install closes a real routing cycle.** `engine/routing.go:323-337`.

The comment (routing.go:293, and the ADR §2 "with all earlier candidates already installed") specifies the walk simulates the table *with the candidate installed*. The code walks `j = fresh[i]; j = mixed[j]; ...` while `mixed[i]` still holds the static hop. Trace: suppose the mixed chain from `fresh[i]` leads back to `i` (possible in any cyclic network, which chi-loop-urban is — earlier-installed candidates or static hops can point at `i`). The walk reaches `i`, follows `mixed[i] = next[i]` (static), reaches the destination, sets `reached = true`; then `mixed[i] = fresh[i]` creates the cycle `i → fresh[i] → … → i`. The served table now strands every vehicle routed through it in a loop — and if the loop is free-flowing, the floored dwell samples (routing.go's own comment at :274-275) keep its weights at free flow, so no later epoch ever breaks it. This is precisely the pathology the constructive check exists to prevent, and it silently voids the ADR's "never abandon the destination" consequence and the induction argument at routing.go:279-281. The diamond/dual-exit test topologies are acyclic, so no current test can catch it.

Fix is two lines: install `mixed[i] = fresh[i]` before the walk, start the walk at `i` (or keep starting at `fresh[i]`), and revert on `!reached`. With the candidate installed, the walk is a pure function iteration, so any revisit of any node (including `i`) loops until the `hops <= len(mixed)` bound and is correctly rejected — and the induction (installing at `i` only rewrites chains that pass through `i`, all of which now follow `i`'s verified chain) becomes sound. Deterministic either way; this is a correctness bug, not a replay bug. A cyclic-topology test (e.g., a two-lane loop with an exit) should pin it.
