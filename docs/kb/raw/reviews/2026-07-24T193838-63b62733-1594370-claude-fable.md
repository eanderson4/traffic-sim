## Review — staged diff (TSSG chunking / chunked GeoJSON / demo identity / themes)

Verified against the patch plus the vendored `nats.ws` client and repo context. Determinism discipline is clean (chunk pack is a pure function of file order, stop-sign clustering is insertion-ordered, no map iteration on published paths, wall clock confined to demosrv infra). Contract changes (`ts.{run}.state.sig.req`, `sig_chunk` header, MaxPayload 4 MiB, GeoJSON manifest) are all covered by ADR-0016/0018 in this same commit.

### BLOCKER

1. **Unchunked signal tables throw on every frame — signal heads never render on any current demo.** `viz/src/main.ts:355` and `:379` call `parseSigChunkHeader(headers?.get("sig_chunk"))`. In the vendored nats.ws, `MsgHdrs.get()` returns `""` — not `undefined` — when the key is absent (`node_modules/nats.ws/lib/nats-base-client/headers.js:186`, `get()` falls through to `return ""`). Every TSSG publish always carries headers (`tick`, `schema_version` — `engine/natsio/bus.go` PublishSignals), so an unchunked table (n=1, no `sig_chunk` header — every net with a table under 768 KiB, i.e. all existing demos) yields `headers.get("sig_chunk") === ""`, and `parseSigChunkHeader("")` throws by design (`viz/src/tssg.ts:~4409`; the test at `viz/test/sigchunk.test.ts` explicitly pins `""` as malformed). Result: every broadcast frame AND every pull reply hits the catch — table never installed, HUD flips to error. The suite misses it because the tests feed `undefined` for "absent," which the real API never produces. Fix: map `""` → absent before parsing (or check `headers.has(...)`); nats.ws cannot distinguish present-but-empty from absent anyway. (`nats-client.ts:89` is unaffected — `if (c)` treats `""` as falsy.)

### Should-fix

2. **`handleStart` run-id race** — `engine/cmd/demosrv/main.go:330`: the run id is read via a second `s.sup.status()` call after `start()` returns. A concurrent start of another demo, or an immediate child exit, between the two calls produces a URL with the wrong run — or `run=` empty (status `ok=false` → `run ""`), which the viz then treats as run `demo`. Have `start()` return the spawned run id instead of re-reading shared state.

3. **Pull-path budget permanently exhausts in exactly the busy-tab case it exists for** — `viz/src/main.ts` `requestSig`: `sigReqRetries` (cap 3) resets only in `installSigTable`, i.e. on a *completed* generation. On a chronically dropping tab (ADR-0016's motivating incident) three failed pulls disable the pull path forever; subsequent broadcast gaps keep calling `requestSig` but it no-ops, and gapped broadcasts never complete to re-arm it. Consider re-arming the budget per new broadcast generation or on a cooldown timer.

### Nits

4. `engine/natsio/bus.go:317` — `noteFrameSize` is recorded even when the publish failed (snapshot path only notes on success); cosmetic inconsistency.
5. `viz/src/main.ts:355,379` use the literal `"sig_chunk"`; `tssg.ts` exports `SIG_CHUNK_HEADER` for exactly this.
6. `handleSigMessage` catch calls `hud.setConnection(false, …)` for a payload/header parse error — the connection is fine; misleading status (pre-existing pattern on the snapshot path).
7. `netCache`: if the manifest survives but a part file is pruned, `part()` 404s forever (`path()` early-returns on the manifest stat) until the manifest is also deleted — acceptable for a dev cache, noting it.

### Questions

8. `wsClientURL()` (`supervisor.go`) embeds a wildcard listen host verbatim (`ws://0.0.0.0:8443`) into client-facing URLs — the comment says deliberate ("the operator owning -ws owns what clients dial"), but a browser handed `0.0.0.0` behaves inconsistently across platforms. Confirm the intended operator workflow always passes a dialable host.
