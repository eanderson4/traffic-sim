## Review — warm start (ADR-0029 p1), gridlock escape (ADR-0034), permissive green (ADR-0031/0033), routed lookahead (ADR-0032)

Read the full diff plus the surrounding engine sources. `go vet ./...` clean. Determinism discipline checked and holds: fingerprints hash lanes in index order with length-prefixed ids and IEEE bits (`engine/warmstart.go:120`), the strand sweep walks `e.order` with a tick counter and no clock/RNG (`engine/gridlock.go:79`), the gridlock print sorts sections (`engine/cmd/serve/main.go:757` area), `fastForward` uses the exact arrival-tick formula the send path uses (`director.go:277` vs `:344`), and the v5 empty-queue writer/reader condition mismatch was correctly closed on both sides with an err-check before trusting the count (`engine/keyframe.go:338-347`).

### Blockers

None.

### Should-fix

1. **ADR-0029 describes a serve integration the code refuses, and the standalone escape hatch ships the exact silent-duplicate the refusal exists to prevent.** ADR-0029 "Phase 1 as built" says the director fast-forward is "set by serve from the sidecar's tick" (docs/kb/decisions/ADR-0029-warm-start-from-keyframe.md, "demand director fast-forwards" bullet) — but `validateStateFlags` rejects `-state-in` with demand parts outright (`engine/cmd/serve/main.go:911`), so serve never sets a nonzero `StartTick`; the ADR never mentions the refusal. Meanwhile `demand-director -start-tick` (`engine/cmd/demand-director/main.go:28`) remains available and has precisely the failure serve's own comment documents: the restored state's `dirQueue` already holds the accepted `(N, N+Lead]` window, `fastForward` skips only `≤ N`, and the per-process request-id dedup starts empty — those arrivals spawn twice. Fix the ADR to record the refusal, and either warn/refuse in the standalone tool or document the hazard on the flag (its help text currently claims the skip is sufficient).

2. **"Format v5" is double-booked.** ADR-0029 reserves v5 for lane-id keyframes ("Decisions 1 (format v5, lane ids)…", also `engine/warmstart.go:28` and `engine/warmstart_test.go:177`), but this same commit assigns v5 to the stuck timer (`engine/keyframe.go`, `keyframeStuckVersion = 5`). Anyone implementing ADR-0029 decision 1 from its own text will collide with a shipped format number. Update the three prose references to "the next format version".

### Nits

3. `limit := uint64(e.Params.StrandAfterS / e.Params.Dt)` truncates: 300/0.1 in float64 is ~2999.99…, so the threshold is 2999 ticks — one tick short of the documented 300 s (`engine/gridlock.go:84`). Deterministic and harmless; `math.Round` if the exact figure ever matters.
4. Test message inverted: `t.Fatal("the escape is off by default…")` fires when the escape is off, in a test asserting it is **on** by default (`engine/gridlock_test.go:196`).
5. The `-state-at == warm-start-tick` rejection's rationale is wrong: RunLive dumps at the starting tick pre-loop (`engine/natsio/run.go:186` area), so it *would* fire; the refusal is fine as a usage rule but the message "the loop starts past it, so the dump would never fire" (`engine/cmd/serve/main.go:920`) misstates the mechanism.
6. serve's guards (seed mismatch, metrics observer, store) live only in the CLI; `RunLive` accepts `InitialState` + `Observer`, where the metrics kernel will **panic** ("first Observe not at tick 1") rather than error. Acceptable for phase 1, but a one-line check in `RunLive` would make the API fail the way the CLI does.
7. Asymmetric strictness: `-state-at` without `-state-out` is an error, but `-state-reseed` without `-state-in` is silently ignored (`validateStateFlags`).

### Questions

8. The permissive-green split and the routed-branch lookahead change trajectories unconditionally, so pre-change recordings that exercised a diverge or a permissive link will fail CRC verification if replayed under the new binary. (The strand escape is safe across the boundary: old registry specs unmarshal `StrandAfterS` as 0, escape off.) Are the existing chi-loop show recordings pinned to their binary, or considered expendable? Worth one line in ADR-0031/0032 either way.

The core mechanisms are sound: the sidecar interlock (count → fingerprint → digest → tick cross-check, empty-guard-is-refusal), the head-of-lane + box-blocked strand discriminator with the backward timer reset, the mutual-yield tie-break via `foeSignalClass`, and the CRC-chain bit-exactness oracles are all correctly built and well pinned by tests.
