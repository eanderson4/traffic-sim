## Findings

**Should-fix**

1. `deploy/README.md:114-118` — the token-rotation note is backwards. Re-running the Secret apply rotates the *stored* token, but the pod captured `DEMOSRV_ADMIN_TOKEN` from the `secretKeyRef` at container start (deploy/k8s/deployment.yaml:485-489): the **old** token keeps working and the **new** one is dead until a pod restart. As written ("invalidates the old one") an operator would believe rotation is immediate — for an auth credential that's the wrong direction to be wrong in. Add "then `kubectl rollout restart` to make it take effect / actually invalidate the old token."

**Question**

2. `deploy/k8s/backendconfig.yaml:25-28` — even after `/healthz` lands, the ws backend's health is coupled to a *live engine child*: 8443 is bound by the spawned serve process, so during every switch (LA world build ≈ 400 s per engine/cmd/demosrv/main.go:288) and every crashed-child idle window the ws backend goes unhealthy and all viewers' dials 502 — including viewers of the outgoing run's teardown. The README documents the idle window but not the switch-window ws outage. Worth stating in the ADR-0020 precondition so the `/healthz` engine round knows the constraint (or decides demosrv should front the health signal). Not actionable in this diff.

3. `deploy/k8s/deployment.yaml:446-459` — the initContainer's GCS access rides the node/metadata-server identity (README: node SA has `objectViewer`). If `carbon-dev` has Workload Identity enabled, the metadata server won't hand out the compute SA and the pull 401s → crash-loop. README says setup was exercised 2026-07-25, so presumably fine — confirming the cluster's WI posture in the README would make the IAM note trustworthy.

**Nits**

4. `deploy/k8s/backendconfig.yaml:15-17,26-28` — no explicit `type: HTTP` on either healthCheck; GKE infers the protocol, but the manifest elsewhere states inherited defaults explicitly (the NEG annotation comment, service.yaml:626-628). One line each buys the same insurance.
5. `Dockerfile:48-59` — final stage has no `USER`; anyone running the image outside the Deployment's `securityContext` (local `docker run`, a future compose file) gets root. `USER 1000` in the image would make the non-root posture self-contained.
6. `deploy/k8s/deployment.yaml:459` — `gcloud storage cp "gs://…/netcache/*"` hard-fails on an empty prefix (glob matches nothing), crash-looping the pod; the overlay dir got tolerant handling but netcache didn't. README documents the all-or-nothing behavior for scenarios but the netcache glob is a second, subtler instance. Fine for v1.
