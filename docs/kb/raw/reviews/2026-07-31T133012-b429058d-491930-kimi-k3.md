  ## Review: ADR-0037 milestone 1 (`signal_set` verb, TSKF v7)

  **Blockers:** none.

  The core mechanics hold up under scrutiny: the override map is lookup-only with all iteration in network order (engine/sigctl.go:215, engine/engine.go CRC fold); the CRC/keyframe gating on a non-empty table preserves pre-ADR-0037 bytes for no-verb runs (pinned by `TestSignalKeyframeVersionFloor`); `sigSpanOnset`/`sigDisplayedOnset` correctly handle lapse-onto-schedule and supersession in both amber and green directions (I hand-traced the four transition cases against engine/signal.go:283-328; the tests pin them); replay/bake/player/logcursor all re-enqueue in spawn-then-signal order matching live application order; the keyframe flags-word split (`hasLaneSection`, engine/keyframe.go:400) is writer/reader symmetric for v6/v7 × flag on/off. Contract change is additive with the ADR-0006 addendum and asyncapi 2.7.0 in the same diff — the "sacred contract" rule is satisfied. Unapplied `sigNew` is unkeyframed, matching the spawn `dirNew` precedent (engine/director.go:164).

  **Should-fix:** none.

  **Nits:**

  - engine/natsio/logcursor.go:97-110, engine/natsio/replay.go:76-90 and 229-243 — the spawn branch unmarshals the payload twice (`decodeLoggedVerbKind` then `decodeLoggedVerb`). `decodeLoggedVerbKind` already returns the full `loggedVerb`; a `toSpawn()` twin of `toSignal()` would drop the redundant decode. Low-rate path, cosmetic.
  - contracts/asyncapi.yaml:1488-1489 — `signal_idx` and `phase` are Go-`omitempty` (engine/natsio/verb.go), so a phase-0 or index-0 record omits the key on the wire; the schema documents neither the omission nor the default-to-0 reading. The decoder does the right thing; the doc should say so (as the `phase` field of `signal_lapse` already does at line 1609).
  - engine/engine.go:1041 — stale comment "restored bit-exactly by keyframes (TSKF v2/v3)"; predates this diff but the version line is now 2–7.

  **Questions:**

  - engine/keyframe.go:394-401 — the v7 reader masks `flags&keyframeFlagAdaptive` and silently ignores any other set bit. The same diff's verb discriminator takes the opposite stance (unknown kind = hard error, engine/natsio/verb.go:1859). Deliberate forward-compat, or should unknown flag bits at a known version be rejected? (CRC verification catches a misread downstream, so this is philosophy, not safety.)
  - engine/sigctl.go:129-133 — kernel dedup checks only the same-boundary buffer (`sigNew`), whereas `EnqueueSpawn` also checks the live queue (engine/director.go:154-163). After application the kernel forgets a signal verb's request id, so a kernel-level caller (not the wire — contract.go:781 dedups for the run's lifetime) can double-apply by reusing an id across boundaries. Acceptable asymmetry given the record is canonical?
  - engine/sigctl.go lapse detection inspects only the newest history entry, so a hold superseded at exactly its bound tick fires no `signal_lapse`. Semantically defensible (the signal never returned to fixed-time) and consistent with "supersession is not a lapse" — confirming that boundary case is intended to be silent on the record.
