Review of the ADR-0039 perimeter-gate diff (density hysteresis, deferral clock, TSKF v8, gate metrics). Findings:

**BLOCKER — Keyframe restore mid-hold expires the entire gate-held backlog immediately, misattributed as non-gate delivery failure.**
`engine/director.go:310-317` + unserialized `dirGateHeld` (`engine/engine.go:212`).
`d.EarliestTick` round-trips through the keyframe (`engine/keyframe.go:349,620`) but `dirGateHeld` does not, so after restore `gateHeld` is 0 and the check at `director.go:316` sees the full elapsed time. Any directive gate-held > 600 ticks at keyframe time expires on the *first* post-restore director step — and because `expireDirective` (`director.go:87`) reads `dirGateHeld[d.RequestID] == 0`, it lands as ordinary expiry: no `DirGateExpired`, no wait stat, so serve's void warning fires on exactly the metering run this change exists to exempt. With the default `gate_hold_max_s` of 1800 s against a 60 s window, holds > 600 ticks are the *normal* state of a metering run (the ADR's chi scenario parks ≈3,500 vehicles at the gate), so a player/replay seek to a mid-hold v8 keyframe diverges from the recorded CRCs the moment the backlog vaporizes — replay breakage reachable in normal operation, the triage bar's own definition. `TestGateKeyframeMidBandRoundTrip` passes only because its fixture is held < 600 ticks at the split. The documented caveat (ADR-0039 line 80-82, `engine.go:212`) says a restore "restarts the deferral clock… can shift that directive's expiry" — the code does the opposite of restart: it forfeits the clock and accelerates expiry to immediate, misclassified. The triage was made on a wrong premise. Cheap serialization-free fix that makes the docs true: on restoring a v8 (gate-engaged) payload, seed `dirGateHeld[d.RequestID] = int(e.Tick - d.EarliestTick)` for each eligible queued directive — clock genuinely restarts, no instant expiry, no misattribution; full fidelity would serialize the map in the v8 section.

**SHOULD-FIX — `delivered_frac` in metrics JSON still counts gate-caused expiry as undelivered.**
`engine/metricsjson.go:198` (`DeliveredFrac: Injected/(Injected+Expired)`). The console path was corrected (`nonGateDelivery` in serve) but the machine-readable contract still reports e.g. 0.75 for a healthy metering run — any consumer applying the 0.95 void threshold to `delivered_frac` reproduces the exact bug this diff fixes on the console. `gated_expired` is present to correct it client-side, but the headline number stays misleading. Either compute `delivered_frac` on the non-gate share (additive-safe: gate-off runs unchanged) or note the consumer obligation in the ADR's metrics section.

**NIT — Stale comment: "version ≥ 7 implies a non-empty table."**
`engine/keyframe.go:365-366`. False since v8: a gate-engaged run with no signal overrides writes v8 with a zero-count signal table. Code is fine (count is explicit); comment now lies.

**NIT — Director evaluates the gate once per tick; spawner re-evaluates per origin.**
`engine/director.go:304` vs `engine/spawn.go:244`. `densityGateHold` mutates the bit, so the spawner can engage it mid-tick while the director's snapshot ignores its own injections' density contribution (the old code re-checked density per directive). Deterministic either way and overshoot is clearance-bounded, but the "exactly the Spawner's rule" comment is now approximately true, and the shared mutable bit means spawner-vs-director step order is load-bearing. Worth one sentence in the comment.

**QUESTION — v≤7 mid-band re-derive duplicates the floor default.**
`engine/keyframe.go:698-702` re-implements the `0.9×cap` fallback from `densityGateHold`. If the default ever changes, the RestoreNotice band check silently drifts. Consider one shared helper.

Everything else checks out: `dirGateHeld` is lookup-only (no map iteration, ADR-0005 clean); the elapsed−gateHeld subtraction cannot underflow in-process (gateHeld ≤ elapsed by construction); v8 version lattice and flag interplay are sound (explicit counts, cap-0 stays byte-identical below v8, capless-spec rejection follows the ADR-0036 precedent); scenario validation covers the floor/cap/hold-max relations with tests; JSON additions are optional/additive and ADR-noted; the void-warning grep string is preserved and the gate line deliberately avoids it.
