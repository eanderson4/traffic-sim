# Review: ADR-0012 + M11 scenario directories

**TLDR:** The core machinery is solid — the strict-YAML fence is thorough and well-tested, the hash framing is sound, and the bit-identity acceptance gate (scenario-vs-flag CRC match) is exactly the right verification. But there is one design-level blocker: **the base seed is hashed into the scenario's content identity**, which contradicts ADR-0012 §6's own run-key model and should be resolved before hashes get durably recorded anywhere. Below that: `scenario fmt` destroys comments (undermining the ADR's stated reason for choosing YAML), non-finite floats sail through validation, the "M10 JSON parses unchanged" claim is false, and the (content-hash, seed) identity claim is silently wrong for director-driven runs.

---

## Blocker (design)

**B1. The base seed is inside the content hash, breaking §6's (content-hash, seed) orthogonality.**
`Manifest.Seed` (scenario.go:51, no omitempty) is encoded into the canonical manifest bytes hashed at scenario.go:140. So two directories identical except `seed: 7` vs `seed: 8` are *different scenarios* by content ID — while `serve -scenario dir -seed 8` (serve/main.go:92-99) produces the *same* hash with a different seed. The comment at serve/main.go:90-91 ("the content hash is unchanged — ADR-0012 §6") is only true for the flag-override path; the moment anyone authors the seed into a variant manifest, "the same scenario" stops being well-defined — which is the one thing §6 says content addressing exists to guarantee. The -seed override's very existence proves seed is a run coordinate, not content. The ADR itself is internally inconsistent here (§1 puts base seed in the manifest; §6 makes it the second run-key coordinate), and M11 resolved it in the wrong direction.

Fix: hash a seed-stripped canonical manifest (zero/omit `seed` in the hashed bytes only), or move base seed out of `scenario.yaml` entirely into sweep tooling. Do it now: nothing durable binds hashes yet (the run-registry KV is ephemeral, recordings are local artifacts per the M10 note), so this is the last cheap moment — after §7 recordings bind hashes, changing the hash definition is a format migration. `ticks` in the hash is defensible by contrast: determinism makes a longer run a strict superset of a shorter one, so `-ticks` override doesn't fork the trajectory — worth a sentence in the ADR, though (see Q1).

## Should-fix

**S1. `scenario fmt` deletes every comment — defeating the ADR's own justification for YAML.**
`Format` (scenario.go:285-300) re-encodes the decoded *structs* via `canonicalYAML`, so all comments and blank-line structure in `scenario.yaml` and demand parts are destroyed. ADR-0012 §2 chose YAML explicitly because it's "the only mainstream format with comments"; §8's round-trip rule says save→load→save loses no information. Running `scenario fmt` on the repo's own `demo-i280.yaml` would strip its header comment. Also note the ADR promised "a canonical formatter (ours, in Go)" — M11 actually delegates the byte format to yaml.v3's encoder + `SetIndent(2)`. A node-level formatter (operate on `yaml.Node`, which carries `HeadComment`/`LineComment`) fixes both: comments survive, and you own the canonical byte format instead of inheriting it. The *hash* can keep using the struct re-encode (comments correctly excluded — `TestHashStableAcrossFormatting` pins that); fmt and hash are separable.

**S2. Non-finite floats pass every validation check.**
`params.dt: .nan` passes scenario.go:332 (`NaN < 0` is false) and is then *applied* at scenario.go:254 (`NaN != 0` is true) — a NaN tick length poisons the entire sim silently. Same hole for `veh_per_h` (scenario.go:372 — `NaN <= 0` is false), slice bounds (:377), slice rates (:383), `until_s` (:388), and vtype weights (:392). `.nan`/`.inf` are plain `!!float`, so the strict fence at scenario.go:444 admits them. For a loader whose doc comment says "fail-loud everywhere" and whose ADR fences the Norway problem, letting IEEE's sharpest footgun through is inconsistent. Add an `isFinite` check to every float field.

**S3. "The M10 strict-JSON flow files parse unchanged" is false.**
The deleted `demo-i280.json` had no `format_version` key; `validateDemand` (scenario.go:355) now hard-fails such a file with "unsupported format_version 0". The claim appears in the ADR addendum (line 217), the package migration comment, and the commit message — and `TestJSONDemandStillParses` (scenario_test.go:254) quietly *adds* `"format_version": 1` to its fixture, masking the break. Impact is small (one in-repo file, migrated), but AGENTS.md treats format changes as migration-note material. Either fix the claim ("parse unchanged after adding format_version: 1") or default a missing demand `format_version` to 1 — I'd fix the claim; strictness is the right call.

**S4. (content-hash, seed) does not actually identify director-driven runs.**
The loader validates and hashes demand parts, but nothing wires them into the run: the director is a separate process with its own `-demand` path and its own `-seed` flag defaulting to **1** (demand-director/main.go:155-156), while the manifest seed defaults elsewhere. `RunMeta` (natsio/registry.go:29) records `(Hash, Seed)` claiming cross-machine comparability (ADR consequences, line 180-182), but the demand realization depends on an unrecorded director seed. Replay is safe (verbs are logged; the sampler never re-runs), but two runs with identical recorded (hash, seed) and different director seeds are *different runs sharing a run key* — the comparability claim §6 exists for is silently void on the director path. The addendum defers the wiring to overlays (line 217-219), but the *claim* is live now. Minimum fix: record the director seed in run meta, or note in the addendum that (hash, seed) identity holds only for spawner-driven runs until the wiring lands.

**S5. Raw-byte hashing of network/control/metrics parts is checkout-fragile, and blocks the overlay hash path.**
Two problems with hashing raw bytes (scenario.go:166, :188-198). (a) git `autocrlf`/`eol` rewrites change those bytes across checkouts — directly contradicting "comparable across machines and checkouts" (ADR line 180). Needs a `.gitattributes` pin (or EOL normalization before hashing) plus an ADR note. (b) Overlays: §4 materializes a *patched* network in memory — there are no raw bytes to hash. You'll need either a canonical netfile serializer (making the network-model ADR a hard dependency of overlays) or hash-of-(base-bytes + patch-bytes). The `hashPart{rel, data}` shape accommodates both, but the choice is unmade and unowned; decide it in the ADR before M12, because it changes what "materialized post-overlay scenario hashes" means.

**S6. (Pre-existing M10, in the touched file) `pickType` sums weights in Go map iteration order.**
demand-director/main.go:133-137: `tot` accumulates over `range weights` — unsorted map order — and the comment two lines above says "Go map order is forbidden anywhere near a sampled path." Float addition is non-associative, so with ≥3 vtypes `tot` can differ in the last ulp between director restarts, flipping `u < cum` at a boundary and violating both ADR-0005 §6 and the "director failover is invisible" claim. Low probability, absolute rule. One-line fix: accumulate `tot` in the sorted-`names` loop.

**S7. yaml.v3's encoder is the de-facto canonical-format spec, and that's undocumented.**
The hash is stable across machines for a *pinned* yaml.v3 (pure-Go strconv, sorted map keys via its numeric-aware sorter — the scenario.go:460 comment is correct), but any yaml.v3 upgrade that changes quoting/float/indent heuristics silently rebrands every scenario. yaml.v3 is effectively frozen upstream, which cuts both ways (low churn risk; also unmaintained). Add one line to the ADR: bumping the YAML library is a format-version event under §8. (Building your own node-level emitter per S1 dissolves this.)

## Nits

- **N1.** scenario.go:332-334: message says "params.dt must be > 0" but the check is `< 0`; `dt: 0` explicitly authored silently means "default." No upper bound either, though ADR-0005 §7 says never above 1 s.
- **N2.** scenario.go:199: `spawner: {rate_per_lane_h: 0}` with no demand parts passes the "an empty run is not a scenario" check — the explicit-zero spawner counts as demand.
- **N3.** serve errors on `-scenario` + `-netfile` (serve/main.go:52) but silently ignores `-rate -density -types` alongside `-scenario` — a user "changing the rate" gets the manifest spawner instead. simrun's help at least documents the override; serve's doesn't. Reject or warn.
- **N4.** validateManifest *mutates* the manifest (scenario.go:335-337 defaults `types: [car]`), so the default is baked into the hash and `fmt` writes it back into files that omitted it. Means the hash is a function of (bytes, loader defaults): if the default type list ever changes, unchanged files change hash. Survivable under format_version discipline, but hashing/formatting a defaulted copy rather than the authored model is worth a comment at minimum.
- **N5.** Part refs are not normalized in canonical form: `./demand/x.yaml` vs `demand/x.yaml` load identically but hash differently (both via manifest bytes and the `rel` framing at scenario.go:140/166/182); backslash refs are non-portable across OSes. Mandate forward slashes + `path.Clean` in validation/fmt. (The `rel\0data\0` framing itself is fine — rel can't contain NUL and reach `os.ReadFile` successfully.)
- **N6.** strictDecode on an empty/comment-only file returns a bare "EOF" (scenario.go:409); and an unquoted date scalar resolves to `!!timestamp`, rejected with the misleading "custom tags and merge keys are forbidden" (scenario.go:446). Both fail loud, both confuse.
- **N7.** `scenario.Scenario` vs `engine.Scenario` (scenario.go:106 / RunSpec.Scen) — two exported types named Scenario meaning different things, one package apart.
- **N8.** Path confinement (scenario.go:305-317) is lexical only; a symlinked part reaches outside the directory, breaking "the directory is the unit of sharing." Fine for local-first trust, worth a comment.
- **N9.** `veh_per_h` alongside `slices` is silently ignored (dead config) but hashed — fail-loud would reject the combination.

## Questions / under-specified for overlay + observability time

- **Q1. How does a variant *change* a value?** §4 says patches address "named entities by durable ID," but `Flow` (scenario.go:88-95) is an anonymous list element — duplicate origins aren't even rejected — and JSON Merge Patch replaces arrays wholesale, so neither flows nor `slices` nor the manifest's `demand:`/`metrics:` lists are patchable at entity granularity. If v1 composition is strictly "add part files," fine — but then the founding use case (baseline rate 600 → variant rate 900) has no overlay expression short of replacing a whole part file, which is the copy-paste the ADR forbids. Decide now whether flows get an optional `id:` (additive, `omitempty` — doesn't move any existing hash) and whether manifest part-lists get append semantics in variant.yaml.
- **Q2.** When control/metrics grow real grammars (observability ADR), their parts move from raw-byte to canonical-byte hashing — every scenario carrying them re-hashes. That's fine under a format_version bump, but §8 should say so, and those part files will need their own `format_version` (they're unparsed today, so nothing enforces one).
- **Q3.** Vehicle-type *definitions* are outside the format: `types:` names resolve against a hard-coded car/truck registry (serve/main.go:74). The hash covers the names, not the IDM parameters behind them — so "same hash, same behavior" holds only per engine version (§7's engine-version binding papers over it for recordings, not for cross-version comparison). Is a `vtypes/*.yaml` part a future format concern? The ADR is silent.

## Load-bearing and good

Briefly, because it's real: the two-pass strict fence (node-walk tag whitelist + `KnownFields` decode, scenario.go:406-457) covers anchors, aliases, merge keys, custom tags, multi-doc, dup keys, and the Norway problem (a `!!bool` into a string field fails loud), with tests for each; the sorted, NUL-framed hash over per-part canonical bytes is the right construction and `TestHashStableAcrossFormatting`'s reorder-and-comment fixture is the right test; the CRC-pinned scenario-vs-flag bit-identity check is exactly the acceptance gate ADR-0005 demands; `RunSpec.Hash` as an additive, non-CRC'd, kernel-invisible JSON field is contract-clean per ADR-0006; and `flag.Visit` for explicit-override detection is the correct semantics. The yaml.v3 confinement mirrors the natsio precedent faithfully.
