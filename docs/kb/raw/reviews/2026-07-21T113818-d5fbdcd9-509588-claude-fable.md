## Findings

**BLOCKER — network replacement leaves `eff.Network` pointing at the base's ref; hash and materialized manifest diverge from the hand-written equivalent.**
`variant.go:136` seeds `netRel` from `base.Manifest.Network`; the replacement branch (`variant.go:163`) updates `netPath, netRel, rawNet` but never `eff.Network`. Consequences: (a) the hashed manifest (`hm := eff`, `variant.go:172`) still says `network: <base ref>` while the network bytes hash under rel `v.Network` — so a network-replacing variant does **not** hash identically to the equivalent hand-written scenario, violating the ADR-0012 M12 addendum §5 acceptance shape and the §4 "conceptual merged directory" frame; (b) the returned `Scenario.Manifest.Network` names a path that need not exist in the variant directory, inconsistent with `NetPath`. `TestVariantNetworkReplacement` (variant_test.go:728) only asserts the hash *moved*, so it can't catch this. Because the content hash is durable identity (run key, recordings), fixing it post-ship is a format event — fix now: `eff.Network = v.Network` in the replacement branch, plus a hand-written-equivalence test for the network path.

**QUESTION — duplicate patches on the same (part, flow).**
`variant.go:191` applies patches in list order; two entries anchored to the same flow (or setting the same key) silently last-win. The ADR is silent, but the package's stated posture is "a typo'd anchor must never silently…" — is silent overwrite intended, or should duplicate `(part, flow)` anchors be a hard error?

**NIT — explicit `types: []` silently becomes `[car]`.**
`variant.go:104-106`: an explicitly empty list is non-nil, replaces the base's list wholesale, then `validateManifest` defaults it back to `["car"]`. Same behavior as a hand-authored manifest, but as an *override* "replace with empty → silently car" is easier to hit by accident; consider rejecting explicit-empty.

**NIT — `v.Network` rel never checked against part rel paths.**
The added-part collision check (`variant.go:110-123`) covers demand/control/metrics but not the network ref, so two `hashPart`s could in principle share a rel. Contrived (a net JSON rarely parses as valid demand YAML), and base `Load` has the same gap — note for the pack-format milestone.

**NIT — latent `checkNodeTypes` trap on `set` keys.**
`Patch.Set` is a `yaml.Node`, so `checkNodeTypes` matches `set`'s top-level keys against `yaml.Node`'s own Go fields (`value`, `tag`, `content`, `line`, …). No current flow field collides, but a future field named one of those would produce a confusing "wants !!str" at variant decode instead of the intended patched-document error.

**NIT — `variant.go:139` reads the base network unconditionally, then discards it in the replacement case.** Harmless dead read.

## Clean on the focus areas
- **Determinism:** the only map in a hashed path (`patchesByPart`) is consumed in `base.Manifest.Demand` order, and leftover keys are sorted before erroring (`variant.go:203-210`); no wall clock, no RNG, hash frame unchanged. Golden variant vector pins the overlay path.
- **Contract:** no NATS surface touched; the `variant.yaml` grammar matches the pre-committed ADR-0012 M12 addendum, which is the required ADR note.
- Patch semantics (recursive mapping merge, wholesale sequence/scalar replace, null rejection, modify-only anchors, single-level composition, both-manifests rejection, fmt-leaves-base-alone) all match the addendum and are test-covered.
