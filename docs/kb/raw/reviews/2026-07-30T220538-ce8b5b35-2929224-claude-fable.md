Review of the staged ADR-0036 diff (congestion-adaptive routing). No blockers found; determinism discipline holds (no map iteration feeds decisions, float updates are fixed-order, no clock/RNG). Findings:

**Should-fix**

1. **`engine.go:789` purity invariant violated without update.** The bucketed `boundaries()` sweep is documented as state-identical to the old `e.order` sweep *only because* "pickSuccessor is pure per-vehicle", with an explicit instruction that "a future order-dependent step here … must preserve the old sweep's e.order scan order instead." Adaptive mode makes `pickSuccessor` → `routeTable` (routing.go:199) order-dependent: it consumes `rerouteBudget` and mutates `routeTabs`/`routeEpochs`. Which asker wins the metered recompute is now decided by boundaries' lane-descending bucket order — and also by the gating probes (`rightofway.go:166,305`, `engine.go:545`), the gridlock escape (`gridlock.go:175`), and even the metrics observer (`updateStats`, engine.go:928), all of which reach `routeTable` and can spend budget or trigger recomputes. Still deterministic, but the ADR's and test's claim that the meter is "served in deterministic `e.order` sweep order" (ADR-0036 §2; adaptive_test.go:428) describes the wrong mechanism, and a metrics/probe read mutating routing state is a footgun. Either make probe/metrics paths serve stale without spending budget, or correct the comments (engine.go:789 especially — it now gives the next editor a false guarantee).

2. **ADR overstates the restore-fidelity bound.** ADR-0036 (Consequences, "divergence window is one epoch"): the *cause* is bounded to one epoch, but a different next-hop taken during that window moves vehicles, which changes later dwell samples, ttEMA, and every subsequent CRC — the trajectories fork permanently. Any post-seek CRC verification against a live recording can mismatch for the rest of the run, which cuts against the keyframe file's own v5 rationale (bit-exact seek is why `stuckTicks` got keyframed). The flag is off by default so nothing durable binds yet, but the ADR text should state the consequence honestly before recordings with the flag on exist.

3. **The gridlock escape never samples** (`gridlock.go:125-126` clears `v.Lane` without `noteLaneLeave`). A stranded vehicle — 300 s+ stopped on exactly the pathology this ADR exists to relieve — contributes zero dwell evidence to the lane it starved on; the router learns only from followers that eventually cross. `noteLaneLeave`'s comment (engine.go:433-438) even reasons about stranded vehicles via the cap but doesn't cover the strand path itself. If deliberate (the vehicle is teleported, not driven out), document it; otherwise fold a capped sample before removal.

**Nit**

4. **Zero-dwell samples drag ttEMA below free flow.** A chained same-tick hop (boundaries re-bucketing, engine.go:866) or a lateral hop shortly before a crossing feeds `dwell ≈ 0` into `l.ttEMA += (dwell − ttEMA)/8` (engine.go:448), so frequently-chained short lanes read *cheaper than empty*. Bounded and self-correcting via relaxation, but flooring the sample at `freeFlowTime(l)` would remove a systematic optimistic bias.

5. **Pre-v6 keyframe into a flag-ON spec poisons on restore** (keyframe.go:352-355): every vehicle restores with `laneEntryTick = 0`, so each first departure feeds a capped 300 s sample into its current lane. Initializing to the restore tick when `ver < keyframeAdaptiveVersion` would be strictly better for the "replay an old recording with the flag flipped" what-if.

6. `cap :=` shadows the builtin in `noteLaneLeave` (engine.go:445). Legal, mildly confusing.

**Question**

7. **Mixed-table acyclicity is asserted, not argued.** After the first reroute, "old" is a hysteresis-mixed table, so the comment "Old tables are trees — no cycles" (routing.go:240-241) is no longer self-evident — and while the walk cap protects the recompute, *vehicles* follow the mixed table with no cap. I believe it's actually safe: for any would-be cycle, each kept node's margin telescopes against its downstream flipped node's (margin(u) − margin(flip) ≤ 0.15·segment weight), forcing Σw < 0.15·Σw — impossible with positive weights. But that property is load-bearing and lives nowhere. A comment or a small adversarial test would protect the next editor who tweaks the margin formula (e.g., a per-lane additive margin would break the telescoping and admit real routing loops).

8. ADR header says "No wire change" while the keyframe format bumps to v6. If keyframes ride the record plane, that's a versioned, flag-gated payload change — fine under the version gate, but the ADR should say "keyframe format v6, flag-gated" rather than a blanket "no wire change" (ADR-0006 sacred-contract optics).

Verified clean: v6 writer/reader symmetry incl. the nLanes guard (keyframe.go:230-235, 352-370); flag-off byte-identity (version scan + `routeWeight` reduce exactly to the static path); `routeEpochs` init via `NewEngine` on the restore path (no nil-map assignment reachable); dwell-clock coverage at all five vehicle-creation sites; oldCost walk convention matches the builder (dest included, origin excluded); test arithmetic in adaptive_test.go checks out.
