## Should-fix

1. **Claim-violation "assertion" doesn't exist, and the per-tick count can't substitute for it.** BENCHMARKS.md (new §(d), ~engine/BENCHMARKS.md:105) says correctness is "asserted per tick (drained == published; claim violations = 0)", but the code only asserts `len(keyed) == n` (bench_intent_test.go:216) and merely `b.Logf`s the violation count (bench_intent_test.go:237–238). The count check cannot catch a violation: with `ContractConfig{}` defaults (`HoldLastTicks` = 2, contract.go:111–112) and cadence 1, a claim-filtered fresh intent is backfilled by a hold-last re-issue (contract.go:777–809), keeping `len(keyed) == n` while silently swapping the measured work from the claim-holder path to the hold path. Add `if violations != 0 { b.Fatalf(...) }` after `contract.Stats()` (and/or assert no keyed intent has `Held == true`), or soften the BENCHMARKS.md sentence. Cheap fix, and it's the validity guard for the baseline every ADR-0026 milestone will be compared against.
