## Findings

**Blockers:** none.

I walked the shutdown/autostart races the comments claim to close, and the design holds: `closed` is stored before the `abortGen` stamp in `shutdownFinal` (supervisor.go:347-354), and `startGuarded` re-checks `closed` under `mu` after allocating its generation (supervisor.go:241-249) — sequential consistency of Go atomics means a start that passes the second check has its generation covered by the stamp, so it aborts inside `waitReady` and its child is killed by the failure-path `stopLocked`. The corpse-clear in the idle guard (supervisor.go:225-237) is consistent with the reaper's `s.active == a` check. The gate-before-handler ordering, verbatim `-wspublic` precedence, and probe-side use of `wsListenAddr` (not the public URL) in `waitIdentity` are all correct.

**Should-fix**

1. **`DEMOSRV_ADMIN_TOKEN` leaks into every engine child's environment.** `childSpawner` (main.go:203) uses `exec.Command` with inherited env, so the admin secret rides along into `serve`/`replay` — the processes that expose the *unauthenticated* public ws plane ADR-0020 itself flags as the soft spot. Same-UID-only exposure, but stripping it (`cmd.Env = os.Environ()` minus the var, or `os.Unsetenv` after `resolveAdminToken`) is one line and keeps the secret confined to the process that checks it.

**Nits**

2. `adminGate` (deploy.go:234) matches `"Bearer "` case-sensitively with exactly one space; RFC 7235 makes the scheme case-insensitive. Harmless for an operator-controlled client, but a curl-typed `bearer` 401s confusingly.
3. `resolveAdminToken` (deploy.go:202-219) trims the env value but not the flag value — asymmetric; a whitespace-bearing flag token gates on the literal whitespace.
4. `/api/status` (main.go:413-423) publicly reports the engine child's PID on a public instance — pointless disclosure; consider omitting when the gate is on.
5. The `log.Fatalf` on the `Serve` error path (main.go:172) skips the deferred `os.RemoveAll(binDir)` — pre-existing pattern, leak of one temp dir at process death.

**Questions**

6. SIGTERM uses `hs.Close()` (main.go:147), which severs in-flight responses — a viewer mid-download of a hundreds-of-MB chunked net part gets cut on pod reschedule. Pre-existing choice; with a public audience, was `Shutdown` with a short deadline considered? (Fine to leave — K8s will re-serve.)
7. ADR/contract: no NATS subject or payload changes; the new 401 semantics and flags are covered by ADR-0020, and the unauthenticated-ws-plane go-live gate is recorded there rather than hand-waved — good. Confirm the deploy manifests repo actually tracks that precondition, since nothing in this repo will enforce it.

Determinism: no sim-path, RNG, map-iteration, or float-accumulation changes; `runNonce` stays crypto-rand with fail-closed semantics. Tests cover every mutating route class, the default-open path, and the shutdown latch; I could not run them in this sandbox, so the pre-commit gate's own run is the execution check.
