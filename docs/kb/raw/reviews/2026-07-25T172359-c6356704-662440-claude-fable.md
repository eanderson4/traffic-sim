## Findings

**Blockers:** none.

The concurrency design is sound. I specifically checked the interleavings the comments claim are load-bearing, and they hold: `stop()`'s pending-before-epoch ordering vs. `startGuarded`'s epoch-snapshot-before-pending-check (supervisor.go:250-256, 369-370) leaves no window where a start is both unrefused and unabortable, because `stopPending` stays ≥1 until the stop acquires `mu`, which a queued start holds. The double `closed` check (supervisor.go:243, 281) with `shutdownFinal`'s closed-first store order is likewise correct. The reaper/`startIfIdle` corpse-clear interaction (supervisor.go:264-272, 316-319) has no double-clear or deadlock: `done` closes before the reaper takes `mu`, and both clears are guarded by identity/`select`.

**Should-fix**

1. `deploy_test.go:490` (`TestStopAbortsInFlightStart`) — the 300 ms `time.Sleep` is a race against goroutine scheduling. If `stop()` completes before the start goroutine snapshots the epoch, the start proceeds with a stable epoch into a 30 s probe of `127.0.0.1:1` and the test fails at the 5 s select. Unlikely locally, real on a loaded CI. A sync point (e.g. a spawner that signals when the child exists) would make it deterministic. Test-only, so deferrable per the triage bar.

**Nits**

2. `deploy_test.go:1006` — `syscall.Mkfifo` pins the test file to unix. The package already leans unix (children, signals), so this only matters if demosrv ever targets Windows; noting for the record.
3. `main.go:206-209` — the `hs.Serve` error path calls `shutdownFinal()` then `log.Fatalf`, which skips the deferred `os.RemoveAll(binDir)`. Pre-existing behavior (the old `ListenAndServe` fatal had the same leak), unchanged by this diff.

**Questions**

4. `deploy.go:338-396` — autostart retry semantics: if an operator's authed start succeeds during autostart's backoff window and that run then *exits on its own* (engine crash) before autostart's next retry (window ≤ ~14 s real time), the retry sees idle + unchanged epoch and spawns the autostart demo. Only an explicit *stop* is terminal. Probably desirable on a demo pod (self-heal), but it's a case the "never replaces / never un-stops" comments don't cover — worth a line in the ADR if intended.
5. ADR-0020 records the 409-on-stop-pending semantic change and the 401 gate; the HTTP control plane isn't a NATS contract, so no ADR-0006 migration note is needed — confirming that reading matches the diff (no NATS subject or payload touched anywhere in it).

**Contract/determinism:** no NATS subject/payload changes; no engine-core (sampled-path) code touched; all new time/backoff usage is orchestration-side. The ws advertisement change is flag-gated and byte-identical when unset (`TestWsAdvertiseLegacyDefault` pins it). Fail-closed token intake, env stripping to children and the go-build, and the `-wspublic`⇒token coupling all match the ADR text.
