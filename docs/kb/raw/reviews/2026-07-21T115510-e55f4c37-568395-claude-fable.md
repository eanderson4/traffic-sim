## Review

**Blockers:** none. The implementation tracks the M12 addendum closely; hash framing, effective-network validation, fail-loud dispatch, and the strict fence for patched documents are all correct. Determinism discipline holds: no map iteration reaches hashed or sampled output (leftover patch targets are sorted at `variant.go:356`; everything else walks deterministic slices), no wall clock, no RNG, and `sort.Slice` in `Hash()` is deterministic for a given input. No NATS subject or payload changes — ADR-0012's "files, not messages" claim remains true.

**Should-fix**

1. `engine/scenario/variant.go:337-343` — the variant loader assumes base demand refs are unique, but nothing rejects duplicates: `validateManifest` (scenario.go:461) never dedups `m.Demand`, so a base listing `demand/main.yaml` twice loads fine (flows silently doubled — a pre-existing quirk). Under a variant, `delete(patchesByPart, ref)` after the first occurrence means the patch applies to the first copy only; the second loads unpatched, and two `hashPart` entries share one rel with different data — a state no hand-written directory can represent, quietly breaking the "conceptual merged directory" hash frame. Cheapest root fix: reject duplicate part refs in `validateManifest` (also closes the base-side silent doubling).

**Nits**

2. `engine/scenario/scenario.go:359` — `Format`'s dispatch treats any `os.Stat` error as "not a variant" and falls into `readManifest`, unlike `Load`'s explicit fail-loud stat handling three lines of doc away. Reachable only via a race after the `Load` at line 355 succeeds, but the asymmetry contradicts the stated dispatch discipline; mirroring the `fs.ErrNotExist` check is two lines.
3. `engine/scenario/variant.go:385-394` — an added control/metrics ref of `variant.yaml` resolves to the variant manifest itself and hashes its raw bytes, so the `seed:` run coordinate leaks into the content hash, and no hand-written equivalent can exist (both-manifests rule). Obscure authoring error; a one-line `ref == VariantManifest` rejection if you want it closed, "too early" is defensible.
4. Patch semantics allow `set: {id: new-name}` — a patch can silently re-anchor the flow it's anchored by. Revalidation catches collisions, so nothing breaks, but "patches MODIFY only, anchored by durable id" arguably implies the anchor is immutable. Worth either a refusal or one sentence in the addendum saying it's permitted.
5. `engine/scenario/variant.go:344-346` — validation errors on a patched part cite line numbers of the re-encoded in-memory document, which matches no file the author can open. Error-UX only; a `(after patching)` hint in the wrap string would suffice.
