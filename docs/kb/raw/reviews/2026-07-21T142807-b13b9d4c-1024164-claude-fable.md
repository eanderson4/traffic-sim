## Review — M13 metric kernel (metrics.go, metrics_test.go, engine.go doc)

Scope note: sandbox denied `go vet`/`go test`, so this is a read-only review; test claims below are from reading, not execution. Determinism discipline checks out everywhere I traced it: vehicle accumulation runs in `e.Vehicles()` append order, every map that reaches an emission or float-accumulation path is sorted first (`gone` at metrics.go:419-424, trip states in Finalize, `Totals` denied keys, both Drains), no wall clock, no RNG. No NATS subject or payload changes in this diff, so no ADR/migration note is required for this commit.

**Blockers** — none.

**Should-fix**

1. **Multi-boundary traversal in one tick silently drops distance** — metrics.go:683 (`splitTick`) and metrics.go:821 (`arrivalLane`). A vehicle crossing prev → mid → cur in one tick (mid lane shorter than one tick of travel, ~3.3–4.3 m at highway speeds) resolves `arrivalLane` to the defensive `cur` and books only `prev.Length−prevS` plus `v.S` — mid's full length vanishes from VMT and its accumulators. Same family: a vehicle that crosses onto an exit lane and despawns in the same tick (boundaries() reprocesses when the successor has a lower index, engine.go:389-411) books only the pre-crossing segment at metrics.go:432 — the exit lane's portion is dropped. The comments say "no current network produces one," which is true for the built-ins, but `netimport` (OSM) is in-tree and OSM junction connectors routinely sit under 4 m. Since the failure is *silent* undercount, either walk the successor chain or fail/count loudly when `arrivalLane` hits the defensive branch. "Too early" is a defensible triage, but record it — this will bite exactly when the first real corridor is imported.

2. **Denied-entry demand undercounts backlog** — metrics.go:474-486 (wait), metrics.go:527-539 (pending). The spawner holds exactly one pending vehicle per origin (spawn.go: `originState.pend`), with backlog encoded in `st.tick` lag, so wait accrues at most dt per origin per tick and Pending caps at 1 per origin regardless of how many schedule-implied arrivals are overdue. At 3000 veh/h blocked for 60 s, ~50 vehicles were "requested but not yet injected" (ADR-0014 §3's definition) but the kernel books one vehicle's worth of wait. This understates latent demand under exactly the oversaturated comparisons §3 says must not lie. The backlog is derivable from `(tick − st.tick)·st.rate` at kernel level, or count it spawner-side. If the single-pending reading of "requested" is the intended v1 semantics, pin that in the contract prose when the wire schema lands.

**Nits**

3. metrics.go:311 — `Observe` reads `e.Params.Dt` while `closeInterval` uses the constructor-captured `k.dt`. Same value today; pick one source so a future param mutation can't split them.
4. metrics.go:398 — stop-episode starts attribute to the *end-of-tick* lane while distance/time/time-loss on a crossing tick go to the *traveled* lane. ADR-0014 §3 only pins interval attribution for stops, so this is legal, but the asymmetry deserves a one-line comment.
5. metrics.go:250 — "Attach before the first Step" is unenforced; attaching mid-run silently stamps pre-existing vehicles `entryTick: 0`. A cheap `e.Tick == 0` check (or documenting the mid-attach semantics as intended) would make the fence strict like the rest of NewKernel.

**Questions**

6. ADR-0014 §3 places normative definitions in `contracts/asyncapi.yaml`; this commit mints `SchemaVersion: 1` on both record types with no contract pin (the sink, `metricsjson.go`, is untracked and unstaged). Confirm the contract pin lands with the publisher commit, before any consumer binds — otherwise SchemaVersion 1 is defined only by Go comments.

**Strengths worth keeping**: the single-clamp-then-split time-loss discrimination test (TestKernelCrossingTimeLossClamp) targets the exact formula ambiguity ADR-0014 §3 pins; conservation tests (Σ intervals = Σ trips = VMT) close the assign-where-traveled loop; CRC-invariance and Finalize-idempotence tests cover the two easiest regressions to ship.
