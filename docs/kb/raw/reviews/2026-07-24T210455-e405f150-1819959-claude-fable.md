### Should-fix

1. **`engine/cmd/demosrv/supervisor.go:158` (`start` holds `s.mu` across `waitIdentity`, up to 660 s).** `status()` and `stop()` also take `s.mu`, so during a big-city start (la-lean ~400 s registration) `/api/status` hangs — the menu polls it every 3 s, piling requests into the browser's per-host connection limit, and `/api/*/stop` cannot cancel a bad start for up to 11 minutes. Separately, the start POST itself blocks past typical browser response-header timeouts (~300 s in Chromium), so the exact flow this change ships (menu-started city demos) can report a network error while the child actually comes up. Consider a "starting" state that releases the lock during the identity wait, or an atomically-snapshotted status.

2. **`engine/cmd/demosrv/geojson.go:628-651` (`part()` double full-file read).** Each part request runs `netKey` (full `os.ReadFile` + sha256 of the network file) and then `c.path()`, which runs `netKey` again — two ~GB reads/allocations per part request on la-lean, ×4 parts + manifest per page load. After validating schema+hash, stat the part file and return it directly, falling into `c.path()` only when it's missing.

### Nits
