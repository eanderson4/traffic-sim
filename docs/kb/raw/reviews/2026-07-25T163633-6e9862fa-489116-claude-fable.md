## Findings

**Blockers:** none.

The core mechanisms hold up under scrutiny: the closed-latch/epoch ordering in `startGuarded` (store `closed` → bump epoch, check `closed` → snapshot epoch → re-check `closed`, all under `mu`) is sound — I could not construct an interleaving where a start both slips the latch and dodges the abort. The never-cleared monotonic epoch fixes the old stamp/clear race. The gate covers exactly the seven mutating POSTs; with a token set, the required `Authorization` header incidentally also closes the no-preflight CSRF hole. `validateWsPublic`'s raw-`#`, `Hostname()`, userinfo, and port-range checks are all correct (Go's `url.Parse` does accept out-of-range numeric ports, so that check is load-bearing). Fail-closed token intake via `flag.Visit` + `LookupEnv` is right. No NATS subject/payload changes; the HTTP-surface changes have their ADR. No determinism exposure — this is orchestration only, and the wall-clock/backoff use is appropriate here.

**Should-fix**

1. `engine/cmd/demosrv/main.go:178` vs `main.go:204` — `close(srv.shutdown)` can be reached from both the signal handler and the `hs.Serve` error path. If a real accept error (fd exhaustion is the realistic public-pod case) coincides with SIGTERM (kubelet killing the now-unhealthy pod — the same incident produces both), one path panics on double close. `sup.shutdownFinal()` is idempotent so the child still dies, but the panic can preempt the `log.Fatalf` that names the actual error. A `sync.Once` around the close (or letting only the signal handler own it) fixes it.

**Nit**

2. `engine/cmd/demosrv/deploy_test.go` (lowercase-scheme check in `TestAdminTokenGate`, ~line 632 of the patch): `if resp, err := http.DefaultClient.Do(req); err != nil || resp.StatusCode != 200 { t.Errorf(..., resp.StatusCode, err) }` — when `err != nil`, `resp` is nil and the `Errorf` args nil-panic. Only bites on a failing test, but it turns a diagnostic into a crash.

**Question**

3. `engine/cmd/demosrv/deploy.go:331-385` (`autostartDemo`) — the "never un-stop what the operator stopped" rule is enforced only for a stop landing *mid-start* (`errStartAborted`). A stop that lands *between* attempts (during the backoff sleep) isn't detected: the next retry snapshots the fresh epoch and starts the demo anyway. The window is ≤ ~14 s after pod boot and only while autostart is still failing, so plausibly "too early to need this" — but if you want it, snapshotting `stopEpoch` before the backoff and treating a bump as terminal would close it symmetrically.

The ADR's honest treatment of the unauthenticated engine ws plane as a go-live precondition (not a property of this commit) is the right call, and the startup warning at `main.go:165` keeps it from being silently forgotten.
