# Review — TSSG chunking (ADR-0016), chunked GeoJSON (ADR-0018), spawn identity, themes

Read the full patch plus surrounding context (`geojson.go` locking, `serve` flags, `main.ts` layer ids, `netfile.go` Junction/Row). Contract discipline is in order: the new subject (`ts.{run}.state.sig.req`), the `sig_chunk` header, the MaxPayload amendment, and the manifest contract are all ADR-covered (0016/0018), and the exporter property additions are handled by the `v2` cache schema bump. Determinism: chunk packing is a pure function of file order, no map iteration in sampled paths, the only wall-clock use (`runNonce`) is run identity, not sim state. No blockers.

## Should-fix

1. **`engine/cmd/demosrv/supervisor.go:146` — `start` now holds `s.mu` for up to 660 s, freezing the whole API.** `waitIdentity` runs under the mutex; `status()` (main.go:326) and `stop()` also take `s.mu`. During an la-lean start (~400 s world build), every `/api/status` poll (menu polls every 3 s) and any stop request blocks until identity resolves — the menu reads as dead, and a doomed start cannot be cancelled. Pre-existing shape, but the bound grew 10 s → 660 s, which changes its character. Snapshot status fields outside the lock, or run the identity phase outside `mu` with a generation guard.

2. **`engine/cmd/demosrv/main.go:123` vs `main.go:157` — `/api/demos` `ws` and start-URL `ws` disagree; wildcard listen yields an undialable deep link.** `reg.WS = wsClientURL()` is the verbatim listen address, so `-ws 0.0.0.0:8443` puts `ws://0.0.0.0:8443` into the menu's running-card deep link (`deepLinkURL` → `buildAppURL`), while `handleStart` correctly substitutes the request host via `advertisedWsURL(r)`. `handleDemos` has `r` — serve the advertised URL there too (the `wsClientURL` comment's rationale defends verbatim against loopback-normalizing, but verbatim `0.0.0.0` is dialable by no one either).

3. **`engine/cmd/demosrv/identity_test.go:22-23` — direct `nats.go`/`nats-server` imports outside `engine/natsio`.** The ADR-0006 exception confines both NATS modules to `engine/natsio/`; this test file imports them into `cmd/demosrv` (test scope, but the convention carves out no test exception, and the existing demosrv tests deliberately stub the engine). A ws-enabled `TestServer` helper plus a `PutRunMeta` test helper in `natsio` would keep the boundary clean. If test files are meant to be exempt, say so in the convention.

## Nits

4. `viz/src/main.ts:640` (requestSig) — pull budget (3) resets only when a generation *completes*. A **paused replay** publishes no broadcast table (that was this change's point), so a client whose 3 pulls all gapped/timed out sits signal-less until resume. Accepted trade-off per the sol-review note; flagging that pause is the one state with no fallback cadence.
5. `engine/cmd/demosrv/main.go:253` — server-built start URLs embed `ws=ws://…` unescaped while `demos-core.ts` uses `encodeURIComponent`; both parse via `URLSearchParams`, but the two "must agree" URL builders now differ byte-wise.
6. `engine/cmd/demosrv/main.go:135` (`advertisedWsURL`) — an IPv6 request host emerges unbracketed (`ws://::1:8443`). Local-first makes this theoretical.
7. `engine/cmd/demosrv/supervisor.go:305` — `waitIdentity` dials a fresh ws connection every second (~660 connects worst case); a single held connection would do.
8. Per-spawn unique run ids leave one `{run}-{nonce}/meta` KV entry per spawn forever (Finish rewrites, never deletes) — harmless dev-store growth, worth a line in ADR-0018's identity section.
9. `viz/src/tssg.ts:31` — `SIG_CHUNK_HEADER` is exported but `main.ts`/`nats-client.ts` use the `"sig_chunk"` literal.
10. `demos.html` palette literals duplicate `theme.ts` values (acknowledged in comments; the theme test only pins the TS side).
