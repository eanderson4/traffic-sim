## Findings

**Blocker**

1. **metrics.go:419-421 — nil-pointer panic on despawn of a pre-seeded, never-observed vehicle.** `NewKernel` seeds `k.last` for vehicles already in the network but creates no `tripState` (deliberate, per the comment at metrics.go:244). A trip state is only created in `Observe` for vehicles still present. If a pre-seeded vehicle despawns during the first Step (within one tick's travel, ~3.3 m, of an exit-lane end — e.g. `AddInitialVehicle(exitLane, 0, 499.9, 33.3, 1)`), the first Observe finds it in `gone` and, with `Trips` on, does `ts := k.tstates[id]; ts.dist += d` on a nil `ts` → panic. One-line guard (skip trip emission when `ts == nil`) fixes it. No test covers this path.

**Should-fix**

2. **metrics.go:763-770 — `isCrossingPlusHop` infers lateral adjacency from `cur.Section == succ.Section && cur.Index == succ.Index±1`, but `Lane.Index` is the global position in `Network.Lanes`** (network.go:12; netfile.go:160 assigns it in file order), not an intra-edge slot. Lateral adjacency is the `Left`/`Right` pointers, wired per edge (netfile.go:319). The proxy holds on the in-code nets (lanedrop's B0/B1 are index 3/4) but not necessarily on file-loaded networks, where same-section lanes need not be index-consecutive. A missed crossing+hop falls into the lateral-hop branch, where `d = v.S − prev.s` goes negative and clamps to 0 — that tick's distance is silently dropped (undercounts VMT/trip distance consistently, so the conservation test won't catch it). Robust check is `succ.Left == cur || succ.Right == cur`; same cost, no proxy.

**Nit**

3. **metrics.go:321, 338, 651 — `d/v.v0eff(lane)` with `v0eff == 0` and `d == 0` yields NaN**, and `addTimeLoss`'s `tl <= 0` guard is false for NaN, so it would poison `sumTimeLoss`/`k.timeLoss` permanently. Currently unreachable (F is clamped positive at injection, speed limits positive), so nit — but a `!(tl > 0)` guard is free and NaN-proof.

4. **metrics.go:458 — `Finalize` is not idempotent**: a second call re-counts `deniedPending` (the maps aren't reset). Documented "call once"; fine for now.

5. **metrics.go:170 — `Totals.DeniedByLane` hands out a bare map**; the kernel builds it from sorted IDs, but any future sink iterating it unsorted reintroduces nondeterministic emission order. Worth a one-line comment obligating the consumer to sort (the interval/trip paths already pre-sort in the drains).

**Question**

6. **metrics.go:441-444 / director.go:134 — expired director directives and denied accounting.** A directive dropped after `DirectorSpawnHoldTicks` keeps its accrued `DeniedWaitS` in totals but never appears in `DeniedPending` — so wait can be nonzero for an origin whose pending count is forever 0, and dropped demand is invisible at the horizon. Is "expired = superseded demand, not denied" the intended §3 reading? If so, a sentence in the ADR (or the kernel comment) would pin it; a dropped-count field would be the alternative.

Determinism discipline checks out otherwise: accumulation runs over `e.Vehicles()` (append order), despawn IDs are sorted before folding, spawner origins and `dirQueue` are slices in fixed order, and every map (accumulators, denied, trip states) is sorted before emission. No wall clock, no RNG, no feedback into engine state; the CRC-invariance and two-run-equality tests directly enforce ADR-0005/ADR-0014 §1. Interval bookkeeping (open/close, EndTick truncation, horizon partials) is internally consistent with the documented (BeginTick, EndTick] window; I traced boundary cases (EndTick on/off a period boundary, horizon = k·P, zero-step Finalize) and found no off-by-ones.
