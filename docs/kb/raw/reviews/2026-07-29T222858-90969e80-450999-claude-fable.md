Reviewed the full patch plus the surrounding code (`recorder.go` publish/OCC path, `logcursor.go`, `intent.go` apply path, `run.go` loop, `checkFreshRecording` in serve). The core design is sound: `applyIntents` stamps every applied intent with `e.Tick` and `LogTick` runs before the next `Step`, so the batch path's mixed-tick abort is a true invariant check; the shared codec (`appendLoggedIntent`/`decodeLoggedIntentAt`) makes the byte-identity claim testable and the tests do test it; no map iteration, wall clock, or float accumulation enters any recorded path; contract discipline (new subject + ADR-0035 + ADR-0006 addendum + asyncapi bump) is followed.

## Findings

**Blockers** — none.

**Should-fix**

1. `engine/natsio/logcursor.go:37` — `cursorBatch = 2048` was sized for ~230-byte per-intent messages ("small enough that the buffer stays incidental"). With TSLB, one message is up to `IntentBatchMax` (768 KiB), and a chi-scale tick is ~350 KB in one message, so a full fetch now buffers ~2048 ticks ≈ hundreds of MB (worst case ~1.5 GiB) in `c.buf` — three orders of magnitude over the buffer this ADR-0024 reader was built to bound. Not a correctness bug, but it quietly erodes the bounded-memory property on exactly the recordings this change targets. Bound the fetch by bytes (`PullMaxBytes`/smaller batch when the stream carries `log.intents`), or shrink `cursorBatch`.

2. `engine/natsio/recorder.go:150-158` — the `AddStream` → `UpdateStream` fallback converges **any** config drift, not just the compression field: an existing stream with different subjects, MaxAge, or retention gets silently rewritten instead of failing loud, and the "has to be empty to get this far" claim in the comment holds only because `checkFreshRecording` runs first — and only on serve's `-store` path (`engine/cmd/serve/main.go:398`); `RunLive` is a public API with no such guard. Cheap containment: `StreamInfo` before `UpdateStream` and refuse if `State.Msgs > 0`, which makes the adoption invariant local instead of trusting a caller two layers up. Defensible to defer under the triage bar (in-repo callers are all guarded today), but record it.

**Nits**

3. `contracts/asyncapi.yaml:49,81` — `compression: s2` is declared unconditionally on both channels' `x-nats`, but it's flag-dependent (`-store-compress=false`), and the two flags are independent — an uncompressed-batched or compressed-unbatched stream is legal. The contract reads as if s2 is invariant. A "default; see -store-compress" word would fix it.
4. `engine/natsio/recorder.go:363-367` — `loggedIntentMax` budgets 256 bytes for the controller id but nothing enforces that at encode time (`uint16(len(ctl))` accepts up to 64 KiB). Consequence is only budget overshoot, comfortably inside the 1 MiB broker cap at the 768 KiB default, but the constant's guarantee ("a record never fails to fit") is an assumption, not an invariant. Pre-existing shape; noting because the new flush logic is what now relies on it.
5. `docs/kb/INDEX.md:147-148` — the ADR-0035 footnote is inserted above the ADR-0034 one, breaking the numeric order of that list.

**Questions**
