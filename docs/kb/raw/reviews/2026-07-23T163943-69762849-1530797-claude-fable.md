The core is sound: no map-iteration in the re-sim path (per-tick slices stay in stream order; maps are only keyed lookups), wall clock confined to the pacing wrapper per ADR-0005 §4, no RNG, CRC verified against the record, and the `indexLogMsgs` extraction is a faithful move of the old inline loop (test confirms final CRC == live CRC). No blockers. Findings:

**Should-fix**

1. `player.go:162-165` — **`keyframeEvery` can be 0 → modulo panic.** `kfEvery = idx.keyframes[1] - idx.keyframes[0]` trusts the record. `Registry.Start` (`registry.go:73`) overwrites meta and `Recorder`'s `AddStream` is idempotent, so re-recording a run id into the same store appends a second tick-0 keyframe; if the first recording was shorter than its keyframe cadence, `keyframes = [0, 0, …]` → `kfEvery = 0` → `p.e.Tick % p.keyframeEvery` (`player.go:244`, also `player.go:308` in `seek`) panics on the first tick. One dirty store takes the demo down. Guard: error out (or fall back to 100) when the delta is 0 — a dirty store deserves fail-loud at `NewPlayer`, not a runtime panic.

2. **HTTP control plane needs an ADR note (ADR-0002 conflict) and so does the `{run}-replay` convention.** ADR-0002 says all inter-service communication flows over NATS, no direct RPC; ADR-0008 already defines pause/resume as NATS contract events. `Player.Handler()` (`player.go:344+`) introduces an HTTP pause/resume/speed/seek plane for the demo UI — a service-boundary decision per AGENTS.md rule 3. Likewise the `-replay` run-id suffix is now a de-facto reserved namespace: subjects `ts.{run}-replay.state.*` carry the existing frame schemas (good — no payload change), but replay runs are registry-less, contract-less runs that consumers must understand. Neither needs code changes; both need an ADR-0006 §8 amendment or a short ADR, in this commit or a docs follow-up, per "raise the conflict instead of silently diverging."

**Nit**

3. `player.go:268-272` — a rejected verb increments `crcErrs`, so `/status` reports it as `crcErrors`. Different failure class (record/spec disagreement at enqueue vs state divergence); separate counter or rename to `divergences`.
4. `player.go:222-229` — after the end-of-recording hold, `POST /resume` flips `paused=false` but the loop stays in the hold branch: `/status` then claims playing while nothing publishes. Consider rejecting resume while `done`, or reporting a distinct `done` field.
5. `player.go:323` — `Status.Ticks` reports `spec.Ticks` even when the recording is truncated (`endTick < spec.Ticks`); a UI seek bar built on it overshoots into the clamp. Report `endTick` (or both).
6. `player.go:275-278` — after one real divergence the rolling CRC never re-converges; with `CRCEvery=1` this logs every remaining tick. Rate-limit or log-first-N.
7. `main.go:114-117` — `fmt.Sprintf("ws://%s:%d", host, port)` produces a malformed URL for IPv6 literals (`ws://::1:8443`); use `net.JoinHostPort`.
8. `player.go:113-115` — the `validToken(replayRun)` check is unreachable: a valid run token plus `-replay` is always a valid token. Harmless; delete or drop the comment implying it can fire.

**Question**

9. A recorded run named `foo-replay` collides with the replay plane of `foo` (same subjects on the same broker). Worth refusing source run ids ending in `-replay` in `NewPlayer`? One line, closes the namespace.
10. While paused (including the end hold), snapshot/sig republication stops entirely — a browser attaching mid-pause renders nothing until seek/resume. Same gap exists in the live loop's pause gate, so maybe accepted; flagging since the player's whole purpose is an audience.
