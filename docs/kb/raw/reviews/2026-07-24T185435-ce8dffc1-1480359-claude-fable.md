## Findings

**should-fix**

1. `engine/cmd/demosrv/supervisor.go:141-167` — `start` now holds `s.mu` through `waitIdentity`, i.e. up to `identityTimeout` (660 s) and realistically 100–400 s on the big nets this change targets. `status()` (supervisor.go:212), `stop()` (supervisor.go:188), and `withActiveReplay` all block on the same mutex, so during a city-scale start the demos menu's 3-second `/api/status` poll piles up and `/api/stop` cannot cancel a slow or wedged start until the timeout expires. Before this change the lock was held ≤ ~10 s. Relatedly, the `/api/demo/{id}/start` POST now takes 400+ s to answer for la-lean; Chromium kills header-less requests around the 5-minute mark, so the menu can report a failed start while the engine actually comes up. Consider returning from `start` after spawn + port probe and letting the identity phase gate a "ready" status outside the lock, or at minimum making `stop` preempt `waitIdentity`.

2. `engine/cmd/demosrv/geojson.go:239` (`part()`) — the `wantSchema`/`wantHash` staleness checks run only *after* `c.path(id, scenarioDir)`. A part request from a stale manifest (old hash) on a cold cache triggers a full chunk-set generation — the documented ~1 GB buffer and minutes of CPU on la-lean, under `c.mu`, blocking every other `/net/` request — and then 404s anyway. Both checks need only `scenario.Load` (cheap); hoist them above the `c.path` call.

3. `viz/src/main.ts` (`requestSig`, near diff line 3259) — `sigReqRetries` resets only when a *pull* delivers a complete table. After three failed pulls the request/reply path is disabled for the rest of the tab's life; a later slow-consumer gap — the exact busy-tab incident ADR-0016 exists for — can then only recover by happening to catch a complete broadcast round, which is what the pull path was added because busy tabs don't do. Reset the counter in `installSigTable` (any complete table, broadcast or pull) instead of only inside the pull callback.

**nit**

4. `engine/cmd/demosrv/main.go:329` vs `viz/src/demos-core.ts:63` — the Go start-response URL embeds `ws` unescaped (`&ws=ws://127.0.0.1:8443`) while `buildAppURL` uses `encodeURIComponent`. Both parse identically, but the "same shape … they must agree" comment is now only true post-decoding.

5. `viz/demos.html` (inline theme script) — duplicates both palettes as literals; `theme.test.ts` pins only `theme.ts`, so the menu page can silently drift from the app palettes.

6. `engine/cmd/demosrv/geojson.go` `geoJSONFrameOf` — hand-mirrors the exporter's frame construction; a future `GeoJSONFrame` field would diverge manifest vs parts with no test tripping.

7. `engine/cmd/demosrv/supervisor.go` `waitIdentity` — the post-probe `done` check reports "run %q belongs to a foreign process", but the same path fires when *our* child crashes right after registering; the message will mislead that debugging session.

**question**

8. `docs/kb/decisions/ADR-0016-tssg-chunking.md:17,83` — the ADR narrates "MaxPayload 64 MB → 4 MB", but against HEAD the staged diff *adds* `MaxPayload: 4 << 20` where nothing was set (NATS default 1 MiB); the 64 MB interim apparently never landed in a commit.
