The mechanism itself (stamp = `(base HEAD, index tree)` captured pre-review, byte-exact drift check, fail-closed marker validation) is sound. Findings:

**Should-fix**

1. `docs/kb/decisions/ADR-0013-external-review-gate.md:162` — "Partial commits (`git commit -- <paths>`, `-p`, `-a`) **always fail** the gate" is false. Those commits run the hook with a temporary `GIT_INDEX_FILE`; `git write-tree` (hooks/pre-commit:236) hashes *that* index, so e.g. `git commit -a` with a fully-staged working tree produces the stamped tree and passes — correctly (reviewed content ships). The hook's own message (hooks/pre-commit:257–259) states the true semantics. Fix the ADR wording; the behavior is fine.

2. hooks/pre-commit:227 / ADR-0013 §1 — `tools/` is a standing ungated prefix, but the ADR's stated rationale for the inverted listing is "future tooling directories cannot slip past by omission." `tools/` currently has zero tracked files (only an untracked venv), so today it exempts nothing — but any future hand-written script dropped there ships unreviewed, contradicting the design's own claim. Gate `tools/` now (cost is zero) or narrow the exemption to the generated artifact paths.

3. scripts/external-review.sh:358–366 — reviewer isolation is asymmetric: Fable gets a tool allowlist, Sol gets `--sandbox read-only`, Gemini runs bare `gemini -p` with no sandbox. The ADR accepts prompt-injection-in-diff, and the drift check (line 395) covers only the *index* — a reviewer writing to the working tree or elsewhere is undetected. Add Gemini's sandbox flag if available, or record the asymmetry in ADR-0013 §4.

**Nit**

4. hooks/pre-commit:256–257 — "so review must precede staging" is inverted: staging must precede review (the script errors on an empty index at scripts/external-review.sh:308). The intended rule is "anything staged *after* review fails the gate."

5. hooks/pre-commit:237 / scripts/external-review.sh:327 — unborn HEAD (fresh repo, no commits) breaks both: the hook demands a stamp no script run can produce (`set -eu` dies at `git rev-parse HEAD`), leaving only the skip hatch. Irrelevant to this repo; worth a one-line comment so a future extraction of this tooling isn't surprised.

6. scripts/external-review.sh:312–315 — the hooksPath check misses equivalent spellings (trailing slash, `~`-relative, symlinked root), producing a false warning. Cosmetic.

**Question**

7. hooks/pre-commit:227 — `.kimi-code/**` is gated, so editing SKILL.md prose (this diff does exactly that) costs two model reviews per commit. Skills steer agent behavior, so gating is defensible — but is doc-only skill editing intentionally in scope? If not, exempting `*.md` under `.kimi-code/skills/` is easy.

8. hooks/pre-commit:239 — the stamp is never deleted after a successful commit. Harmless (it binds base+tree, so it can't be replayed onto different content), but confirm leaving it stale is intentional rather than adding a post-commit cleanup.
