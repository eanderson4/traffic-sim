## Review — staged diff (TSSG chunking / chunked GeoJSON / spawn identity / themes)

### Blocker

1. **`contracts/asyncapi.yaml:156-176` — the `sigReplyInbox` channel insertion is structurally botched.** The new channel block was inserted *between* `stateSigReq`'s `address`/`x-permissions` and its original body, so `stateSigReq`'s old `description`, `parameters`, and `messages` now sit under `sigReplyInbox`. Result: (a) duplicate `description` mapping key at line 163 — invalid YAML per spec (verified with a strict parser; `yaml.v3` and AsyncAPI tooling reject duplicate keys); (b) `stateSigReq` has no description/messages while the new `receiveSignalTableRequest` operation points at that channel; (c) `sigReplyInbox` (`_INBOX.>`) carries a `run` parameter its address doesn't use, plus the request message that belongs to `stateSigReq`. Message contracts are sacred (ADR-0006) and this is the contract file itself. Fix: move the stranded block back under `stateSigReq`; leave `sigReplyInbox` with only its own description and the `SignalTable` reply message.

### Should-fix

2. **`engine/cmd/demosrv/supervisor.go:245-251` — `stop()`'s generation stamp can miss the start it's meant to abort.** `start()` increments `startGen` *before* taking `mu` (line 172). If start B is queued behind start A's in-flight 660 s identity wait, `stop()` reads `startGen = B's gen` and aborts B (which isn't probing yet), while A — the one actually holding `mu` — never sees its gen in `abortGen` and runs the full timeout. That silently reinstates exactly the SIGINT hang this mechanism exists to fix (worst case = old behavior, and B is unharmed since `abortGen` is cleared under `mu`, so no corruption — but the abort no-ops). Stamp the gen of the *in-flight* start instead (e.g. an atomic `currentGen` set inside `start` after `mu.Lock()`, or store gen on `activeRun`).

### Nits

3. `engine/cmd/demosrv/geojson.go:239` — an out-of-range part index for a *valid* generation returns a non-`errStalePart` error, which `handleNet` maps to 500. It's an absent resource; 404 fits, and the viz only treats 404 as retryable. Only reachable via hand-crafted URLs today (hash+schema pin the part count), hence nit.
4. `engine/cmd/demosrv/identity_test.go:149` — comment says "the 120 s identity timeout"; the const is 660 s.
5. `engine/cmd/demosrv/geojson.go` `isManifest` — sniffing the first 4 KiB for `"parts"` can false-positive on a single-file network whose early lane/edge ids contain the literal `parts` (consequence is only a spurious `no-store`; harmless).
6. `engine/cmd/demosrv/geojson.go` `part()` + `path()` each do a full network read + sha256 per part request (2 full reads per part; ~8 reads of a multi-hundred-MB file per la-lean page load). Page cache makes it tolerable; noting for the ADR-0016 §8-style "known walls" list.

### Questions

7. `contracts/asyncapi.yaml` operations — `receiveSignalTableRequest`/`sendSignalTableReply` reference `#/components/messages/...` directly; AsyncAPI 3.0 expects operation messages to ref the *channel's* messages (`#/channels/<ch>/messages/<name>`). If nothing validates this file today it's cosmetic, but since finding 1 forces you back into this block anyway, worth aligning.
8. `engine/cmd/demosrv/supervisor.go` `mirrorStatus` at spawn time — `/api/status` now reports a demo as active for the whole (up to 660 s) identity phase, so other tabs' running-cards deep-link into a run that isn't streaming yet (the 20 s watchdog message covers it). Intentional trade for the lock-free status? Fine if yes.

### Verified clean

Determinism: chunk packing (`signalChunksMax`), program bodies, GeoJSON range export, and stop-sign clustering are pure functions of file-ordered inputs — no map iteration, no wall clock, no RNG in sampled paths; `runNonce` is ops-side (demosrv), not sim-side. Tick patch offset (byte 8) matches the TSSG layout and is copy-on-write against the shared cache. `sig_chunk` absent = whole-table back-compat holds on both sides; malformed headers throw rather than reading as whole-table. Reply confinement to `_INBOX.` and empty-payload validation close the amplification hole the new observer-publish permission opens. Chunked-GeoJSON generation is parts-first/manifest-last with atomic renames; hash+schema pinning 404s cross-generation mixes and the client refetches once. `netCache.path` still takes `mu` with double-stat. ADR-0016 is ratified and ADR-0018 added — the contract changes have their ADR trail (modulo finding 1's file damage).
