## Review — TSSG chunking (ADR-0016), chunked GeoJSON (ADR-0018), spawn identity, themes

Verified against the staged patch: sig-frame tick offset (byte 8) matches `withSigTick`; the chunk pack is a pure function of file order (no map iteration, no float accumulation in sampled paths); `stateSigReq` channel is defined in `contracts/asyncapi.yaml:152` with the version bump and ADR — contract discipline satisfied; cmd/* importing the NATS modules in `identity_test.go` has precedent (serve, replay). `NewBus`'s error path unsubscribing the sig.req responder, the dedicated reply accumulator, and the corpse recheck after a passing probe are all correct.

### Blockers

None found.

### Should-fix

1. **`engine/cmd/demosrv/supervisor.go:162` — `start` now holds `s.mu` for up to 660 s.** `waitIdentity` runs inside the lock, and `status()` (line 251), `stop()` (line 225), and `withActiveReplay` (line 284) all take the same mutex. During an la-lean start (~400 s world build), every `/api/status` poll (the menu fires one every 3 s) and every stop/start request blocks until the identity phase resolves — the browser's per-host connection cap then stalls the tab, and a user cannot cancel a wedged start. When the bound was 10 s this was tolerable; at 660 s it isn't. Consider running the readiness wait outside the lock (hold a "starting" generation token; re-take the lock to commit/abort), or at minimum letting `status()` read without blocking on an in-flight start.

2. **`engine/cmd/demosrv/main.go:432` (`isManifest`, geojson.go:89) — substring sniff can misclassify a single-file document.** `bytes.Contains(head4KiB, "parts")` matches any lane id / property value containing `parts` in the first 4 KiB (OSM-derived edge names are arbitrary strings). A false positive stamps `Cache-Control: no-store` on a ~190 MB single-file network — full re-download every page load, silently. Manifests are tiny and generated by you: gate on file size (manifest ≪ 1 MiB) or actually JSON-decode the head key set.

### Nits

3. **`engine/cmd/demosrv/geojson.go:82-88`** — `path`'s doc comment is spliced directly above `isManifest`; `func (c *netCache) path` now has no doc comment and godoc attaches the wrong paragraph.

4. **`engine/cmd/demosrv/geojson.go:105` (`netKey`)** — every `/net/{id}` request and every part request re-reads and re-SHA256s the whole network file; an la-lean page load is ~5 full reads of a multi-hundred-MB file. Fine for a dev cache today; a `(path, mtime, size)` memo is a one-liner if it ever shows up in profiles.

5. **`viz/src/nats-client.ts:98`** — `break` out of the `requestMany` iterator leaves the Timer-strategy request running until `maxWait`; call the iterator's `return()`/stop explicitly (or rely on GC — harmless, just a lingering inbox subscription for up to 10 s).

6. **`viz/src/main.ts:925` (handleSigMessage catch)** — a single malformed `sig_chunk` header sets the HUD to "disconnected" though the connection is fine. Pre-existing pattern extended to a new failure class; a distinct "bad frame" surface would lie less.

### Questions

7. **Broadcast cost at city scale**: keeping the 20-tick cadence means la-lean's full chunk set (~7.3 MB) ships every 2 s per subscriber (~3.6 MB/s sustained). The ADR consciously chose this (drops now cost one chunk, encode is cached), but was the steady-state wire cost measured with a busy tab attached? If not, worth one observation before recordings/demos durably depend on it.

8. **`engine/natsio/probe.go:56`** — the 5 s clock-skew tolerance plus same-second run-id reuse false-pass is documented and caught by the child-death recheck; agreed the per-spawn nonce in `meta` is correctly deferred (ADR-0006 payload change). Just confirming that deferral is intentional, since the nonce-suffixed run id already makes the collision essentially unreachable.

Everything else checked out: chunk-pack boundary math (oversized program rides alone, empty table explicit), accumulator generation rules (order-based, complete-swap, straggler = regression) with the interleaved-round limitation honestly documented in ADR-0016, part-URL parsing (non-numeric/out-of-range → 404), atomic parts-before-manifest write ordering, the byte-identical small-net path pinned by tests, and the navy-theme zero-visual-change pin.
