## Review — ADR-0020 demosrv public deployment (staged diff)

Verified statically against the working tree (patch is applied there); sandbox blocked `go test`, so run the suite before commit if it hasn't been. No blockers found. The shutdown-race design (closed latch stored before the abort stamp, re-checked under mu after gen allocation, `startGuarded`) checks out under interleaving analysis, including concurrent `stop()` + `shutdownFinal()` (both stamp the same generation; the clear-to-0 can only happen after the in-flight start released mu, so the abort is always observed).

**Should-fix**

- `engine/cmd/demosrv/main.go:1076` (patch line; the go-build pre-warm) — `exec.Command("go", "build", ...)` inherits the full environment, including `DEMOSRV_ADMIN_TOKEN`. The stripEnv rationale ("demosrv's own credential must not ride into children") is applied to engine children but not to this child, and `go build` can invoke module/toolchain subprocesses. One line (`build.Env = stripEnv(os.Environ(), adminTokenEnv)`) closes the inconsistency. Low severity in practice — the public deploy uses `-nobuild` — but the env+build combination is legal and the ADR doesn't record it as accepted.

**Question**

- `deploy.go:299` / ADR-0020 — an unknown `-autostart` id logs and keeps serving. The registry is already loaded before the listener binds, so a typo'd id is a *static* misconfiguration detectable at startup — exactly the class `-wspublic`, `-admintoken`, and `-nobuild` all fatal on ("a pod that looks healthy but can't do its job"). The ADR documents keep-serving deliberately, so this is a consistency question, not a bug: was fail-fast-on-unknown-id considered and rejected, or lumped in with the (correctly non-fatal) transient-start-failure case?

**Nits**

- `deploy.go:264` — `CutPrefix(..., "Bearer ")` is case-sensitive; RFC 9110 auth schemes are case-insensitive (`bearer x` gets 401). Fine for operator-controlled clients; noting for the token-aware menu follow-up.
- `deploy_test.go:475-509` — `TestResolveAdminToken` hand-rolls save/Setenv/restore; `t.Setenv` does this and additionally guards against a future `t.Parallel` being added to the package (env mutation is currently safe only because nothing is parallel).
- `deploy_test.go:840` — `syscall.Mkfifo` pins the test to Unix; fine for this repo, but a `//go:build` note would save a future Windows-CI surprise.

**Checked and clean**

- Determinism: nothing here touches the sim/engine kernel; wall clock and backoff live in orchestration only. No map iteration feeding sampled output; `flag.Visit` order is irrelevant (boolean latch).
- Contract: no NATS subject/payload changes. The demosrv HTTP surface change (401 on gated POSTs) has its ADR; the unauthenticated engine ws plane is correctly flagged as a go-live gate, not silently shipped.
- The mux-level gate covers exactly the seven mutating POSTs; all GETs verified public. Autostart bypasses the gate by construction (direct supervisor call), and `startIfIdle`'s idle check + corpse-clear (`done`-closed but unreaped) are correct under mu.
- Reaper now clears `s.active` (not just the mirror); `stopLocked`/`withActiveReplay`/`mirrorStatus` all tolerate the nil.
- `-wspublic` validation (absolute ws/wss, hostname required, raw-`#` and userinfo rejected) is sound — including the trailing-`#`-parses-to-empty-fragment case; `url.Parse` rejects malformed ports.
- Fail-closed token intake (flag.Visit presence + LookupEnv) is correct in all eight flag/env combinations; tests cover them.
- Bind-before-autostart ordering, `hs.Serve` error path killing the child before `log.Fatalf`, and the double-close-on-second-signal concern (single reader, buffered chan — no double close) are all fine.
