## Should-fix

1. **`supervisor.start` holds `s.mu` through the identity phase — up to 660 s + 60 s — blocking every other endpoint** (`engine/cmd/demosrv/supervisor.go:153`, `:238`, `:212`). `waitIdentity` runs under the lock, and la-lean's *happy path* is ~400 s there. During that window `/api/status` (menu polls every 3 s — pending fetches pile up to the browser's per-host connection cap and the whole menu stalls), `/api/demo/stop`, and the replay proxy (`withActiveReplay`, `:271`) all block, and a wedged start cannot be cancelled. Before this change the lock hold was bounded at ~10 s. Snapshot the active run outside the lock (or move the wait phases out of the critical section with a "starting" state) so status/stop stay responsive.

2. **`Cache-Control: no-store` applies to every `/net/{id}.geojson`, not just manifests** (`engine/cmd/demosrv/main.go:415`). The header is set before the manifest-vs-single-file distinction is knowable, so a large *unchunked* net (sf-lean, 188 MB — under the 256 MiB threshold) loses `http.ServeFile`'s Last-Modified/304 revalidation and is fully re-downloaded on every page load. The staleness argument only applies to manifests; scope the header to them (e.g. have `netCache.path` report whether it returned a manifest).

3. **`/api/demos` `ws` is the verbatim listen address while start URLs are request-host-aware** (`engine/cmd/demosrv/main.go` `reg.WS = wsClientURL()` vs `advertisedWsURL`; `registry.go` WS field). With `-ws 0.0.0.0:8443` the menu's running-card deep link carries `ws=ws://0.0.0.0:8443` (non-dialable in several browsers) while the start-POST URL for the same engine correctly substitutes the request host; with the default loopback listen, a remote browser gets `ws://127.0.0.1:8443` pointed at itself, where the old no-param behavior (`ws://${location.hostname}:8443`) at least targeted the right box. Compute the `/api/demos` value per request via `advertisedWsURL`, same as the start handlers.
