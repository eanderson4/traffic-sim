The change is correct for its stated purpose: with the old `L["id"] in ids` filter, a second `--add-lane` of the same corridor would re-select the original outermost labelled lane as donor (the label map never learns clone ids) and mint a second lane with the identical `X_w1` id — a duplicate-id network. Grouping by edge makes the first pass's clone (higher `edgeIndex`, same `edge`) the next donor, and the id chains to `X_w1_w1`. Wiring also composes: pass-1 upstream lanes gained `X_w1` as a successor, so pass 2's feeder scan correctly wires them into `X_w1_w1`. The set `edges` is used for membership only and `by_edge` is iterated via `sorted(...)`, so no iteration-order nondeterminism is introduced.
