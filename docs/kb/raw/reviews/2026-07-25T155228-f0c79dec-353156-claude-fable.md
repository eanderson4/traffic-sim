## Blocker

**B1. `-admintoken=` (explicitly supplied, empty) silently deploys the gate OPEN — contradicting the ADR, the flag help, and the feature's own motivating scenario.**
`deploy.go:217` (`resolveAdminToken`), `main.go:61`, ADR-0020 lines 106–111.

`resolveAdminToken` treats `flagVal == ""` as "flag not supplied" and falls through to the env; with the env also unset, startup succeeds with the mutating routes open. But `flag.String` cannot distinguish `-admintoken=` / `-admintoken "$TOK"` (with `$TOK` expanding empty under a shell-wrapped manifest) from the flag being absent — and that `$TOK`-expands-empty manifest is the exact scenario the fail-closed design cites (deploy_test.go:873, though the test uses `"  "` because `""` is uncatchable by the current code). The whitespace-only guard catches `"  "` but not the far more likely `""`. Three claims shipped in this commit are therefore false: the flag help ("a supplied-but-empty token fatals (fail closed)"), ADR-0020 ("ANY explicitly supplied token that trims to empty — flag or env … fails startup CLOSED"), and the resolveAdminToken doc comment.

Fix is small: after `flag.Parse()`, use `flag.Visit` to record whether `admintoken` was explicitly set, and fail closed on set-but-empty. Alternatively (valid triage) narrow the ADR/help/comment text to "whitespace-only flag or set-but-empty env" — but code and docs must agree before this ADR ships in the same commit.
