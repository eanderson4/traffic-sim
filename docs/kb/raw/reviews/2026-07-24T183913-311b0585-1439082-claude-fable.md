## Should-fix

1. **`engine/cmd/demosrv/supervisor.go:140` / `:212` — supervisor mutex held for the whole identity wait (up to 660 s).** `start()` holds `s.mu` through `waitIdentity`, and `status()` and `stop()` take the same mutex. On sf-lean/la-lean a demo start blocks `/api/status` (the menu polls it every 3 s — requests pile up, badge freezes) and `POST /api/demo/stop` for ~100–400 s; a bad start can't be aborted for up to 11 minutes. The start POST itself also now returns only after world build (~400 s on la-lean), past the point some browser/network stacks abandon a stalled request — the menu would report a failed start for an engine that then comes up fine. Consider running the identity phase outside the lock (or a cancellable wait + a lock-free status snapshot).

2. **`viz/src/main.ts:347,366` + `viz/src/tssg.ts:151` — nats.ws `MsgHdrs.get()` returns `""` for an absent key, and `""` is treated as malformed.** `parseSigChunkHeader` throws on `""` (explicitly pinned in sigchunk.test.ts), but `headers?.get("sig_chunk")` yields `""` — not `undefined` — for any message that carries headers without a `sig_chunk` key. Such frames are dropped and the HUD flags an error on every one. Latent today (HEAD publishes sig frames headerless), armed the moment the server half ever attaches any other header. Gate on `headers?.has(SIG_CHUNK_HEADER)` at the call sites (keeps the malformed-value throw intact).

3. **`docs/kb/decisions/ADR-0018-chunked-geojson.md:39,46` (and `viz/src/netload.ts:6`) — the contract doc omits the `{schema}` URL segment.** The ADR's part-URL example is `/net/{id}.geojson.{hash12}.part-000`, but the implementation emits and validates `/net/{id}.geojson.{schema}.{hash12}.part-NNN` (`geojson.go`, and the KB INDEX line even says "hash+schema-pinned"). This ADR is the contract record — make the example match.
