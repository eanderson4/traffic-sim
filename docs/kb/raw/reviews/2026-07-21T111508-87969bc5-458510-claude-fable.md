**Should-fix**

1. `hooks/pre-commit:27` — the comment claims newline-bearing filenames "split into fragments that still fail the ungated regex (fail-safe direction)". Not true in general: a gated path like `foo.md\ndocs/x.go` splits into fragments `foo.md` (matches root-Markdown) and `docs/x.go` (matches `^docs/`), so the whole file classifies as ungated — fail-open, not fail-safe. ADR-0013 (Consequences) states the opposite — and correct — behavior ("can mis-classify a newline-bearing filename as docs-only"). The two normative texts contradict; fix the hook comment to match the ADR. Risk is accepted there, so this is comment accuracy, not mechanism change.

**Nits**

2. `scripts/external-review.sh:50` — `mktemp -d /tmp/external-review-XXXXXX` hardcodes `/tmp`; the hook honors `${TMPDIR:-/tmp}`. Inconsistent.
3. `scripts/external-review.sh:34-37` — the `core.hooksPath` check accepts only `hooks|./hooks|$(pwd)/hooks`; spellings like `hooks/` or an equivalent absolute path with a symlinked cwd produce a spurious "gate not enforced" warning. Warning-only, so harmless.

Workflow friction, not a bug: an ungated docs-only commit landing between `external-review.sh` and the gated commit moves HEAD, so the stamp's `base` no longer matches and the full review must re-run even though the reviewed content is unchanged. Fail-closed, but worth knowing; a one-line note in the script's failure message would save confusion.

**Questions**

5. `hooks/pre-merge-commit:4` — merges are gated via the same index-vs-HEAD diff, so merging a long-lived, already-reviewed branch re-reviews the entire branch delta as one round (and merge diffs vs first parent can be large). ADR-0013 §4 states "no merge waiver" deliberately, and rebase/cherry-pick get the opposite treatment (accepted gap). Asymmetry is recorded, so this is confirmation, not an objection: is one monolithic re-review of merge deltas the intended cost?
