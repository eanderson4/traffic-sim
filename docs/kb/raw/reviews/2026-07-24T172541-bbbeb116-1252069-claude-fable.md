## Blocker

1. **Part URLs drop the `{hash12}` generation pin that ADR-0018 mandates — stale-manifest fetches silently mix two network versions.** `engine/cmd/demosrv/geojson.go:151` emits `/net/{id}.geojson.part-NNN` (no hash) and the handler at `engine/cmd/demosrv/main.go:355` resolves the part against the scenario's *current* hash. ADR-0018 explicitly specifies `/net/{id}.geojson.{hash12}.part-NNN` with the handler validating the hash and 404ing a stale generation ("Single-file mode was atomic per fetch; this preserves that guarantee"). As staged: client holds gen-A manifest, scenario is edited, part request regenerates under gen B and — whenever B has ≥ that many parts — serves B's slice, so the client reassembles a franken-network (duplicate/missing lanes, geometry disagreeing with the recording hash check) with no error. `viz/src/netload.ts:6,46` documents the hash-pinned contract and its `PartStaleError` 404→refetch path is dead code in exactly the dangerous case. Either add the hash to part URLs + validate in `handleNet` (small fix; `TestNetCacheChunked`'s URL assertion updates with it), or amend ADR-0018 — code and accepted ADR must not ship contradicting each other.

## Should-fix

2. **`parseSigChunkHeader` uses the wrong "absent" sentinel for nats.ws.** `viz/src/tssg.ts:152` treats only `undefined` as "no header = whole table" and throws on `""` — but nats.ws `MsgHdrs.get()` returns `""`, never `undefined`, for a missing key (verified in the vendored `headers.js`). Any signal frame carrying headers without `sig_chunk` (an unrelated header added later) is rejected as malformed and surfaces a HUD error instead of installing the table. Treat `""` from a present-headers message as absent; keep throwing on genuinely malformed values.

3. **TDZ on `mapReady` during network load.** `viz/src/main.ts:154` (`applyLayerToggles`) reads `mapReady`, declared at line 305 — *after* the `await fetchNetwork(...)`, which this very diff makes minutes-long on big nets. A legend click during that window throws an uncaught ReferenceError. Harmless in outcome (toggle state was already recorded; the load handler re-applies), but the adjacent comment claims a graceful path the code doesn't deliver. Move `let mapReady = false` above the legend wiring.
