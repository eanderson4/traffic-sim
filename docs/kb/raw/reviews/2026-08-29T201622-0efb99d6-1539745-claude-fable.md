## Findings

**should-fix**

1. `scripts/show/score-timing.py:349` + `scripts/serve-baked.py:131` — **A guest design named `base`, `retime-short`, or `green-wave` silently overwrites the published baseline's leaderboard row.** The names pass `NAME_RE`, mktimingvariant builds `variants/base`, and in the `--bake` flow (always used by serve-baked) `score()` finds the cached baseline row, sees it has no bake (`score-timing.py:233`, baselines are never baked), and re-runs *the guest's scenario* under the baseline's cache slug and `kind: "baseline"`. The board then shows "base" with the guest's numbers until someone notices and runs `--rebase`. Reachable from the play page / drawer by typing a plausible name on show day. Fix: reject `BASELINES` slugs in `mktimingvariant.validate` (or in `timing_run`).

**nit**

2. `scripts/demos/bottleneck_town.py:723` — `_seg_intersect` returns None for parallel/collinear segments, so the build-time "same-phase conflict freedom verified on the emitted polylines" check is blind to exactly-overlapping (collinear) paths. Merge foes cover the shared-target case; just know the validator's limit before leaning on the "verified by geometry" claim elsewhere.
3. `scripts/serve-baked.py:140` — `data/runs/timing-game/incoming/<slug>-<pid>.dial.json` files are written per POST and never cleaned; a long show session accumulates them silently.
4. `viz/src/hero/gamedrawer.ts:367` — the 4 s `navTimer` to `location.assign` is never cancelled: closing the drawer, editing, or starting another interaction inside the window still yanks the page to the bake. Consider clearing it on `close()`.
5. `viz/src/hero/timingpanel.ts:371` — `update()` flags the offset input `.bad` only for non-number/negative, not for `offset >= cycle` (the error text does report it); cosmetic inconsistency with the green inputs.
6. `viz/public/play.html:352` (and the same line in `signal-game.html:248`) — dead ternary: `(v.errs.length && v.cycle ? fmt(v.cycle) : fmt(v.cycle))` — both branches identical.
7. `scripts/show/score-timing.py:276` — `rewrite_board` hard-fails on any cached row with foreign seed/ticks *after* the sim time is already spent, and every subsequent invocation fails until the file is hand-removed. Unproducible through this tooling today (score() validates before caching), but it's the failure mode of a future `SEED`/`TICKS` bump — a skip-with-warning would degrade better.

**question**

8. `scripts/show/score-timing.py:157` — retry ladder: `mpath` is not removed between attempts. If serve can ever exit 0 without rewriting `-metrics-out`, a later attempt would parse the *previous voided attempt's* metrics against a fresh log. If serve rc==0 guarantees the metrics write, this is moot.
9. `scripts/show/score-timing.py:360` — CLI-only: `--dial x.json --name y` builds the variant under the dial's internal name but caches/labels under `--name`, so one design can score under an unrelated label. serve-baked always passes them equal; is the divergence intended for host use, or worth an equality check?
