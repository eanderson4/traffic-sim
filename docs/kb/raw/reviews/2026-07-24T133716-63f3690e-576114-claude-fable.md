## Findings

**Blockers** — none.

The `boundaries()` bucketing is state-identical to the old sweep: per-vehicle handling touches no cross-vehicle state (counters are commutative, `pickSuccessor`/`routeNextHop` are deterministic and query-order-independent — routing.go memoizes tables that are identical regardless of fill order), the re-entry condition `next.Index < i && v.S > next.Length` exactly reproduces when the old sweep would reconsider a crosser, and the `past` map is never iterated (keyed access only, loop drives off the `Lanes` slice) — no map-iteration determinism hazard. `Lane.Index == slice position` holds in every constructor (netfile.go:160, scenario_i80.go:139, all in-code kinds). `TotalLaneKm` cache preserves the same left-to-right slice fold, so bit-identical as claimed.

**Should-fix**

1. `engine/cmd/metview/main.go:249` — loopback check is bypassed by an empty host: `-addr :8910` gives `host == ""` from `SplitHostPort`, the `host != "" && …` guard passes, and the server binds all interfaces — the opposite of the check's stated intent. Require a non-empty loopback host.

**Nits**

2. `engine/engine.go:461-463` — comment says "at most one extra hop per tick," but hops can chain whenever each successor's index keeps decreasing (behavior correctly matches the old sweep; the comment doesn't).
3. `engine/network.go:85-96` — the zero-value sentinel means no invalidation path; safe under the "network immutable for the run" invariant (routing.go's memo relies on the same one), but tests do mutate `Length` post-construction (`metrics_test.go:594` — safe only because it precedes the first `Step`). Worth stating the immutability invariant on the `Length` field itself so a future mid-run mutation doesn't silently use a stale density denominator.
4. `engine/cmd/metview/main.go:196-233` — `metricsFile` hand-duplicates the simrun file-sink schema; a rename in the sink silently zeroes fields here. Acceptable for a read-only dev tool; a shared exported type would remove the drift risk.

**Questions**

6. `engine/cmd/metview/main.go:353-356` — `MeanK`/`MeanOcc` divide by the global run horizon, not per-lane covered time, so a lane with sparse interval coverage reads diluted. If "run-average density" is the intent, fine; if "density while observed" is, the denominator should be per-lane summed window.
