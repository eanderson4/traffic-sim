## Review — ADR-0020 demosrv public deployment

Verified: `go vet` clean, package tests pass (4.4 s). No NATS subject/payload changes anywhere in the patch — the new surface is demosrv's HTTP API + flags, and ADR-0020 covers it, so the contract discipline is satisfied. No determinism exposure: nothing touches the engine core; all `time.Now`/`time.After` use is demosrv orchestration.

I traced the supervisor concurrency redesign (`closed` latch / `stopEpoch` / `stopPending`, supervisor.go:241-283, 361-393) against the interleavings the comments claim to cover — start-vs-stop, start-vs-shutdownFinal, stop-landing-mid-guard, corpse-not-yet-reaped (supervisor.go:263-275 vs the reaper at supervisor.go:315-320) — and found no hole: every path either refuses under `mu`, or its epoch snapshot is stale and the readiness probes abort. The reaper closes `done` before taking `mu`, so `stopLocked`'s `<-a.done` wait cannot deadlock against it.

### Blockers
None.

### Should-fix
None. (The one item at that severity — the publicly advertised ws plane being an unauthenticated, publish-capable broker — is already recorded in the ADR as a go-live precondition with a startup warning at main.go's `-wspublic` branch, which is the correct triage under the repo's own rules.)

### Nits
1. `engine/cmd/demosrv/main.go:485` — with the new `stopPending` refusal (supervisor.go:251-256), an operator's start racing a queued stop now surfaces as **502 Bad Gateway** carrying "start aborted (stop requested)". The refusal itself is right (avoids spawning a child the stop immediately kills), but 502 is a misleading status for "retry your click"; 409 would be truthier. Pre-existing error mapping, so fine to defer.
2. `engine/cmd/demosrv/deploy_test.go:977-1019` — `TestResolveAdminToken` hand-rolls `os.Setenv` + cleanup; `t.Setenv` does the same restore and additionally guards against a future `t.Parallel` in the package.
3. `engine/cmd/demosrv/main.go` (server struct) — the HTTP server gets only `ReadHeaderTimeout`; no `IdleTimeout`. Absent `WriteTimeout` is clearly deliberate (multi-hundred-MB `/net/` responses), but an `IdleTimeout` is free hardening for the public shape. "Too early to need this" is an acceptable answer.

### Questions
1. `engine/cmd/demosrv/deploy.go:117-120` — length is excluded from the constant-time compare, acknowledged in the comment as acceptable for a high-entropy token. Agreed, just confirming that's the settled position rather than an oversight (a hash-then-compare would close it in two lines if anyone ever cares).
2. ADR-0020's known gap makes the public UI view-only (menu POSTs 401 with no way to supply the token). Since `-autostart` is one-shot and crash recovery is delegated to pod restart, a demo that dies mid-podcast leaves a public idle menu nobody can click back to life without an operator. That's the documented trade-off — flagging it only because the demo-program use case is exactly where it bites.

The change is unusually well-defended for its size: the fail-closed token intake (`deploy.go:225-240`), verbatim-URL validation including the trailing-`#` and userinfo cases (`deploy.go:268-281`), env stripping into both child classes, and the guard-ordering proofs in the supervisor comments all check out against the code, and the tests exercise the actual race fixtures rather than happy paths.
