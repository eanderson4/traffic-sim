## Should-fix

1. **`supervisor.start` holds `s.mu` through the identity wait (up to 660 s) — the whole control API freezes during a big-city spawn.** `start` locks at `engine/cmd/demosrv/supervisor.go:164` and `waitIdentity` polls under that lock (`supervisor.go:367`); `status()` (`supervisor.go:259`) and `withActiveReplay` (`supervisor.go:292`) block behind it. `viz/src/demos.ts:151` fires `refreshStatus` every 3 s regardless of completion, so a la-lean start (~400 s) piles ~130 hanging fetches into the browser's 6-per-origin connection cap — the menu can't render status, and even unrelated demosrv requests from that tab stall. Previously bounded at ~10 s; this change makes it minutes by design. Suggest releasing `mu` for the wait phase (a `starting` generation guard) or at minimum a non-blocking `status()` snapshot.

2. **Every part request reads and hashes the full network file twice.** `netCache.part` computes `netKey` (`engine/cmd/demosrv/geojson.go:224` — full `os.ReadFile` + SHA256), then calls `c.path` (`geojson.go:234`) which does it again (`geojson.go:125`). For la-lean (network.json in the hundreds of MB) that's ~8–10 full read+hash passes per page load on the sequential 4-part fetch, all pure waste after the first. Memoize the hash by `(path, size, mtime)` or thread it through to `path`.

3. **Stop/start race can spuriously abort an unrelated start.** `stop()` sets `stopRequested` before taking `mu` (`supervisor.go:231`); a start that was already queued on `mu` can win the lock race, observe the still-set flag in `waitPort`/`waitIdentity`, and fail with "start aborted (stop requested)" even though the user's stop targeted the *previous* run. The flag is only cleared once `stop()` finally gets the lock. Low probability (single-user menu), but the failure reads as a mystery 502; consider a per-`activeRun` abort channel instead of a supervisor-global bool.

## Nits

4. `isManifest` sniffs the first 4 KiB for the literal `"parts"` (`geojson.go:103`) — a single-file net whose first feature carries an id/property containing `"parts"` gets a spurious `Cache-Control: no-store`. Harmless (cache-defeating only), but a cheap `json.Decoder` token peek would be exact.
5. In-range hash + out-of-range part index returns 500, not 404 (`geojson.go:239` — "no part %03d" isn't `errStalePart`). Unreachable from a well-behaved client; worth a 404 anyway since it's a client-addressable URL.
6. `WriteGeoJSON` now builds the full feature slice *before* the version check rejects the file (`engine/geojson.go:85` vs check in `encodeGeoJSON`) — GBs of wasted work on a bad-version city file. Move the check ahead of `geoJSONFeatures`.
7. `noteFrameSize` counts a sig chunk even when its publish failed (`engine/natsio/bus.go:340`), while the snapshot path counts only successes (`bus.go:295`) — inconsistent watermark semantics, cosmetic.
8. `geoJSONFrameOf` (`engine/cmd/demosrv/geojson.go:249`) hand-mirrors the exporter's frame construction — if `GeoJSONFrame` grows a field, manifest and parts silently diverge. A tiny exported `engine.FrameOf(nf)` would pin them together.
9. `requestSig()` before `natsConn` is assigned is a silent no-op (`viz/src/main.ts` — gap during the subscribe handshake); the attach-time pull and the 15 s partial timer cover it, so behavior is right, but a comment there would save the next reader the trace.

## Questions

10. ADR-0016 documents the interleaved-round merge limitation (complementary chunk losses across two rounds can splice A-head+B-tail; `sig_gen` deferred until tables can change mid-run). Confirmed harmless today since the accumulator requires exact `1..n` with matching `n` *and* tables are static — is there any near-term path (scenario hot-reload, adaptive control) that changes programs mid-run? If yes, `sig_gen` should land before it.
11. The ADR-0016 §7 observer-publish amendment (`contracts/asyncapi.yaml:52` x-permissions) is doc-only — the embedded broker runs authless, so nothing enforces "that one subject only." Intended as forward doc for when auth lands?
