## Should-fix

1. **`deploy.go:199-206` — a set-but-effectively-empty `DEMOSRV_ADMIN_TOKEN` silently deploys the gate OPEN.** `resolveAdminToken` trims the env value; a Secret that decodes to `"\n"` or whitespace (the exact `echo`-into-Secret footgun class the TrimSpace targets) yields `""`, which `adminGate` treats as "local dev, no gate." On a public pod the operator's only signal is the *absence* of the "admin gate ON" line (`main.go:970-972`). The dual failure (trailing newline → 401 forever) got a fix; this direction fails open and silent, which is strictly worse for the deployment this flag exists for. Suggest: if `os.Getenv(adminTokenEnv)` is non-empty but trims to empty, log loudly or fatal.

## Nits

2. **`deploy.go:221` — `Bearer ` prefix match is case-sensitive.** RFC 7235 auth-scheme is case-insensitive; `bearer <tok>` 401s. Operator-tooling audience makes this low-impact, but it's a one-line `strings.EqualFold`-style fix if you ever touch this again.

3. **`deploy.go:216-218` — gate binding is construction-time.** `adminGate` returns `h` unwrapped when `s.adminToken == ""` at `routes()` time. Correct today (token resolved before `routes()` in `main.go`), but the invariant "adminToken must be set before routes()" is load-bearing and undocumented at the `server.adminToken` field. Comment-only.

## Questions

4. **`deploy.go:253` — autostart is one-shot: a demo that crashes *after* a successful autostart leaves the public pod idle indefinitely** (the reaper clears `s.active`, nothing restarts it; the token-less public UI can't restart it either, per the ADR's known-gap). Is the recovery story a K8s liveness probe / pod restart in the out-of-repo manifests? If so it might deserve one line in ADR-0020; if not, it's a gap in "always-on public instance."
