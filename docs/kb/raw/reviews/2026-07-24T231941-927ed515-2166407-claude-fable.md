Review of the staged diff (route-budget metering in the driver's obs path + new budget test).

**Blockers:** none.

**Should-fix**

1. `driver.go:380-386` — the budget charges every `pickExit` draw, but the cost it defends against is only the reach-cache **miss** (the O(network) BFS in `destinations.go:85`; a warm-cache draw is O(candidates)). Two consequences: (a) a 1000-vehicle claim burst on an already-warm cache still takes ~31 ticks to route despite negligible per-draw cost; (b) deferred vehicles drift off the small set of origin lanes before their turn comes, so their draws hit *new* `fromIdx` values — more first-touch BFS scans and a lower memo hit rate, i.e. the deferral partially defeats the cache it protects (still bounded per tick, so the stated goal holds). Charging the budget only when `d.exits.reach[fromIdx]` is absent targets the actual cost directly. Defensible either way under the triage bar, but the comment's cost rationale and the mechanism don't quite line up.

2. `driver.go:382` behavior drift under load: a deferred vehicle draws from its LaneIdx *at draw time*, not at first observation. Concrete bad case: over-budget on tick 1, by tick 2+ it has advanced into a stretch from which `pickExit` returns `ok=false` (or a different reachable-exit set) — it then gets `want=""`, is marked routed, and keeps kernel-default routing for life, where the origin-lane draw would have succeeded. Deterministic per (seed, ID, lane) and live-only (replay reads recorded intents), so not an ADR-0005 replay hazard — but exit-distribution now depends on claim-burst size vs. budget. Worth a line in the commit message; fix 1 also shrinks the deferral window.
