## Should-fix

1. **`engine/cmd/demosrv/supervisor.go:163` — `start()` holds `s.mu` across the identity wait (≤660 s), and `status()` takes the same mutex (`supervisor.go:258`).** During an la-lean spawn (~400 s world build), every `/api/status` poll blocks until start returns; the menu's 3 s poll accumulates hanging requests and saturates the browser's per-host connection pool, freezing the whole menu (not just the starting card) for minutes. `stop()` is covered by `stopRequested`, but status should read a snapshot outside the start-blocking lock (atomic active pointer or a narrower state mutex).

2. **`engine/cmd/demosrv/geojson.go:105` (`netKey`) + `geojson.go:195-219` (`part`) — full network re-read + sha256 per request, twice per part.** `part()` hashes the net file for validation, then calls `c.path()` which re-reads and re-hashes it again. A cold la-lean page load does ~10 full reads+hashes of a ~GB file on the serving path (manifest + 4 parts × 2). Memoize `(netPath, mtime, size) → hash`, or at least skip `c.path()` when the requested part file already stat-hits.

3. **`viz/src/main.ts` (`requestSig`) — the pull path stays permanently dead after 3 failed attempts until a reconnect.** Live runs fall back to the 20-tick broadcast, but a paused replay never rebroadcasts (this diff removes it, `engine/natsio/player.go:399`): a paused-replay client whose 3 pulls failed transiently has no signal path at all — the 15 s partial timer's `requestSig()` calls are no-ops against the exhausted budget. A time-based re-arm of `sigReqRetries` closes it. Per the repo's triage bar this is deferrable — record it.
