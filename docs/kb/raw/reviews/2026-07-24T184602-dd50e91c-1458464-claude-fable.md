## Should-fix

1. **`viz/src/main.ts:2510` (patch) / `tssg.ts parseSigChunkHeader` — empty-string header reads as malformed, but nats.ws returns `""` for an *absent* header.** Verified in `node_modules/nats.ws/.../headers.js:194`: `MsgHdrs.get()` returns `""` when the key is missing. `parseSigChunkHeader("")` throws (and `sigchunk.test.ts:3740` deliberately pins `""` as malformed). Today the staged engine publishes signal frames with no headers object at all (`msg.headers === undefined` → fine), but the moment any frame carries a headers block without `sig_chunk` — the unstaged engine half, or any future header addition — **every** signal frame throws and the client treats it as an error, not a whole table. Map `""` → `null` at the call site (`headers.has(...)` guard) or in the parser.

2. **`viz/src/main.ts` (patch ~2496-2498) — the pull-retry condition is self-contradicting; the bounded retry never fires.** `.finally(() => { ... if (retry && replyAccum.partial) requestSig(); })`: a mid-reply gap sets `retry = true` but the accumulator's gap handling calls `reset()`, so `partial` is false → no retry. A truncated reply (timer expired mid-generation) leaves `partial = true` but `retry = false` → also no retry. Neither failure mode retries; the intended condition is `retry || replyAccum.partial`. Related: `sigReqRetries` is a *lifetime* budget — it resets only on a successful pull, never when a broadcast round completes (`installSigTable`), so three failed pulls (the attach-time pull against the current staged engine, which has **no** `sig.req` responder, always burns one) permanently disable the pull path for the session. Impact is bounded — the 20-tick broadcast re-converges in ~2 s — but the resync mechanism ADR-0016 exists for is mostly dead code as written.

3. **`supervisor.go:140-166` — `start()` now holds `s.mu` for up to `readyTimeout + identityTimeout` ≈ 12 minutes, and `status()`/`stop()`/`withActiveReplay` block on the same mutex.** Previously the lock-held readiness window was ≤10 s. On an la-lean start (~400 s world build — the case this change exists for), the demos menu's 3 s `/api/status` poll hangs, stacked fetches accumulate, and there is no way to stop or abort a stuck start until the identity phase resolves. Consider probing identity outside the lock (re-validate `s.active` on completion) or serving `status()` from an atomic snapshot.

4. **Commit split vs. KB claim: `docs/kb/INDEX.md:19` flips ADR-0016 to `[x]` (implemented), but the engine half is not in this patch.** The staged `natsio` has no `sig_chunk` publisher, no `ts.{run}.state.sig.req` responder (both exist only in *unstaged* `bus.go`/`sigframe.go`/`player.go`, plus untracked `sigchunk_test.go`). The client degrades gracefully, so the split is shippable — but as staged the commit's KB asserts an implementation it doesn't contain, and the engine half will need its own review round. Either stage the engine side or defer the `[x]` flip to that commit.

## Nits

- **ADR-0018 / `netload.ts` header comment document the part-URL shape as `/net/{id}.geojson.{hash12}.part-NNN`, omitting the `{schema}` segment** the implementation emits (`geojson.go:151`, pinned by `geojson_test.go`'s regexp). Cosmetic (clients only follow manifest URLs), but the ADR should match what ships.
- **`main.go handleStart` embeds `ws=ws://...` unencoded while `demos-core.ts buildAppURL` uses `encodeURIComponent`** — the "must agree" comment now holds only for shape, not bytes. `URLSearchParams` decodes both identically, so no functional impact; align or soften the comment.
- **`supervisor.go:303`** — a passing probe followed by a dead child is reported as "belongs to a foreign process", but the same path covers our own child registering then crashing. Message overclaims.
- **`natsio/probe.go`** — a fresh WS connection + JetStream context per 1 s poll for up to 660 s (~660 handshakes). Fine for a dev tool; a held connection would be gentler.
- **`supervisor.go:45` comment** says `identityTimeout` "matches" the 600 s `-attach-timeout`; it's 660 s — presumably intentional margin so the child's own timeout fires first. Say so.
