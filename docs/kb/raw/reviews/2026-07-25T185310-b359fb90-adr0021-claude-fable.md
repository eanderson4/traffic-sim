## Review — ADR-0021 (OD demand) + ADR-0022 (US urban typemap)

Verified along the way: the layered 0-1 BFS in `routeLatDepth` is correct (full 0-cost closure before each lateral step; lateral links are mutual at all three construction sites — network.go:159, netfile.go:324, scenario_i80.go:147 — so the reversed lateral edge set really is `u.Left`/`u.Right`); the draw-order append (gap→vtype→destination) and sorted-key `weightedDraw` preserve pinned realizations; keyframe v3/v4 gating round-trips; the typemap's "only speed differs, no id added or dropped" claim is **exactly true** against the venv's stock `osmNetconvert.typ.xml` (verified by script); `gateTarget` already measures from `v.S` so interior probes gate correctly.

### Blockers

**B1. `followerAt` has a one-vehicle-length blind spot — interior injection can materialize on top of a vehicle.** `engine/spawn.go` (new `followerAt`): it searches for the first vehicle with `S > rear` and takes `a[i-1]`, i.e. the nearest vehicle at-or-behind the injected REAR bumper. But `leaderAt` is probed from `v.S − 1e-9` (spawn.go, `injectionPlan`), so a vehicle whose front bumper lies strictly inside `(rear, v.S)` — inside the injected vehicle's own body span — is found by *neither* check. Concrete failure: lane B0, offset 250, car length 4.5 ⇒ rear = 245.5; a queued car with front bumper at 248 (car behind it at 228). `leaderAt(lane, 249.999…)` skips it (248 < 250), `followerAt` takes the car at 228 (gap 17.5 ⇒ clear), injection admitted, bodies overlap ⇒ immediate collision observation and IDM shock. Queued traffic at a garage mouth is exactly the chi-loop-od regime, and this violates the one property ADR-0021 §3 promises ("there is no entry speed that fixes being materialized on top of someone"). `TestInteriorInjectionRearClearance` places its follower fully behind `rear` (S=238) so the window is untested. Fix shape: search the follower from the injection point `v.S` (mirroring leaderAt's epsilon), not from `rear` — then `gap = rear − b.S` goes negative for an overlapper and `room ≤ 0` denies. Note the same window exists on the `i == 0 → prevFollower` fall-through.

**B2. Replay of existing driver-attached recordings diverges — the ADR's bit-identical claim doesn't cover the two new lateral mechanisms.** ADR-0021 §1 claims "Every pre-ADR-0021 recording … is bit-identical. The CRC-pinned fixture suite is the check." That holds for the arrival-despawn case ordering, but not for:
  - `engine/intent.go:354` (`tryForcedLaneChange` now gated on `routeHopOK`): replay re-applies recorded `LaneDelta` intents, and pre-ADR-0021 recordings are full of routed vehicles — the default driver sets `Route` on *every* vehicle (driver.go:443, ADR-0019 exit routing) and its MOBIL is route-blind (the ADR's own numbers: 28% of positions have an off-route neighbour; 92% of routed vehicles were walked off-route). Hops that executed live now get vetoed on replay ⇒ different state ⇒ CRC mismatch against the recorded CRC stream.
  - `engine/mobil.go` (`tryRouteRecovery` runs "in live runs too", i.e. under holdlast): replaying an old recording now inserts engine-initiated lane changes that never happened live.

  The fixture suite cannot catch either — no fixture sets `Route` (grep: zero hits). So every archived recording made with the default driver attached (the 2026-07-24 city-scale serving rounds, anything the podcast demo work banks on) stops replaying/seeking to its recorded CRCs. ADR-0022 §5 goes out of its way to keep old recordings valid; ADR-0021 breaks them silently while claiming the opposite. Minimum fix: correct the ADR claim and add the migration note ("recordings with driver-routed vehicles replay only on the pre-ADR-0021 kernel"); alternatively gate veto+recovery on something the recording carries. Decide explicitly — don't ship the false claim.

### Should-fix

**S1. ADR-0022 flag list contradicts the shipped pipeline.** ADR-0022 Consequences (~line 189) says the chi-loop A/B used "same flags — `--proj.utm --no-turnarounds --junctions.join`", but `scripts/import-city.sh` deliberately passes **no** `--junctions.join` anywhere (its own comment, per ADR-0017 stop-node keying). Either the flag list is a typo, or `chi-loop-urban` was produced outside the shipped script — in which case its `REPO_REV` provenance doesn't describe how it was actually built and the script can't reproduce it. State which.

### Nits

- **N2.** `scripts/chicago/mkod.py` `emit_flow` formats destination weights `%.4f`; a normalized share < 5e-5 emits `0.0000`, which scenario load rejects ("weight must be > 0"). Fail-loud, but the generator should floor/omit instead of emitting an invalid file.
