## Review — ADR-0026 M2 (driver-side TSIB batching)

**Scope check:** matches the ADR-0026 M2 plan exactly — per-tick aggregation, cap split, route-diversion to standalone v2, `-intent-batch` flag, one-batch-per-tick / split / route-tick / byte-identical-off tests, paired-seed on/off parity. Subject unchanged; header demux and codec were M1; asyncapi.yaml is deliberately M4. No contract gap.

**Blockers:** none.

**Should-fix:** none.

**Nits:**

- `engine/natsio/driver/driver.go:418` — `flushBatch` trusts `NewTSIBMsg` to be non-nil and `sentIntents.Add(uint64(n))` to equal encoded records. Both hold today only by construction (the `in.RouteSet` switch at driver.go:366 keeps route intents out of `batch`, and `n ≤ TSIBMaxRecords` keeps `EncodeTSIB` from returning nil) — but the invariant lives two functions away. If a future change lets a `RouteSet` intent into `batch`, `EncodeTSIB` silently skips it while the counter still counts it; if the nil path is ever reachable, `PublishMsg(nil)` panics. A one-line comment or nil-skip would pin it. Per the triage bar (hypothetical hardening), fine to ignore.
- `engine/natsio/driver_test.go:731` (`resimBatchLeg`) — duplicates the inline re-sim block of `TestDifferentialLanedrop` (driver_test.go:441–471) rather than refactoring that test to call the new helper. Test-only duplication; ignore or fold later.

**Questions:**

- `engine/natsio/driver_test.go:830` — the wave-envelope gate reuses `TestDifferentialLanedrop`'s ±2 m/s bounds but *without* that test's documented `TRAFFICSIM_DRIVER_DIFF_STRICT` escape (driver_test.go:503–531, added because driver lag reshapes waveP90). Here both legs carry the same driver lag so the tighter hard-fail is plausibly intentional — but ADR-0026 itself says applied ticks "legitimately diverge" between modes, which is the same mechanism that forced the skip there. Has this test been run enough times (`-count=10`+) to trust the bounds? If it flakes, the skip precedent is already in the file.

**Verified clean:**

- **Determinism:** batch assembly is ego (observation-slice) order — no map iteration in any publish path, no wall clock, no RNG change (streams stay per-vehicle-ID, ADR-0007). Fleet-map iteration at driver.go:384 is delete-only, order-irrelevant. Each parity leg independently asserts record→re-sim→live CRC identity (`resimBatchLeg`), which is exactly the guarantee ADR-0026 makes; cross-leg comparison is correctly statistical, not CRC.
- **Arbitration safety:** route-tick vehicles ride one complete v2 and are omitted from the batch (driver.go:366), so no competing same-vehicle intents under first-wins; v2s and the batch share one connection/subject, so per-publisher ordering (and hence engine-assigned seq monotonicity) is preserved across the mixed stream.
- **Split correctness:** `flushBatch` chunks at `TSIBMaxRecords`; decode side enforces `count ≤ cap` and exact length; test covers cap+5 with order and exactly-once coverage across the split.
- **Batch-off fidelity:** `publishIntent` is the pre-M2 publish verbatim (headerless `EncodeIntent`), pinned byte-for-byte by `TestBatchOffByteIdenticalV2`; test header strings are pinned literally on purpose (wire-contract pinning, since natsio's constants are unexported).
- **Counter semantics:** `SentIntents` documented and implemented as per-vehicle records in both modes — comparable across A/B, matching its use in the parity test.
- **Flag validation** in both binaries rejects non-`on|off` values before connecting; `attachDriver` plumb-through in serve is consistent.
