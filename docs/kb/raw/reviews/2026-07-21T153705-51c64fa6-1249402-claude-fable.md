## Findings

**Blockers** — none. Determinism discipline is clean throughout: all maps are either lookup-only (`crossedChain`/`exitResolve` parent maps, `metricSet.acc`) or key-sorted before emission (`gone` despawns, `servedIDs`, `Totals`, drains); accumulation runs in `e.Vehicles()` append order and fixed set/origin/queue orders; no wall clock, no RNG. CRC/keyframe untouched; no NATS subject/payload change in this diff, so no contract note needed beyond ADR-0014 itself.

**Should-fix**

1. `engine/metrics.go:575-585` — `k.spPend` is never seeded, so the first `Observe` always sees `st.pend.ID != 0` and books a phantom "injection", decrementing the just-initialized backlog. If an origin is overdue at tick 1 (schedule tick 1 + blocked by pre-placed vehicles or a density cap — reachable, e.g. the `TestKernelDeniedFutureDirective`-style setup with the spawner enabled), the backlog goes 1 → 0 and the whole first blocked episode integrates from 0: `DeniedWaitS` undercounts by dt per overdue tick and `Pending` misses the held vehicle, violating the documented "≥ 1 while the origin is overdue" invariant (`LaneDenied` doc, metrics.go:172-178). `spawner.init` runs in `NewEngine` (engine.go:136-139), so the pend IDs exist at `NewKernel` time — seed `spPend` (and `spOverdue`) there. One-line fix; no test covers a tick-1-overdue origin.

**Nits**

2. `engine/metrics.go:519-529` vs the normal despawn path — the defensive trip-reconstruction branch adds `stoppedS`/`stops` for the exit tick when `prev.stopped`, but the normal despawn path accrues neither for that final partial tick. The two paths disagree on exit-tick stop semantics; pick one (dropping it from the defensive branch is simpler and matches the "pre-run/final-fraction unobservable" stance).
3. `engine/metrics.go:611-629` — `dirDue` is keyed by `RequestID`, whose uniqueness is a contract-layer duty (`director.go:42-45`); a duplicate ID slipping into `dirQueue` (kernel `EnqueueSpawn` doesn't dedup) silently collapses wait/served accounting for one entry. Fine to leave given the documented layering; worth a one-line comment at most.
4. `engine/metrics.go:899-988` (`crossedChain`/`exitResolve`) — BFS is shortest-by-hop-count; on a net with two parallel internal lanes connecting the same pair (plausible in OSM junction imports) or diamond paths to a single exit, the booked chain's lane lengths can differ from the traveled one's, misbooking distance with no `DroppedCrossings` signal. Unreachable on current nets (needs sub-tick-length parallel internals); "too early to need this" is a fair triage — a comment acknowledging it would do.
5. `engine/metrics_test.go` (`TestKernelDeniedBacklog`, `blocked := map[uint64]string{}`) — keyed by frozen `st.tick`; two origins sharing a schedule tick silently halve coverage. Key by lane ID instead.

**Questions** — none blocking. The 900 s default window, stop pin, occupancy/time-loss formulas, interval bounds/partial semantics, and prospective backlog integration all match ADR-0014 §2/§3/§5 as written.

Per the triage bar: nothing here blocks the commit; item 1 is the only finding I'd fix before shipping since it breaks a documented invariant on a reachable path and the fix is a construction-time seed.
