Move the resync description/parameters/messages back under `stateSigReq`; leave `sigReplyInbox` with only its own description. The contract file is the sacred artifact — this is exactly the file that must parse.

## Should-fix

2. **`engine/cmd/demosrv/supervisor.go:163` — `start` now holds `s.mu` for up to ~720 s (60 s port + 660 s identity), and `status()` (:258) takes the same mutex.** `/api/status` (`main.go:332`, polled every 3 s by the menu) and every other supervisor-touching handler blocks for the entire la-lean world build (~400 s); requests pile up and the menu freezes with no feedback. `stop()` stays responsive via `stopRequested`, but status doesn't. Snapshot status under a separate small lock (or record a "starting" state before the wait) so the menu can render progress. Previously `mu` was held ≤10 s, so this is a behavioral regression, not a pre-existing wart.

3. **`engine/cmd/demosrv/geojson.go:217` — every part request hashes the full network file twice.** `part()` calls `netKey` (full `os.ReadFile` + sha256), then `c.path()` (:120) which calls `netKey` again. On la-lean (~0.9 GB network.json) that's ~2 GB of disk read + hashing per part request, ×4 sequential parts + 1 manifest ≈ 10 GB per page load, all inside a browser's critical load path. Since `part()` has already validated the hash, pass it into a hash-trusting variant of `path` (or memoize on `(path, size, mtime)`), consistent with the "generation is rare and cheap" comment that no longer holds at this scale.
