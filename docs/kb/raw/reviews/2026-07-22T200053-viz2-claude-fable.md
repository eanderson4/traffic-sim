## Findings

**Blocker**

1. **engine/geometry.go:42-44 (+ removed branch at old geometry.go:100-103), engine/netfile.go:176-180 — all-coincident lanes regress from "sit on the point" to a wrong-frame teleport.** Before this diff, an all-coincident shape (`i30677892_0_0`) was kept and `Project` hit the `shapeLen == 0` branch: the vehicle rendered at the lane's actual coordinates. Now dedup collapses it to one point, `SetShape` clears the shape, `Project` returns `!ok`, and `SnapshotFrame` falls into the placeholder branch (engine/natsio/frame.go:115-118) — which is the M1 chain-offset frame (`x = XOff + s`, `y = 3.5 × lateral slot`, `angle = 0`), **not** the network's local UTM frame. Any vehicle resting on that lane at a tick boundary (plausible: SUMO gives such lanes Length ≈ 0.1 m, and a queued crawl spends many ticks per 0.1 m — the M13 notes already document vehicles occupying sub-4 m internal lanes) publishes coordinates near the network origin: a full-map teleport, strictly worse than the east-flash this commit exists to fix, on the flagship I-280 demo. The netfile.go comment ("clears to the placeholder projection, not an error") reads as if the placeholder were benign; on an imported network it isn't. Fix direction: when dedup leaves exactly 1 point from an originally ≥2-point shape, preserve sit-on-the-point behavior (e.g. keep the single point and restore the degenerate branch) instead of clearing.

**Should-fix**

2. **viz/src/glyphs.ts:267-278 + viz/src/main.ts:464-465 — the "SDF" image is not a distance field.** `fillRect` produces binary alpha (0/255); registering it with `{ sdf: true }` makes tinting work, but `icon-halo-color`/`icon-halo-width: 1` need an alpha ramp in the halo band to render — with a hard edge the halo is essentially absent and edges alias under the heavy minification (icon-size 0.086–0.43). The PAD comment ("room for the SDF field to fall off") describes a falloff that is never drawn. Either render a real distance ramp in the alpha channel (a few concentric fills or tiny-sdf-style) or drop the halo paint props and the SDF claim. Since the pass was live-viewed, downgrade to nit if the on-screen result was judged acceptable.

**Question**

3. **Wire frame values change without a note in the KB addendum.** The dedup corrects published `angle` (and finding 1 changes published x/y) on affected lanes — TSSF stays v1 and frame.go's own doc establishes the values-only precedent, so no ADR needed; but the addendum claims "no engine/wire change," which is inaccurate at the value level. If any frame recordings or content hashes are golden-pinned (the review-workflow doc warns about exactly this binding), they shift. Confirm none are pinned yet; fix the addendum wording either way.

4. **viz/src/legend.ts:14-15 — `SIM_DT_S = 0.1` hardcoded, but dt is a runtime engine parameter (`e.Params.Dt`), not a constant, and it isn't on the wire** (frame carries tick only). If a scenario ever runs a non-default dt, the clock silently lies. Fine for now if ADR-0005 pins 0.1 as the only supported dt; otherwise this is a latent mismatch worth a comment or a config plumb.

**Nit**

5. **viz/src/main.ts:442,463 — positional coupling `GLYPHS[0]`/`GLYPHS[1]` alongside literal match keys `0`.** If GLYPHS is ever reordered, cls 0 silently gets the truck image; the theme test checks presence by cls, not array order. Deriving via `glyphFor(0)`/`glyphFor(1)` removes the coupling.

6. **viz/src/theme.ts:563-566 vs main.ts:446 — `vehicleBearingDeg` normalizes to [0, 360) but the "same math" style expression doesn't.** Harmless (MapLibre normalizes rotation), but the tested "spec" and the shipped expression differ in exactly the branch the wraparound tests exercise.

**Clean on the focus axes otherwise:** dedup is exact-equality and order-preserving (deterministic, `pts[:0:0]` avoids aliasing the caller's slice); after dedup `cum[n-1] > 0` is guaranteed for every 2+-point shape and `cum` is package-private with `SetShape` the sole writer, so removing the zero-check from `Project` is internally safe (the *behavioral* consequence is finding 1); no map iteration, wall clock, or RNG touched; netfile one-point-shape error path still covered by netfile_test.go:102; geometry_test math checks out (Project(150) → (100, 50), π/2); viz changes are pure client-side with source/promoteId/diff channel untouched — no subject or schema change.
