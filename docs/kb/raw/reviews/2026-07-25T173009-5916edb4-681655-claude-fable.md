## Findings

**Blockers** — none.

The epoch/pending/latch ordering holds up under every interleaving I could construct: `stop()` marks `stopPending` before bumping `stopEpoch` and holds the mark until it owns `mu`, while `startGuarded` snapshots the epoch before checking pending under `mu` — so a racing stop either trips the pending refusal or its bump post-dates the snapshot and the probes abort (`supervisor.go:361-393`, `supervisor.go:244-283`). The reaper clearing `s.active` under `mu` closes `a.done` *before* taking the lock, so `stopLocked`'s wait can't deadlock against it. All four advertisement points (`reg.WS` at startup, `/api/demos`, both start deep links) route through `wsClientURL`/`advertisedWsURL`, which `-wspublic` overrides; `wsDialURL` correctly stays on the pod-local listen address for the identity probe. No NATS subject/payload changes; the HTTP-surface changes (401 gate, 409 start-vs-stop refusal) are covered by ADR-0020. Nothing touches sim/determinism paths.

**Should-fix**

1. **ADR-0020 contradicts itself on crash recovery.** The Decision's `-autostart` bullet (`docs/kb/decisions/ADR-0020-demosrv-public-deployment.md:73-75`) says an engine crash is "NOT terminal — a later retry starts the autostart demo, the intended pod self-heal," but the Consequences section (`:169-172`) says `-autostart` is "ONE-SHOT: a demo that crashes after a successful start leaves the pod idle — crash recovery is the manifests' job." The code is one-shot: `autostartDemo` returns permanently on first success (`deploy.go:196-198`); a self-exited run only gets re-started if the crash lands inside the ≤4-attempt retry window (the narrow case `TestStartIfIdleAfterChildExit` covers). The Consequences text matches the code; the Decision text over-promises self-heal. Since the ADR is what the deploy manifests will be written against (liveness probe vs. relying on demosrv), fix the Decision wording before commit — docs-only edit, doesn't re-trigger review.

**Nits**

2. `main.go:203-209` — the `hs.Serve` error path calls `log.Fatalf`, which skips the deferred `os.RemoveAll(binDir)`; the pre-warm temp dir leaks. Pre-existing pattern on the other post-mkdir `Fatalf` paths; noting, not asking.
3. `main.go:463,473` — public `/api/status` reports the engine child's PID. Inside a pod it's near-worthless to an attacker; zeroing it in the public shape would be free, but ignorable per the triage bar.
4. `deploy_test.go` (`TestResolveAdminToken`) hand-rolls env save/restore; `t.Setenv` does the same and additionally panics on accidental `t.Parallel`, which is the actual hazard for package-global env mutation.

**Questions**

- The gate is per-route wrapping in `routes()` (`main.go:398-443`), and `TestAdminTokenGate` enumerates the seven current mutating routes by hand — a future mutating POST added without `adminGate` ships open and no test notices. The routes() comment flags the discipline, and a structural guard now is arguably hardening-against-hypotheticals; flagging so the choice is conscious.
- `resolveAdminToken` lets a supplied flag win silently over a *different* env value. Documented behavior and reasonable; just confirming flag-shadows-Secret is intended in a pod that sets both.
