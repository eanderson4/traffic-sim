  ## Should-fix

  - **engine/signal.go:302-306 — offset-wrap guard discards a real override boundary.** In the `ov.until <= x` branch, when `elapsed > x` (fixed phase onset wraps before tick 0 — possible with an offset program early in the run), the function returns `(idx, 0, false)` without checking `ov.until`. If a hold lapsed at `ov.until > 0` inside that first wrapped phase, the displayed transition was the lapse, but the reported onset is 0 — and `sigInClearance` returns false on `onset == 0` (signal.go:379), silently denying the clearance window round-3 was built to protect. Narrow (needs offset ≠ 0 + a lapse inside the first partial cycle), but it's the same bug class round 3 fixed, and offset programs are the norm in real SUMO crops.
