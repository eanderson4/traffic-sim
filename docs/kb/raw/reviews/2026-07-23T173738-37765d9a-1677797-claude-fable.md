## Should-fix

1. **`player.go:487` — seek doesn't republish the signal table at the landing tick unless `tick % keyframeEvery == 0`.** Harmless today because TSSG is self-sufficient (clients derive light state from tick by integer math, ADR-0011 §1) and the program table is static per run — but the demo-program work-queue (logged in f3f1921) will make tables mutable mid-run, at which point a backward seek while playing leaves the viz rendering the *future* program for up to `keyframeEvery` ticks. The unconditional publish is one line and matches what `republishPaused` already does; alternatively record the deferral. Your triage bar may legitimately call this "too early."

2. **`main.go:110` (`-ws`) has no loopback enforcement while `-http` does.** The NATS WebSocket listener is a full pub/sub + JetStream-API endpoint over the *durable record store* — a routable `-ws` bind exposes strictly more than the control plane the patch carefully fences with `checkLoopback`. It mirrors `serve`'s existing posture (serve/main.go:47 is identical), so this is a pre-existing decision — but the new binary is the one whose comment argues loopback-only security. Worth a one-line note in the ADR addendum if intentionally deferred.
