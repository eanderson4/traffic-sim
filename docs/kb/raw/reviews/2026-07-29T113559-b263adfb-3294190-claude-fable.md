# Review — staged diff (ADR-0029 phase 1, ADR-0031/0032/0033/0034)

## Blocker

**1. Warm start + demand director double-spawns the Lead-window arrivals (serve's scenario path — the primary use case).**
`fastForward` (`engine/natsio/demand/director.go:326`) skips only arrivals with `atTick <= startTick`. But the cold run had already *sent* arrivals up to `N+Lead` (Lead default 30) — those directives are in the restored `dirQueue`. The warm director re-sends them on its first snapshot, and dedup has no memory of consumed IDs:
- the fresh Contract's `c.verbs` is empty (`engine/natsio/contract.go:764`);
- `EnqueueSpawn` rejects only IDs **live in the queue** (`engine/director.go:154-163`).

No snapshot is published before the first Step (`engine/natsio/run.go:211-227` — first `PublishSnapshot` is after Step N+1), so a restored directive with earliest tick near N is injected *before* the re-sent verb lands; its RequestID is then gone from the queue, the duplicate is accepted, and with `DirectorSpawnHoldTicks = 600` it injects a second copy of the same vehicle instead of expiring. In batch mode (`-pace 0`) many ticks pass before the verb round-trips, widening the duplicated window. Result: nondeterministic extra vehicles right after the warm-start tick — the "program from that tick on is identical" claim (ADR-0029, `director.go` comment) is silently false for `serve -state-in` with a demand scenario. Both bit-exact tests (`engine.TestWarmStartRoundTripIsBitExact`, `natsio.TestRunLiveWarmStartIsBitExact`) use the spawner-only `lanedrop` spec, so nothing pins this. Fix options: dedup against consumed RequestIDs (engine- or contract-side, seeded from the restored queue), or publish a snapshot and drain the director before the start gate opens — the current shape loses the race by construction.

## Should-fix

**2. `leaderAtFor` spends the held turn later than the vehicle does.** `engine/engine.go:452-455`: the probe zeroes `HeldTurn` only inside the `len(cur.Successors) > 1` branch. `boundaries()` consumes it at the *first* crossing regardless (`engine.go:749`), and `gateTarget`'s probe zeroes it after every hop (`rightofway.go:166-167`). A vehicle whose first hop is a single-successor lane (netimport's fragment stubs are exactly this) carries the turn into a later diverge and the lookahead watches the turn branch instead of the routed one — the wrong-branch class ADR-0032 exists to kill, and the comment's claim "exactly as exitBlocked's probe does" is not true of the code.

**3. Keyframe v5 with an empty director queue relies on a swallowed short-read.** Writer emits the directive section only when `len(e.dirQueue) > 0` (`engine/keyframe.go:173`), but the reader does `n := r.u32()` for every `ver >= 3` (`keyframe.go:325-329`). Pre-diff those coincided (version ≥ 3 ⇔ non-empty queue); v5 breaks the invariant: stuck timers + empty queue (the normal gridlock case, hit by `TestStuckTimerSurvivesAKeyframe`) makes the reader short-read, latch `r.err`, get `n=0` by accident, and pass only because the section is last and `r.err` is never re-checked. Write the count unconditionally for version ≥ 3 (0 when empty), or gate the read on remaining bytes.

**4. `engine/vehicle.go:84-88` comment is the pre-review text: "NOT keyframed — a warm-started vehicle begins its stuck timer at zero."** It contradicts the same diff's keyframe v5 and the ADR-0034 correction that exists precisely because this reasoning was wrong. Left standing, it invites someone to undo the replay fix.

**5. `-state-in` + `-metrics-out` is knowable-bad but not validated.** `NewKernel` refuses a nonzero-tick engine (`engine/metrics.go:320-321`), so the combination always dies in `RunLive` after broker/store setup with the misleading "metrics: attach before the first Step (engine already at tick N)". `validateStateFlags` (`engine/cmd/serve/main.go`) states its own rule — "every one of them is knowable before the run starts" — and this one is.

## Nits

**6. `fastForward` ignores `d.endS`** (`director.go:329`): warm-starting past the demand end keeps drawing where the cold path marks the flow exhausted at the first `at > endS`. No verb ever differs; internal draw counts do. Harmless today.

**7. Stale future-format numbering.** ADR-0029 Decision 1 says lane-id keyframes are "format v4", its Phase-1 section and `warmstart.go`/`warmstart_test.go:4129-4131` say v5 — and v5 is now taken by the ADR-0034 stuck timer. The lane-id format will be v6; three references will mislead.

**8. Even where dedup wins, warm start re-sends the whole restored Lead window and every rejection logs "verb … REJECTED"** (`director.go:336`) — reads like a failure on every warm start. Worth a quieter reply path for "duplicate of restored directive" once finding 1 is fixed.

## Checked and clean

- Determinism: `LaneFingerprint`/`TypeFingerprint` hash in index order with length prefixes and IEEE bits, no map iteration; `resetStuckBehind`'s map is membership-only over slice-ordered work; the serve strand printout sorts with a total order; `strandStuck` sweeps `e.order`, no clock/RNG. `stuckTicks` out of the CRC but keyframed is coherent.
- Contract: no NATS subject/payload changes; `ContractConfig`/`demand.Config` additions are Go API; metrics JSON additions are additive to a local artifact and covered by ADR-0034's ADR-0014 amendment; keyframe format bump is self-versioned and ADR-documented, old versions stay readable and old recordings replay with `StrandAfterS` zero-valued from their stored spec.
- `Observe` is enforced consecutive-per-tick, so the per-tick `StrandedIDs` handoff can't skew; stranded trips are excluded from completions and included in the mean-time-loss denominator.
- ADR-0031/0033 gate logic: `sigPermissive` reads the current tick's char; `foeHeld` skip / mutual-yield tie-break / protected-and-unsignalised fallthrough match the stated table; unsignalised paths (`foe.Signal == nil`) are byte-identical to before.
- `maxLaneHops` (12) covers the measured 8-lane cycle for `resetStuckBehind`; the I-80 control and sealed-junction bleed tests pin the escape's boundaries well.
