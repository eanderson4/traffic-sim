## Findings

**Should-fix**

1. `engine/cmd/demosrv/replay.go:715-727` (`handleReplayStart`) — TOCTOU between `sup.start` and `checkRecordingHash`: if a second start (demo or replay) swaps the child in between, the first request's hash check reads the *new* child's `/status` and, on mismatch/error, calls `s.sup.stop()` — killing the winner that just returned 200 to its own caller. Pre-existing start races were last-start-wins; this failure path can kill the last starter. A compare-and-stop (stop only if the active target is still this recording) would close it. Localhost single-operator, so triaging this out as too-early is defensible — but it's a newly introduced kill-the-innocent path, not just a stale read.

**Question**

2. `engine/cmd/serve/main.go:1525-1527` — absolutizing `spec.Net.Path` into the durable RunMeta trades cwd-dependence for machine/path-dependence: a recording breaks if the repo moves or the scenario dir is renamed, and the hash comment ("stable across copies, renames, and machines") no longer describes the record's *replayability*. The KB already logs a run-meta-lifecycle deferral (ab8b039) — confirm this is the same deferral and note it there; a repo-root-relative convention or embedding the network in the record are the eventual fixes. Also, recordings made before this change still carry relative paths and stay cwd-bound.

**Nits**

3. `engine/cmd/demosrv/replay.go:668-670` — `checkRecordingHash` uses the package const `ctlTimeout` while everything else uses the injectable `s.ctlTimeout`; the tests happen to pass real 2 s timeouts so it's unobservable today, but the injectability is half-done.
4. `engine/cmd/demosrv/replay.go:803-809` — a response of exactly 1 MiB false-positives the truncation log; and a genuinely truncated body is still forwarded to the client as 200 with malformed JSON (log-only). Fine for a memory guard, but returning 502 on hitting the cap would be one line.
5. `viz/src/main.ts:1917` — the `console.warn` "speeds rendered so far were off" fires on the *documented normal path* (running-recording deep links carry no `?dt=`, so config's 0.1 default vs a 0.05 recording always warns). Consider downgrading to `console.info` or only warning when an explicit `?dt=` was overridden.
6. `engine/cmd/demosrv/registry.go` → `/api/demos` now also serializes recordings' absolute `store`/`scenarioDir` paths to the browser (pre-existing pattern for demo `scenarioDir`; localhost-only).
7. `engine/natsio/player.go:1543` — the new `hash` status field is additive control-plane surface; the ADR-0006 addendum describes the control plane but doesn't name the field. One line in the addendum (docs, ungated) keeps the contract doc exhaustive.

**Determinism** — clean: no sim-kernel changes; new Go map (`seen`) is never ranged for output; viz `Map` iteration (speed buttons) is insertion-ordered; SeekGate/SnapshotBuffer changes are render-side only, and the authoritative-dt adoption moves speed derivation *toward* the recorded truth.

**Contract** — clean: no NATS subject or payload changes; `-replay` suffix rejection in the registry mirrors the ADR-0006 reservation already enforced at activation, failing loud at load instead.

Test coverage is strong (both-ports readiness, kill-symmetry, run-binding 409s, pre-POST reset ordering with a pre-ack landing frame, hash match/mismatch/unverifiable). Nothing here blocks the commit.
