## Blocker

**B1. `rerouteTable` reachability walk validates the pre-install graph — a spliced hop can close a routing cycle** — `engine/routing.go:339-349` (patch: the walk in `rerouteTable`).

The walk starts at `j = fresh[i]` and follows `mixed[]`, but `mixed[i]` still holds the *static* hop during the walk. If the chain from `fresh[i]` passes back through `i`, the walk continues via the static `mixed[i]` and can reach the destination → `reached = true` → install `mixed[i] = fresh[i]` → the served table now contains the cycle `i → fresh[i] → … → i`. The comment claims the walk runs "with the candidate installed"; the code does not install it.

Concrete construction (2 lanes A, B, dest D; `idx(A) < idx(B)`): static A→C→D, B→A; fresh tree A→B, B→E→D. Candidate A: walk from B goes B→(static)A→(static)C→D, reached, install A→B. Candidate B: fails the hysteresis margin, keeps static B→A. Final table: A→B→A. Vehicles orbit forever, and — as the ADR itself notes for free-flow loops — the floored dwell samples never break the cycle. This is exactly the regime hysteresis creates (near-margin candidates rejected downstream). Fix: tentatively install `mixed[i] = fresh[i]`, walk from `i` with the hop bound, revert on failure.

**B2. First-use table build bypasses hysteresis — the served table depends on access history, breaking the restore-purity claim** — `engine/routing.go:216` (miss path: `e.routeDijkstra(destIdx, e.routeWeight)`) vs `engine/routing.go:213` (stale path: `e.rerouteTable`).

Under the flag, a cache miss builds the raw adaptive Dijkstra tree; a stale-recompute builds the hysteresis-reconciled mix against the static table. Same epoch, same frozen weights, two different tables — whichever is served depends on whether the destination was already cached in a prior epoch. A mid-run restore starts with an empty cache, so its first access takes the miss path and serves the raw tree, while the live engine may have been serving the mixed table for the same epoch → replay divergence (the ADR-0029 property this design exists to guarantee), and ADR-0036's "every table is a pure function of (frozen weights, network)" is false as implemented. `TestAdaptiveRestoreIsCRCExact` misses it because its first-use builds all happen while `ttSnap` is still ≈ free flow (the c₀ dwell sample lands at ~tick 790, after the epoch-1 freeze at 600), so raw and mixed coincide. Secondary effect even without restore: a destination first requested in a congested epoch gets a table with no hysteresis damping and no B1 reachability guard (harmless there — a pure Dijkstra tree is acyclic — but inconsistent). Fix: with the flag on, route the miss path through `rerouteTable` too; a test where the first-ever access to a destination happens in a congested epoch, followed by a restore, would pin it.

## Should-fix

**S1. Hysteresis margin is tested against the idealized fresh-tree cost, not the installed mixed chain** — `engine/routing.go:334-337` (`dist[i] >= oldCost-margin`). `dist[i]` assumes the entire fresh tree downstream of `i` is installed, but later candidates on that chain can be rejected by their own margin, so the actual mixed path from `i` may be worse than `dist[i]` — a splice can install without genuinely beating the static path by the margin (or at all). Determinism is unaffected; oscillation damping — the margin's stated job — is weakened. Reasonable to record and defer per the triage bar, but note it interacts with validation-plan item 3 (flip counts): if oscillation shows up in the bracket, look here before reaching for the seeded fallback.

## Nit

**N1.** `engine/engine.go:664-665` — `routeEpochTicks`/`ttRelaxTicks` divide by `Params.Dt` with no guard; a zero Dt gives `uint64(+Inf)`. Fine if Dt is validated upstream, which it appears to be.

**N2.** `engine/keyframe.go:938-939` — the v6 lane-section guard checks lane *count* only; a different network with an equal lane count restores silently misattributed ttEMAs. The `checkNet` hook covers the callers that pass it, so this is defense-in-depth only.

## Question

**Q1.** `engine/engine.go:748-750` — the free-flow floor means a lateral hop or mid-lane spawn that leaves after seconds contributes a full free-flow-time sample. On a congested lane (EMA ≫ ff) that's an *optimistic* sample actively pulling the EMA down — lane-changers dilute the congestion evidence of exactly the lanes vehicles are escaping. Intended dilution, or worth restricting samples to full traversals (junction entry → junction exit)?
