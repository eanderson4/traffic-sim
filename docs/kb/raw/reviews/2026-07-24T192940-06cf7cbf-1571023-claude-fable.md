## Blockers

None.

## Should-fix

1. **`supervisor.start` holds `s.mu` for the entire identity wait (up to 660 s), freezing the API at exactly the scale this change targets.** `start` (supervisor.go:146) holds the mutex through `waitIdentity`, and `identityTimeout` is now 660 s (supervisor.go:46) against a la-lean world build the diff itself estimates at ~400 s. During that window `status()` blocks, so every 3-second menu poll (`refreshStatus`, viz/src/demos.ts) hangs and goroutines pile up; the start POST itself won't answer for minutes, which is past Chrome's ~300 s stalled-response limit — the menu reports failure while the child is still building, and a user retry then acquires the lock and *kills the half-built child* (kill-before-spawn). Previously the bound was 10 s so holding the lock was harmless. Consider probing outside the lock, or keeping status readable via an atomic snapshot.

2. **`handleStart` reads the run id back via a second, unchecked `status()` call.** main.go:330 ignores the `ok` result: if the child exits between readiness and this call (crash, tick horizon), `run` is `""` and the client gets `/app/?run=&net=…`; a concurrent start could also swap the active run between the two calls. `start()` computed the nonce-suffixed id — return it from `start` instead of re-deriving it from mutable state.

## Nits

3. **`netCache.part` validates the generation pin *after* regenerating.** geojson.go:185–197 calls `c.path()` (a full ~1 GB encode on a cold cache) before checking `wantSchema`/`wantHash`; a stale-generation request pays the whole generation just to 404. Swap the order — the checks are pure.

4. **Comment drift:** supervisor.go:46 says identityTimeout "Matches the -attach-timeout demosrv passes serve" — it's 660 s vs 600 s. Say "outlasts" or align the values.

5. **`ProbeRunMeta` dials a fresh WS connection + JetStream + KV handle every second** for up to 11 minutes of polling (probe.go / supervisor.go `waitIdentity` loop). Works, but a reused connection would be cheaper and quieter in broker logs.

6. **gofmt spacing inconsistency:** sigchunk_test.go has `sub2.NextMsg(5*time.Second)` where every sibling call in the same file writes `5 * time.Second` — verify `gofmt -l` is clean (I couldn't execute gofmt in this sandbox).

7. **ws param encoding asymmetry:** demosrv embeds `&ws=ws://…` raw (main.go handleStart, replay.go:134) while `buildAppURL` (demos-core.ts) uses `encodeURIComponent`. Both parse identically via URLSearchParams, but the "they must agree" comment overstates — the agreement is shape-level, and the two sides now produce different bytes for the same URL.

## Questions

8. **Pull-budget exhaustion re-creates push-and-pray for the motivating case.** main.ts `requestSig`: after 3 pulls that don't complete, `sigReqRetries` stays pinned until a *broadcast* generation completes — so a chronically busy tab (the ADR-0016 incident) permanently loses the pull path. The bounded budget is clearly deliberate (comment cites hot-loop avoidance); confirm the no-decay choice is intended rather than, say, re-arming on a timer.

9. **Redundant pull on generation turnover:** `handleSigMessage` fires `requestSig()` on the `gap` produced when a new round's chunk 1 abandons a stale partial — that new round is already in flight and usually completes. Bounded by the in-flight guard, so just confirming it's intentional.

## Verified clean

- **Determinism:** chunk packing is a pure slice-order function; single-chunk output is byte-pinned to `SignalFrame` (TestSignalChunksRoundTrip); no map iteration in any published path; wall clock (`runNonce`, probe) is confined to demosrv infra, not the engine kernel.
- **Contract:** the `sig_chunk` header, `ts.{run}.state.sig.req` subject, MaxPayload 1 MiB→4 MiB, and the GeoJSON `junction`/`row` properties + manifest/parts shape are all covered by ADR-0016 (ratified in this commit) and ADR-0018; the exporter schema bump (`v2` in cache filenames) correctly invalidates stale caches; exact-subject subscribers of `.state.sig` can't receive `.sig.req` traffic.
- **Part-URL parsing** (main.go handleNet) validates schema+hash before any filesystem join and the route pattern excludes path separators — no traversal.
- **Accumulator** never installs a partial table, distinguishes same-tick paused-replay rounds by order not tick, and the reply path uses a dedicated accumulator so broadcast interleave can't corrupt a pull (sol-review fix present and tested).
