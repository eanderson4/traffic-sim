**No blockers.** The design is sound: exact-subject discrimination (no prefix matching anywhere — verified), shared record codec, strict decode, header/payload tick cross-check in one choke point, and `PullMaxBytes` is genuinely passed through to the server by `Fetch` in nats.go v1.52.0 (verified against the tagged source). Old recordings keep their untouched path; contract change has the ADR, version bump, and migration note.

**Should-fix**

1. `engine/natsio/recorder.go:383` — `loggedIntentMax` hard-codes 256 bytes for the controller name, but nothing enforces that bound. Engine-assigned ids are `ctl-%d` (contract.go:588), but legacy-path intents record the controller name straight off the wire subject token (`bus.go:348` `tokens[4]` → `contract.go:841`), which is unbounded up to the server control-line limit (~4 KB). `appendLoggedIntent` then emits a record wider than the reservation the flush check at recorder.go:404 relies on, so a batch can exceed `IntentBatchMax`. Harmless at the 768 KiB default (broker max_payload 1 MB), but a user who raises `IntentBatchMax` toward max_payload gets a rejected publish mid-run — a run abort from a constant whose premise was never checked. Cheap fix: clamp or refuse `len(ctl) > 256` in `appendLoggedIntent`, mirroring the `intentMaxRoute` truncation two lines up.

2. `engine/natsio/tslb_migration_test.go:210-239` — the empty-stream half of `TestRecorderRefusesToAdoptANonEmptyStream` very likely never enters the `AddStream` → `UpdateStream` fallback it claims to cover. The seed stream (no Compression, defaults) and the recorder's `UncompressedStore: true` config are identical after server normalization (Replicas 0→1, zero Retention = Limits), so `AddStream` succeeds idempotently, the fallback never runs, and the final assert (`NoCompression`) passes either way. The one genuinely new broker path — empty stream, *differing* config, converge via `UpdateStream` — has no coverage. Make the assert discriminating: seed without compression, adopt with the S2 **default**, assert the adopted stream ends up `S2Compression`.

**Nit**

3. `engine/natsio/recorder.go:154` — the non-empty-stream refusal only triggers when `AddStream` errors, i.e. when configs differ. A name collision with a preserved recording whose config happens to match the current defaults passes `NewRecorder` silently and dies later as an opaque OCC sequence mismatch on the first publish, not the clear "refusing to adopt" error. Pre-existing shape (idempotent `AddStream` always allowed this); an unconditional `StreamInfo` emptiness check would make the guard mean what its comment says.

**Question**
