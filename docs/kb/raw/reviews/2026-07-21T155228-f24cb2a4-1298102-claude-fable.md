## Findings

**should-fix — `engine/metrics.go:406-411` (invisible-gap detector overcounts routinely, not rarely).** The gap heuristic (`v.ID > maxFirstSeenID+1` ⇒ `droppedCrossings += gap`) treats out-of-order first observations as invisible vehicles. But spawner pend IDs are pre-assigned at the *previous* injection (`spawn.go:179-186`), and per-origin schedules are jittered — so with ≥2 origins, cross-origin injection order inverts ID order as a matter of course (adjacent pends invert whenever the jittered intervals differ by >1 tick). Every inversion permanently increments `DroppedCrossings`, and there is no reconciliation when the "missing" ID appears later (a below-max first-seen ID is silently ignored). On a multi-origin run like the `TestKernelCongestion` spec this plausibly accrues tens of spurious counts, drowning the signal the counter exists to carry (genuine attribution failures). The code comment frames this as a rare race ("a late-spawning low ID"); it is the common case. Cheap fix: decrement when a previously-gap-counted ID is later first-observed, and/or reconcile held pend IDs at Finalize. Notably no test asserts `DroppedCrossings == 0` on a clean multi-origin run — worth adding once fixed.

**nit — `engine/metrics.go:223` (comment points at the wrong enforcement layer).** The `dirDue` comment says RequestID uniqueness among live entries "is a contract-layer invariant, director.go" — but `director.go`/`EnqueueSpawn` accept duplicate RequestIDs; the dedup actually lives in `natsio/contract.go:595` and only covers NATS-driven runs. A local driver enqueueing duplicates collapses them in the `dueNow` map: wait accrues correctly (per-entry), but `DeniedServed` undercounts. Fix the comment (or dedup in `EnqueueSpawn`).

**nit — `engine/metrics.go` (`DroppedCrossings` conflates units).** One counter mixes (a) crossings booked conservatively (metric error ~meters), (b) whole vehicles never observed (gap estimate, entire trips missing), and (c) the false positives above. A consumer can't tell "≈2 m misattributed" from "N trips absent". Fine for v1 if documented at the `Totals` field, but consider splitting when the NATS publisher pins the schema — after that it's a contract change.
