## Findings

**BLOCKER — `scripts/osm-stop-nodes.py:284-308` — `refs` is not reset between `direction=both` walks; the backward walk can run on the wrong way.**
Inside `for step in steps:` the per-step state resets only `cur, j, seen` (line 284); the split-hop rebinds `refs` (lines 306/308) and that binding leaks into the next iteration of the `steps` loop. With `direction=both` and a forward walk that hops a way split, the backward iteration computes `j = i + step` from `i` (an index into the *original* way's refs) but indexes into the *hopped* way's refs. Concrete failure: ways `10=[1,2,3]`, `11=[3,4,5]` same-name split at 3, junctions at 1 and 5, stop at node 2 with `direction=both` → forward correctly marks 5; backward then starts at `refs=[3,4,5], j=0`, falls off the front, re-hops to way 11 with `step` flipped to `+1`, and re-marks 5 — junction 1 is never marked and the arm set used for allway aggregation is wrong. Silently corrupts the stop map on real city extracts (splits are ubiquitous; `direction=both` occurs). Fix is one line: reset `refs = way_nodes[wid]` (and derive nothing else from the stale binding) inside the `steps` loop. `test_both_marks_both_ends` (test_osm_stop_nodes.py:797) doesn't cover the hop+both combination — add a case.

**QUESTION — `scripts/import-city.sh:103-105` — does pass 2 preserve the no-turnaround topology?**
Pass 1 passes `--no-turnarounds` (the contract doc at network-format-v1.md says default turnarounds close the clipped map boundary into U-turn loops); pass 2 (`--sumo-net-file` + `--node-files`) doesn't repeat the flag, and netconvert recomputes connection logic for re-typed nodes on reimport. If 1.27.1 re-adds turnarounds on reimport, every stop-carrying import silently regains the boundary U-turns pass 1 removed. If the two-pass output was already checked for this (the header claims verification on 1.27.1), note it in the comment; otherwise verify one net or add `--no-turnarounds` to pass 2.

**QUESTION — `scripts/overpass2osm.py:475-482` — bbox-clipped `out geom` ways.**
Overpass clipped `out geom(s,w,n,e)` output can carry `geometry` entries that don't 1:1 match `nodes` (clipped/`null` points). The `len(refs) == len(geom)` guard then skips synthesis entirely, emitting `<nd>` refs with no `<node>` behind them (or `pt["lat"]` throws on a `null` entry inside the zip when lengths do match). If all cached inputs are unclipped this is fine — but a one-line comment stating "unclipped extracts only" would stop the next person from feeding it a clipped pull.

**NIT — `scripts/import-city.sh:112-117`** — `-source` stamps "two-pass stop overrides" even when the no-stops branch ran a single pass; provenance metadata is slightly wrong for stop-free imports.

**NIT — `scripts/import-city.sh:112`** — `NC_VER=$("$NC" --version | head -1)` under `set -o pipefail`: if netconvert's version output ever exceeds the pipe buffer, SIGPIPE fails the assignment and aborts the script. Theoretical at today's output size.

Determinism: all outputs are order-stable — `osm-stop-nodes.py` sorts way ids before walking (line 277) and node ids before rendering (line 326); `overpass2osm.py` and `overpass-lean.py` preserve input order via insertion-ordered dicts/lists; `render-city.py` uses wall clock only for progress logging on a static render.
