Review of the staged diff (chunked GeoJSON serving per ADR-0018, supervisor identity probe, ADR-0016 sig-table chunking client, themes, stop signs). Determinism discipline is clean — the export/chunk paths iterate lane slices in order, no map iteration, no wall clock in engine code, and the manifest/part encoding is deterministic. Contract additions (`sig_chunk` header, `ts.{run}.state.sig.req`) are covered by ADR-0016 and `contracts/asyncapi.yaml`. One blocker:

**Blocker**

1. **Part URLs omit the content hash that ADR-0018 mandates — the mixed-generation guard doesn't exist.** `engine/cmd/demosrv/geojson.go:151` emits `/net/{id}.geojson.part-NNN`; `engine/cmd/demosrv/main.go:355` parses no hash and `part()` re-resolves the hash from the *current* scenario at request time. ADR-0018 (docs/kb/decisions/ADR-0018-chunked-geojson.md:46) explicitly requires `/net/{id}.geojson.{hash12}.part-NNN` with handler validation that "404s a stale generation… preserves the single-file atomic-per-fetch guarantee", and `viz/src/netload.ts:6` claims that same hash-pinned behavior in its header comment. As staged, a scenario edit between the client's manifest fetch and its part fetches silently serves parts from the new generation under the old manifest — mixed lane sets, or a spurious 404 when the part count shrank. Either implement the hash segment + validation, or amend ADR-0018 and the netload.ts comment — but the ADR's rationale is sound and the client comment already promises it, so implement. (The geojson.go:29 header comment also documents the hash-less shape, so the two comment blocks in this one diff disagree with each other.)

**Should-fix**

2. **Resync requests can self-amplify on stream interleave.** `viz/src/main.ts:340`: `if (res.gap) requestSig()`. Reply chunks (from `requestSignalTable`) and broadcast chunks feed the one accumulator; a resync reply landing while a broadcast round is partially accumulated abandons the partial (correct) but the `i==1` branch returns `gap: true` — which immediately fires *another* full chunk-set request. There's no in-flight guard or backoff, and each `requestSig` opens a 10 s `requestMany` iterator whose replies can interleave with the next cadence broadcast and re-trigger. Bounded in the common case, but it costs redundant full-table round-trips under exactly the busy-tab conditions ADR-0016 targets. Minimal fix: suppress `requestSig` while a request is already in flight (or don't fire on gaps whose new round is the reply itself).

3. **ADR-0018 is untracked, not staged.** Docs pass the gate ungated, but the ADR recording this contract should land with (or before) the implementing commit, per ground rule 3.

**Nit**

4. `engine/cmd/demosrv/main.go:329` (and replay.go:134) emit `ws=ws://…` unescaped while `demos-core.ts` `encodeURIComponent`s it — the "must agree" comment now only holds after URL parsing, and the two sides' tests pin different byte shapes. Harmless; both parse identically.

5. `viz/src/netload.ts:36-39`: the 4096-batched inner loop is a no-op — it pushes one element per iteration either way; only spread/`apply` hits the arg-count limit. A plain `for…of` push is equivalent and simpler.

**Question**

6. `probeRunMeta` (supervisor.go) equates identity with `{run}/meta` presence. Two checkouts running the same run id (both spawning the default registry's `r1`) still cross-attach — the probe closes the *different-run-id* incident only. Fine to defer per the triage bar; verifying the meta's content hash would close it fully if it recurs.
