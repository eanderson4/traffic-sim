### Should-fix

1. **`deploy/k8s/ingress.yaml:32` — FrontendConfig annotation key is likely wrong case.** GKE's documented key is `networking.gke.io/v1beta1.FrontendConfig` (capital F, C); annotation keys are exact-match, so the lowercase `networking.gke.io/v1beta1.frontendconfig` would be silently ignored — no HTTPS redirect, no error anywhere. Verify against current GKE docs and fix before the eventual apply; silent-no-op is the worst failure mode for a security-adjacent redirect.

2. **`deploy/k8s/service.yaml:7` — BackendConfig attachment depends on NEG backends, which is implicit.** `cloud.google.com/backend-config` (and its custom health checks + the load-bearing 86400s ws timeout) only takes effect with container-native LB. That's the default only on VPC-native clusters; if `carbon-dev` predates that default, the Ingress falls back to instance groups, the BackendConfig health-check ports (container ports 8900/8443) are wrong, and the 30s default timeout severs websockets — exactly what this file exists to prevent. Add `cloud.google.com/neg: '{"ingress": true}'` explicitly so the assumption is stated, not inherited.

### Question

3. **`deploy/demos.public.json` — all-or-nothing startup coupling to bucket contents.** `registry.Load` stat-checks every `scenarioDir` at startup (`registry.go:207-214`), so if any one of the six `<city>-lean` prefixes is missing from `gs://roaring-bots-traffic-sim/scenarios/`, demosrv fatals and the pod crash-loops — one missing city takes down the whole site rather than dropping one menu entry. Similarly, `deploy/k8s/deployment.yaml:37`: `gcloud storage cp "gs://…/netcache/*"` errors on an empty prefix and fails the initContainer. Confirm all six cities + a non-empty netcache are uploaded; consider noting the failure mode in deploy/README.md.
