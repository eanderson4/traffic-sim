Read the diff and reviewed both scripts. Findings, ranked:

**Blocker**

- `scripts/external-review.sh:192` — TOCTOU: the stamp is computed from `git diff --cached` *after* the reviews finish, not from the diff that was actually reviewed (`$work/diff.patch`, captured at line 138). Reviews take minutes; anything (a parallel agent, an editor auto-stage, the user) that changes the index during that window gets stamped as "reviewed" without any reviewer having seen it. This silently defeats the one invariant the whole change exists to enforce ("review always covers what ships"). Fix: `git hash-object "$work/diff.patch" > "$root/.git/external-review-stamp"`. As a bonus that also makes the commit fail loudly when the index drifted mid-review, which is exactly what you want.

**Should-fix**

- `hooks/pre-commit:72` — comment says the stamp is written by `scripts/review-stamp.sh`, which doesn't exist; it's written by `scripts/external-review.sh`. Same block (line 69) claims the gate proves "Claude Fable + GPT-5.6-sol + Gemini reviewed" — Gemini is milestone-only and optional. Fresh file shipping with a wrong pointer and wrong claim.
- `hooks/pre-commit:81` and `scripts/external-review.sh:192` — `$root/.git/...` breaks in linked worktrees, where `.git` is a file: the script's redirect fails with "Not a directory" *after* both paid reviews succeed (`set -e` kills it before archiving prints), and the hook can never match. Use `git rev-parse --git-dir` (per-worktree, which is also arguably the right scope for the stamp).
- `scripts/external-review.sh:176-181` — the empty-output check covers `fable` and `sol` but not `gemini`. A Gemini CLI that exits 0 with empty stdout (auth prompt swallowed, quota) gets an empty file archived as a "review" in the KB and the round still counts. Add `g`emini to the loop when `with_gemini=1`.

**Nit**

- `scripts/external-review.sh:184` — `slug` is computed and never used. Dead code; delete or use it in the archive filenames (which are currently timestamp-only, so concurrent rounds in the same second collide — unlikely, but the slug was presumably meant to help).
- `scripts/external-review.sh:137` — `$work` is never cleaned up on success, so full repo diffs accumulate in `/tmp` indefinitely. A `trap 'rm -rf "$work"' EXIT` on the success path (keep on failure, as now) would do.
- `hooks/pre-commit:76` — with `core.quotePath` (the default), paths containing non-ASCII bytes are emitted quoted (`"engine/\346..."`), so the leading `"` defeats the `^engine/` anchor and the commit bypasses the gate. `git -c core.quotePath=false diff ...` closes it.
- `hooks/pre-commit:95` — the error message says "Run /external-review first" but that's the milestone skill; the per-commit gate is the script shown two lines later. Minor, but this is the message people see most often — worth making it name the script only.

**Question**

- `scripts/external-review.sh:192` — the stamp is written before anyone triages the findings, so a commit passes the gate even when the reviews contain blockers. AGENTS.md's wording ("unless the exact staged diff was reviewed") says that's intentional — the gate proves *review happened*, not *review was clean*. If that's the design, fine; but note the fix-and-re-stage loop is enforced only by honor, since re-staging after fixes requires a re-run anyway. Just confirming this is the intended trust boundary.
- `hooks/pre-commit:80` — partial-path commits (`git commit -- <paths>`, `git commit -a`) run the hook against a temporary index, so the diff hash will never match the stamp and such commits are always blocked even when fully reviewed. Probably acceptable (arguably even desirable), but worth knowing before someone hits it confused.
