## Findings

**Should-fix**

1. **`viz/src/main.ts:590` + `viz/src/main.ts:190` — the adopted authoritative dt only reaches the SnapshotBuffer; the articulator and SeekGate keep `cfg.dt`.** `onStatus` calls `buffer.setSimDt(s.dt)` when the recorded dt disagrees with the URL hint, but the render loop still computes trailer sim-elapsed as `(sample.tick - prevSampleTick) * cfg.dt`, and `new SeekGate(cfg.dt)` is never re-targeted. The exact path this adoption exists for — a running-recording card deep link, which `buildReplayURL` (viz/src/demos-core.ts:902 in the patch) deliberately ships without `?dt=` so `cfg.dt` defaults to 0.1 — leaves both stale for the whole session: a dt-0.05 recording integrates 2× sim time into every trailer (permanent over-articulation), and a fine-timestep recording (dt < ~N/2400 at N× speed, e.g. 0.001 at 8×) advances ~800 ticks per frame against a maxJump of 240, tripping `resetForSeek` on **every** frame — the buffer never holds two frames, all speeds render 0, and vehicles teleport at snapshot cadence. Fix is small: derive `dtS` from `buffer.simDt` and add a `SeekGate.setSimDt` (or recreate the gate) inside the `onStatus` adoption branch.

2. **`viz/src/replaypanel.ts:2372` (patch line; `refresh()`) — a malformed 200 body drops the adopted run identity.** `this.status = parseStatus(await resp.json())` assigns `null` on parse failure, so the next poll goes out unbound and silently adopts whatever replay is then active — bypassing exactly the stale-tab 409 protection the run binding was built for (the failure mode the `refresh: a bound-poll 409 does NOT adopt` test pins for the 409 path exists here via the parse path). Keep the old `status` on parse failure and just return null.

**Nit**

3. `engine/cmd/demosrv/replay.go:756` — `checkRecordingHash` uses the package const `ctlTimeout` while every proxied call uses the injectable `s.ctlTimeout`. Harmless today, but the verify hook is the one call tests can't shrink.

4. `engine/cmd/demosrv/registry.go` (`LoadRegistry`) — demo runs are registered in `seenRuns` but demo↔demo duplicates are never rejected, despite the comment declaring one shared NATS-subject namespace. Pre-existing behavior and harmless under single-active-run, but the enforcement is now asymmetric (recordings collide loudly, demos don't).

5. `/api/demos` now serves absolute `store` filesystem paths to the browser (`Recording.Store` is absolutized at load and has no `json:"-"`). Same pre-existing pattern as `scenarioDir`; localhost-only tool, so cosmetic.

**Question**

The comment only prices in the start-click delay — confirm the menu-poll stall is also acceptable (it looks fine for a demo console).
