# External review — staged diff (TSSG chunking / ADR-0016, chunked GeoJSON / ADR-0018, run-identity readiness, themes)

Read the full patch plus the staged `geojson.go`, `supervisor.go`, `player.go`, `main.ts`, and `asyncapi.yaml` for context. Contract discipline is in order: the new subject (`ts.{run}.state.sig.req`), the `sig_chunk` header, and the MaxPayload amendment are all covered by ratified ADR-0016 with the asyncapi bump to 2.3.0; the HTTP manifest contract is ADR-0018. Determinism checks came up clean — chunk packing iterates slices in file order (no map iteration), the tick patch is a fixed-offset memcpy, `crypto/rand` touches only infrastructure run ids, and the byte-identity of single-chunk output vs `SignalFrame` is test-pinned.

**Blockers:** none.

**Should-fix**

1. `viz/src/main.ts:346` — the pull budget (`sigReqRetries >= 3`) permanently disables the request/reply path until a *reconnect*; only a pull success (`main.ts:359`) or reconnect (`main.ts:868`) re-arms it. The stated fallback is the broadcast cadence, but a **paused replay no longer broadcasts the table at all** (`player.go` `republishPaused`). A client attaching to a paused replay that burns three 10 s attempts during a transient hiccup shows no signals indefinitely while appearing connected. Re-arm the budget on a slow timer (e.g. once a minute) or on the paused-attach path.

2. `engine/cmd/demosrv/geojson.go:211` (`part`) — each part request runs `netKey` (full read + SHA-256 of the source network file) and then `c.path`, which runs `netKey` *again*. A chunked la-lean load (manifest + 4 parts) does ~9 full reads of a multi-hundred-MB file, each materialized in memory (`os.ReadFile`) even where only the hash is needed. Correct, but an avoidable latency/GC spike on exactly the big-city path this feature exists for; streaming the hash in `part` (or passing the hash from `part` into a `path` variant) halves it cheaply.

**Nits**

3. `engine/cmd/demosrv/geojson.go:82` — `path`'s doc comment is now orphaned: the inserted `isManifest` sits between the "path returns…" comment and `func path`, so the comment documents the wrong function.
4. `engine/cmd/demosrv/geojson.go:89` — `isManifest` substring-sniffs `"parts"` in the first 4 KiB; a lane id literally named `parts` in a single-file net would false-positive and stamp `no-store` on a 100+ MB document (re-download every load). Harmless today, worth a tighter check (e.g. also require `"features":[]`) if it ever bites.
5. `engine/cmd/demosrv/main.go` (`reg.WS = wsClientURL()` in `main`) — dead in practice: `handleDemos` overwrites it per-request; only the flag default survives via `wsClientURL()` fallback. Fine, mildly misleading.
6. `engine/cmd/demosrv/identity_test.go` — first direct `nats.go` client use in `cmd/*`; `probe.go`'s stated rule is "cmd/* never touches nats.go directly". Test-only and pragmatic (fixture setup), but worth a one-line note so the boundary doesn't erode silently.
7. `engine/cmd/demosrv/geojson.go` `writePart` — a single lane over the threshold is emitted as-is *silently*; the analogous TSSG case logs. ADR-0018 doesn't require a log, so this is consistent-but-quieter.
8. `viz/demos.html` inline theme script duplicates both palettes from `theme.ts` by hand; `theme.test.ts` pins `theme.ts` but nothing pins the HTML mirror, so paper/navy drift there would ship unnoticed.

**Questions**

9. `/api/demo/{id}/start` now blocks up to `identityTimeout` = 660 s inside the handler (`supervisor.go`); the `http.Server` (`main.go:95`) has no timeouts so the server side is fine — is a >5-minute in-flight browser `fetch` acceptable for la-lean, or should start return early and let the menu poll `/api/status`? (Deliberate per the ADR note; flagging the UX cliff only.)

The chunk accumulator, the greedy pack boundary math, `withSigTick` immutability, the manifest atomic-write ordering (parts before manifest), the hash-pinned 404-stale part contract, and the per-spawn run-nonce ownership proof all check out against their tests and ADR text.
