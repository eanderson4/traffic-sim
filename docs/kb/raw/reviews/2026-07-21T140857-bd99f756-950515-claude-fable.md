## Findings

**Blockers** — none found.

- Determinism: clean. All map emissions are key-sorted (`Observe` despawn scan metrics.go:399–404, `Finalize` trips :492–496, `Totals` :569–578); accumulation runs in `e.Vehicles()` append order, `k.sets`/`s.lanes` config order, `e.spawner.origins`/`e.dirQueue` fixed order. No wall clock, no RNG, no bare map iteration reaching an accumulation or emission path. `DeniedByLane` is documented as lookup-only with a sort-before-emit warning (metrics.go:170–172).
- Engine-model alignment: the crossing taxonomy (same-lane wrap / successor / successor+lateral-hop / pure lateral) matches `boundaries()`'s downstream-first one-crossing-per-tick guarantee (engine.go:379–388) and phase 5-before-6 ordering; ring wrap (`S -= Length`, lane pointer unchanged, engine.go:400) matches the `d < 0` branch. Denied-entry predicates (`pend != nil && st.tick <= tick`; `EarliestTick <= tick` on the retained queue) match spawner hold-and-retry (spawn.go:110) and director drop-on-expiry (director.go:134–135), including the wait-without-pending semantics for expired directives.
- Contract: no NATS subject or payload is touched; records are in-process structs with `SchemaVersion` stamped for the ADR-0014 §4 sinks. No ADR note needed for this commit.

**Should-fix**

1. metrics.go:174 (`Kernel` doc) / :479 — `Finalize` is not idempotent for denied demand: a second call re-runs the `deniedPending[...]++` loops (:503–515) and doubles `Pending` counts (intervals and trips are naturally protected; this one isn't). "Call once" is documented, but a two-line guard (or clearing the maps first, making it a stamp) is cheap insurance for a state-mutating method on an otherwise read-safe type. Defer if you count this as hypothetical-hardening.

**Nits**

2. metrics.go:760 (`denom := l.Length * dur`) — a zero-length lane emits `±Inf`/`NaN` Q/K/Occupancy silently. `NewKernel` validates everything else loudly (the §5 "strict fence"); `netimport` copies `length` from the XML unvalidated (netimport.go:224). SUMO doesn't emit 0-length lanes, so this is latent, but a `Length <= 0` check at construction would be consistent with the fence.
3. metrics.go:430–437 vs :420–424 — despawn-tick stopped-time asymmetry: the reconstruction path credits the exit sliver (`ts.stoppedS = t` when `prev.stopped`), the normal path never does. Sub-tick noise; note it or unify when convenient.
4. metrics.go:673–674 — on a crossing tick onto an exit lane shorter than one tick's travel (~4 m), `dNew = v.S` can exceed the exit lane's length, booking out-of-network overshoot as VMT (the next-tick despawn then clamps to 0). No such lane exists in current nets; the multi-boundary skip case is impossible by `boundaries()` construction, so this is the only residual short-lane artifact beyond the documented intermediate-lane one.
5. engine.go:174 (pre-existing, not this diff) — `Vehicles()` claims "ID order"; `register()` (:151–154) and the kernel's determinism argument correctly say append order. Since the kernel's header comment (metrics.go:15) now leans on that ordering, fixing the stale comment alongside would keep the record straight.

**Questions**

6. metrics.go:62 vs :113 — `MetricSetConfig.EndTick` is inclusive ("last accumulating tick") while `IntervalRecord.EndTick` is exclusive. Both are documented, but the same field name with opposite conventions across the config/record boundary is a foot-gun for sink authors; consider renaming one before the NATS payloads freeze the record shape.
7. Kernel state is not keyframe/replay-persisted: a run restored mid-stream and re-observed produces pre-seeded-vehicle trips (entryTick 0, origin = current lane) rather than the original ones. Fine if M13 scopes metrics to whole runs — worth a line in the ADR-0014 implementation notes so it's a decision, not an omission.

Test design is strong — CRC-invariance, seed-determinism with destructive-drain checks, conservation (Σ intervals = Σ trips = VMT), the clamp-discrimination case at metrics_test.go:621, and the index-proxy trap at :669 all pin real failure modes.
