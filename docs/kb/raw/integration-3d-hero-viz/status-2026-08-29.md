## What exists

- `viz/hero.html` + `viz/src/hero/main.ts` — standalone three.js baked-replay
  page. No MapLibre/basemap/projection/NATS; renders the network local
  metric frame mapped **(x, y) → world (x, 0, −y)** (east +X, north −Z).
  Fleet models (+Z forward per `viz/src/fleet3d/SPEC.md`) take
  `rotation.y = angle + π/2`; engine positions are FRONT BUMPER, so groups
  shift back half the model length along the heading.
- `viz/fleet-review.html` + `viz/src/fleet3d/review.ts` — model review
  harness: dims cage + AxesHelper (red +X / green +Y / blue +Z),
  `?model=<id>&angle=front34|side|rear34|top`, per-model tris readout,
  in-page error text for models that throw on import (it keeps rendering
  the rest).
- `viz/src/fleet3d/loader.ts` — SPEC.md loader: manifest →
  `import.meta.glob` dynamic imports → smoke-build at load → weighted hash
  pick (FNV-1a of the decimal id; low bits pick the model, high bits the
  body tint) → classDefault → plain box of class dims. Missing manifest ⇒
  everything boxes; the page can never be broken by a bad model file.
- `viz/src/fleet3d/manifest.json` — the SPEC roster (6 models). **No model
  files existed at writing** (workstream C lands them separately); every
  roster entry therefore errors "not found in fleet3d/" and renders as
  boxes until then — that is the designed fallback, exercised and
  screenshot-verified.
- `three` 0.185.1 + `@types/three` 0.185.4 (three bundles NO .d.ts),
  exact-pinned per repo convention; vite.config.ts now has 5 page inputs.
  Model modules chunk lazily (verified: a stub `sedan.ts` built to its own
  1 kB chunk and loaded on demand; stub removed after the proof).

## Serve / view

```
cd viz && pnpm build
python3 scripts/serve-baked.py --baked data/baked --viz viz/dist --port 8790
# hero:         http://127.0.0.1:8790/hero.html?run=bthero42
# pinned:       http://127.0.0.1:8790/hero.html?run=bthero42/9418d700e5e8&t=6100&view=arterial
# fleet review: http://127.0.0.1:8790/fleet-review.html?model=sedan&angle=front34
```

URL params (hero): `run` (name or name/hash12), `bake` (full index.json
URL), `t` (tick, floored to the 5-tick bake stride), `speed` (0 = paused),
`pause=1`, `view=pod|arterial|junction` (keys 1/2/3 switch live, space =
play/pause), `bare=1` (capture chrome off). A bare run name resolves its
hash12 via the server's directory listing (python http.server HTML) —
first sorted, warned on console when several exist. `demosrv` does NOT
serve baked artifacts; `serve-baked.py` (or Pages) is the only path, and
its `Content-Encoding: br` on `.br` chunks is LOAD-BEARING (the browser
decompresses; the decoders never see brotli).

## Bake recipe (per-run, the game's payoff step)

```
cd engine
go build -o /tmp/tsim/serve ./cmd/serve && go build -o /tmp/tsim/bake ./cmd/bake
/tmp/tsim/serve -scenario ../data/pods/bottleneck-town/base -seed 42 -pace 0 \
  -run <runid> -store /tmp/<runid>-store -intent-log=false \
  -metrics-out /tmp/<runid>.metrics.json   # must EXIT before bake (one broker per store)
/tmp/tsim/bake -run <runid> -store /tmp/<runid>-store -out ../data/baked
# lands at data/baked/baked/<runid>/<hash12>/
```

`-pace 0` (unpaced batch) works fine with the in-process driver: the attach
barrier parks tick 0 until the driver attaches — no quirk. bottleneck-town
base seed 42 (15,000 ticks, 670 spawns) records in ~1 s; bake is instant.
Reference bake: `bthero42` → hash12 **9418d700e5e8** (200 lanes, 1 z11
region, 26 frame chunks, 4 programs J1–J4, cycle 860 ticks).

## Format gotchas (cost me time; don't relearn)

- `resolveBakedUrl` does `new URL(rel, indexUrl)` → the index URL must be
  ABSOLUTE. Root-relative `/baked/...` throws "Invalid base URL" (the same
  trap serve-baked.py's docstring warns about for `?bake=`).
- index.json has NO scenario type list: TSRB `cls` is the scenario type
  INDEX (0 = car, 1 = truck for bottleneck-town). hero maps by
  `["car","truck"][cls] ?? "car"`; a scenario with a different type list
  needs that table revisited.
- `signals.tssg` is `chunkBytes`-framed: slice per chunkBytes,
  `decodeSignalFrame` each, concat programs. Pod bakes are a single chunk.
- `signalHeads()` (viz/src/signals.ts, DOM-free) clusters TSSG links →
  heads with stop bars; bottleneck-town: 24 heads, 0 missing bound lanes.
- Signal furniture is drawn ~2.5× real size (posts 4.2 m, lens r 0.42 m,
  bars 0.9 m wide) — real-scale heads are sub-pixel at replay distance.
- Depth buffer: near 0.5 / far span×5 across a 3.7 km pod made coplanar
  ribbons z-fight invisibly (lanes vanished at close zoom while visible
  far away). Fixed by vertical separation: ground y=−0.5, casing 0,
  internal 0.02, centerline 0.04, stop bars ~0.08, vehicles 0.1. Keep that
  stack when adding geometry.
- Determinism: all TSRB chunks are PRELOADED into a tick→vehicles map and
  every head's color precomputed per baked frame (`Uint8Array`), so any
  tick renders f(tick) — two captures of `?t=6100&pause=1` are
  byte-identical (verified by md5). No per-frame allocations in the tick
  loop (vehicle pool keyed by model+tint, materials preallocated).
- PMTiles (city) bakes are rejected loudly: hero v0 is GeoJSON-bakes-only
  (pods). `network.geojson` absent ⇒ clear error, not a blank page.

### Behavior forensics (host reports vs the bake — exhaustive checks, not vibes)

Investigated against `rehearsal42/9da93a51331f` (all 3001 frames, SAT
footprint overlap with engine class rects, hero's front-bumper contract):

- **"Right turn through a car" = ENGINE TRUTH, and it's the pod's documented
  known defect.** `scripts/demos/bottleneck_town.py:281-297` ships mirrored
  lane indexing (lane 0 nearest the centreline), so the right turn issues
  from the centreline-side lane and crosses the through lane beside it INSIDE
  the shared `main_thru` green; the opposed protected lefts likewise cross
  each other. The generator leaves `foesCross`/`foesMerge` empty "phases are
  conflict-free by construction" — so on green, `sigGate` returns before
  `rowConflict` and `boxWalk` reads empty foes (`engine/signal.go:447-453`,
  `engine/rightofway.go:277-286`): nothing arbitrates. Measured: **64
  crossing overlap episodes in raw baked frames**, 110/3001 frames, all four
  junctions, median depth 1.41 m, max 3.82 m (truck right-turn vs through,
  J2 t=8825). Right-turn × same-green through dominates (67 pair-frames).
  Camera sentence: *"That pass-through really happened — this toy town's
  junctions were drawn with the right-turn lane on the wrong side, and with
  every movement labelled protected, nothing tells them to yield; known
  defect in the demo town, not a rendering glitch."*
  **Deferred deliberately**: fixing = correct the lane indexing or declare
  foes for same-phase crossing movements + regenerate networks/variants +
  re-run ALL baselines (scores WILL shift). Post-show work, and the first
  real use for the empty `foesCross` fields.
- **Viewer-lerp phantom overlaps (secondary, real)**: simulating the chord
  lerp at α=.25/.5/.75 found 23 overlap pair-frames present in NEITHER
  bracketing raw frame (~90 M pair checks; 16 ≥0.3 m, max 3.29 m; 18/23 with
  >20° heading change). ~5× rarer than the engine-truth overlaps. Future
  fix: lane-aware lerp — when heading changes materially and both poses sit
  near a junction's internal-lane polylines (already in network.geojson),
  project and lerp along arc length with tangent heading.
- **"Stops at green" = legitimate engine behavior, no bug.** 4,444
  stopped-at-green vehicle-frames: 50% within 1.0 s of green onset (IDM
  start-up lag from rest), 69% with a leader <6 m (ordinary queue), 15%
  discharge creep; the 17-frame residue all resolved to `boxBlocked` exit-room
  gating (verified numerically against `exitWalk`'s rule — gate opened the
  exact tick the exit had Length+S0 room). Viewer/engine phase math proven
  identical (`tssg.ts:237` ≡ `signal.go:139`). Camera sentence: *"A car
  stops at green here because it has nowhere to go — a queue in front or the
  exit lane still full; green means go only if you can actually clear the
  intersection."*

## Lane-fix addendum (2026-08-29 late evening) — mirrored indexing FIXED

The pod generator's known defect (`bottleneck_town.py` lane 0 at the
centreline) is fixed on this branch; the earlier addendum's "deferred
deliberately" is superseded.

- **The fix**: lane 0 = kerb (netfile.go's edgeIndex contract). Flare widens
  kerb-ward into a right-turn pocket (`chain()` maps upstream lane i →
  downstream i+extra so continuing lanes keep their lateral position); the
  protected left shares the centreline through lane (the carriageway cannot
  widen centreline-ward — the old defect's dedicated left bay is
  geometrically unaffordable). Left internals use an early-hook cubic:
  **opposed lefts cannot pass offside-to-offside in this box** — with
  entry/exit lanes 1.75 m off the centrelines, a symmetric late-arc pair
  either crosses (R<3.5 m) or passes <2.2 m apart at the apexes; the
  early-hook passes right-side-to-right-side at 3.64 m clearance. Worth
  remembering when drawing future junction templates.
- **Foes are now geometry-derived at build time** (`cross_foes()` intersects
  every same-phase internal pair): J1–J4 add nothing (paths verifiably
  don't cross); connector-south's 2-phase CS junctions declare 16 pairs.
  Known gap (review, deferred): the CS permitted-left yield relies on
  `boxBlocked` occupancy — simultaneous *approaching* conflicting movements
  both see protected `G` and can both commit; connector-south is not baked
  or run for the show.
- **Recalibration is real and uniform**: base 161.7→207.3, retime-short
  186.9→221.0, green-wave 117.0→190.7, rehearsal-wave 148.7→201.6 (seed 42,
  15k ticks). Ordering preserved; green-wave margin over base 16.6 s. The
  defective layout's free left bay was worth ~10% corridor throughput.
- **Forensics verdict (independent, exhaustive, both new bakes)**: zero
  front-bumper interpenetrations (min separation 2.89 m vs ~1.2 m pre-fix),
  zero same-phase path crossings, zero `cross2_f1` contacts. The residual
  70/68 "contact" episodes are ONE render-fidelity class: a turning
  vehicle's RIGID rectangle (front-bumper pose) sweeps the adjacent lane
  for 1–3 frames mid-rotation — the point-mass trajectories are clean
  (≥2.89 m apart); only the drawing says they touch. Mitigation path:
  render turning vehicles bent along the internal-lane arc (geometry is in
  network.geojson). Until then the on-camera answer is "the drawing
  overstates the turn; the simulation's bodies never overlap."
- **Review-gate dispositions**: FIXED — baseline-name collision
